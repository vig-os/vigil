# [PR 75](https://github.com/vig-os/vigil/pull/75) feat(audit): decode strict v1 OTLP records (B1/3)

## Description

Enforce audit writer/reader agreement through one shared validation domain and a production record mapping; add the strict parse side of ADR-0005's v1 OTLP format, on the merged primitives from #73. Messages are closed at every level: Collector snake_case aliases and unknown nested keys are rejected. OTLP intValue fields require canonical signed-int64 strings; audit counters are nonnegative, while timestamps fit u64. Context bytes require standard padded base64. Raw-read bytesValue, traceId and spanId reject every JSON escape before unescaping. Raw bytes below 0x20 and oversized payloads are refused before parsing, except one optional final LF; checkpoint anchors exclude that delimiter. Malformed lines retain verifier finding kinds alongside CorruptTrail (TooLarge for the size bound). Collector lines with multiple resources, scopes and records retain their order.

## Changes Made

- Add Record::parse_line with recursive duplicate-key rejection after unescaping, recursive OTLP message allowlists, exact record attribute/type rules, fixed severity and observed time, decimal-string i64 counters and u64 timestamps, strict hex spellings and record-hash checks.
- Add FindingKind and AuditError::finding_kind for Unparsable, UnknownVersion, UnknownField, MissingField, InvalidField and HashMismatch; writers can still refuse malformed history as CorruptTrail.
- Amend ADR-0005 (2026-10-11): withdraw JSON-number int64 acceptance, close all message keys, reject raw bytes below 0x20 including interior LF and CRLF, and enforce the 1,000,000-byte JSON payload limit before parsing (excluding an optional final LF). Escaped controls and DEL remain content in unescaped text fields; raw-read base64 and IDs reject all escapes. Also bound every intValue to i64, refuses oversized writer counters with InvalidConfig, validates contextual base64 using Go decoder semantics, and excludes the final LF from checkpoint anchors.
- Add Checkpoint::parse and its ADR getters, retaining the original payload without its optional final LF for external anchors. Parsing checks structure and hashes; it does not verify signatures, trust, chain links or MMR history.
- Reject empty/whitespace input and incomplete JSON as complete records. The named decode_complete_json seam preserves serde's error category for B2 recovery. Strict warning policy (#68) and receipts across resume (#70) remain deferred.
- Add fixed OTLP fixtures checked against the previously merged canonical vectors, malformed-input cases, nested Collector records, i64 counter and u64 timestamp boundary cases and a deterministic short decoder fuzz.
- Add optional direct serde access for the duplicate-rejecting visitor. Add optional direct base64 0.22 access for standard padded decoding with accepted unused trailing bits. Raw string spelling is retained for the three raw-reader fields, with no CR/LF stripping, matching pdata. Enable serde_json raw_value to inspect those values before unescaping. Both crates were already in the locked dependency graph; no new crate version is introduced.
- Resolve #82 systematically: document the complete reachable logs-reader field table for pinned Collector 0.151.0/pdata v1.57.0 and reviewed pdata v1.68.0, preserve raw spelling for bytesValue/traceId/spanId, correct the ADR's CR/LF claim, and share parity fixtures between Rust tests and the real Collector harness.
- Explicitly preserve ASCII space between tokens and around the JSON payload in checkpoint anchors (except the optional framing LF). Different payload spellings can have the same canonical record hash; the test pins this no-normalization policy.

- Define one shared validation module used by production mapping and parse_line: nonempty/NUL-free/unique keys, present KeyValue/AnyValue values, maximum 16 container edges, shared text/framing and 1,000,000-byte size rules. Invalid context is refused with InvalidConfig and excessive size with TooLarge before any write. A bounded typed walk uses the same nesting guard before cloning/projection.
- Preserve #83's public documentation contract: add explicit decoder/checkpoint error sections and retain the documented OTLP int64 sequence bounds while resolving the documentation rebase conflict.
- Register the existing B1 public decoder/checkpoint/finding declarations in the stable API allowlist and snapshot introduced by #81, with ADR-0005 justification.
- Require canonical finite double tokens before JSON loses their spelling, using the shared validator and the encoder’s shortest round-trip form. Require lowercase traceId/spanId through shared validation; document both intentional pdata differences in ADR-0005.
- Prove contextual intValue canonicalization and typed-depth refusal independently of JSON validation: the latter test observes the first clone and fails if it is reached. Generate unrestricted Unicode context strings and keys, including NUL; NUL keys exercise typed refusal.
- Record the architect decision in ADR-0005, dated 2026-10-11 and explicitly decided in review of PR #75. Keep the decoder canonical-only; document pdata-accepted context rejected by the reader and refused by the writer.
- Enforce the writer/decoder contract with shrinking proptest strategies: Unicode (including controls, DEL, surrogate-adjacent and astral scalars), optional fields, entries/checkpoints, all seven nested AnyValue kinds, int64 extremes, arbitrary bytes, and encoded payloads near the one-million-byte cap. The production Record-to-request mapping (required for B2/B3) uses the shared encode_line path; compare decoded canonical bytes and hashes with the original record.
- Accept DEL per RFC 8259 and pdata; reject only raw bytes below 0x20. The shared encoder now omits absent protobuf bodies to satisfy ADR-0005's required body absence. Document “every line the writer can emit verifies” and a table of intentional canonical-only rejections that pdata accepts.
- Commit a reproducible gzip-compressed 256-line corpus from the same generator (ChaCha seed [0x75; 32], with uncompressed BLAKE3 digest and regeneration instructions). Run every line against the pinned Collector in CI. Split JSON Lines on LF only and poll output byte length, preserving legal Unicode separators and avoiding decoding partial UTF-8 writes.

- Update module/API rustdoc, README and fixture provenance. Scope is B1 only; B2 and B3 wait for review and merge.

_Posted on October 11, 2026 at 11:55 AM_

Architect decision, round 6: the decoder stays strict (canonical-only). The invariant that every line the writer can emit verifies now holds by construction. One shared validation module defines the accepted domain, and both the production Record→request mapping (writer side, which refuses with a typed error before writing) and `parse_line` call it. `request()` moves into production code as the mapping B2 and B3 must use. The reason for doing it this way: rounds 3 to 5 each found a new boundary case because the writer and the reader each kept their own copy of the rules. ADR-0005 records this decision.
