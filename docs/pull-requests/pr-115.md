# [PR 115](https://github.com/vig-os/vigil/pull/115) test(logs): pin scope packing with allocation accounting

## Description

Packing 512 scopes previously had to finish within three seconds, causing failures under host load. Assert a deterministic bound on actual allocated bytes instead, retaining the packing, line-size, record-count and determinism assertions. The ignored release measurement now prints its results without a timing gate, as ruled in 96-d2.

## Type of Change

- [x] `test` -- Adding or updating tests

## Changes Made

The existing test measures only the synchronous shared `envelope::bounded_lines` call, using the crates.io dev dependency `allocation-counter` 0.8.1. Its thread-local allocator records total allocated bytes, including allocations freed during the call. Fixture construction, parsing and validation are outside the measured closure. The budget is 32 times the serialized input length (62,522,880 bytes for this fixture), allowing record serialization and geometric buffer growth while rejecting repeated copies of accumulated output. A growing-line `String::clone`, batch `Value::clone`, or fresh-string serialization goes through the allocator directly; there is no packer-specific counter that a different serialization helper can omit. The counter is referenced only inside the existing `cfg(test)` module; release code and public APIs are unchanged. No unsafe code is added to this crate.

This dependency is justified by observing actual copying allocations without instrumenting release code or substituting a serializer proxy. It has no dependencies of its own. The total allocated-byte bound is a deterministic regression check on this fixture, not a claim to count copies into preallocated buffers or serialization to a nonallocating writer.

Only eight non-test lines change (manifest plus lockfile), below the limit of 40. `scripts/check_public_api.py` and the API baselines are unchanged. No edits to initialization, audit, or other unrelated modules.
