# [PR 54](https://github.com/vig-os/vigil/pull/54) docs(adr): ADR-0004 public API, stability, composition and feature flags

## Description

Proposes ADR-0004 (Status: Proposed), which decides vigil's 1.0 public surface before 0.2.0 adds metrics and traces exporters. It covers R1, R2 and R10 from the path-to-1.0 pre-mortem, the MSRV policy and the semver baseline. Docs only: no code changes.

## Changes Made

- `docs/adr/0004-public-api-and-stability.md` makes these decisions:
  1. No `opentelemetry*` type is in the stable surface. Only std and the `tracing` family are allowed, and a rustdoc-JSON allowlist check in #43 enforces this.
  2. Exporters and sinks move behind `unstable-exporters`, which is exempt from semver. They graduate only after `opentelemetry_sdk` reaches 1.0.
  3. Composition API: `Config::layer::<S>()` returns a boxed layer with a per-layer filter, plus `filter_env`, `default_filter`, `Console` and `Guard::dir`.
  4. `InitError` and `ShutdownError` get `kind()` with `#[non_exhaustive]` kinds. `Guard::shutdown` and `shutdown_with_timeout` return the loss count.
  5. No public struct has a public field. `RotationConfig` uses a builder and is no longer `Copy`. Retention is a `Duration`. `NON_FINITE` becomes private.
  6. Each item of the stable surface is listed with the reason it is public.
  7. Feature plan: `metrics` and `traces` on by default; `audit`, `push` and `unstable-exporters` off. There is no `test-util`.
  8. MSRV: 1.95 for 1.0. Raises happen only in a minor, to a release at least six months old. #45 adds an MSRV lane and a latest-stable lane.
  9. Semver baseline: before the first publish, the merge base with dev and `--release-type minor`, with a `semver:major` exception that must cite an ADR decision. From 1.0, the registry baseline.
- `docs/adr/README.md`: adds ADR-0004 to the index and lists the reserved numbers 0003, 0005 and 0006.

### Manual Testing Details

Probes ran in `mktemp -d` scratch crates on Rust 1.95, with tools from the flake's pinned nixpkgs:
- cargo-semver-checks 0.47 misses an opentelemetry 0.32 → 0.33 bump in a public signature: 196 pass, exit 0. A consumer on 0.32 fails with E0308.
- cargo-semver-checks skips `unstable-*` features: removing an item behind one passes, exit 0. Control: removing an item behind a plain feature fails with `function_missing`, exit 1.
- Composition: a boxed, per-layer-filtered vigil layer inside a flock-shaped `Registry`, with `FLOCK_LOG` and an own JSON layer, keeps the filters isolated: `PROBE OK`.
- Shutdown loss: `provider.shutdown()` returns `Ok` after 999 of 1000 records were dropped. A scoped capture reads `dropped_logs_count=999` even under a global ERROR filter.
- `cargo public-api` works on stable 1.95 through rustdoc JSON with `RUSTC_BOOTSTRAP=1`: 80 items, 4 of them `opentelemetry_sdk`.
- MSRV: dependencies need ≤1.85, the code needs 1.89 (`File::lock`), `try_update` needs 1.95, and rustc 1.99 deprecates `fetch_update` (`src/logs.rs:144`).
- Feature weight: `metrics` adds 0 crates, `traces` adds 1.
- Two fresh review rounds. Round 1 found 4 blockers and 7 nits; round 2 found 1 blocker and 3 nits. All are fixed.
