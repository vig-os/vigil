# [PR 85](https://github.com/vig-os/vigil/pull/85) feat(audit): format support for ADR-0005 amendment 2 (#79)

## Description

Support ADR-0005 amendment 2 in the audit v1 format before the durable sink lands. A checkpoint now counts preceding records independently of skipped sequence numbers, and the first line after a torn-tail repair can authenticate the repair gap.

## Type of Change

- [x] `feat` -- New feature

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- Permit checkpoint `mmr_size <= seq`; exact counts and resume gap declarations require trail history and remain the verifier's responsibility. Reject size above sequence, zero size at nonzero sequence, and counters above the OTLP int64 bound. Creation is a leaf, so even a resume opening checkpoint includes at least that preceding record (ADR-0005 decisions 7–8).
- Add optional `RecordContext::repaired` and canonical tag 0x07; carry the digest through production OTLP mapping and strict decoding. Missing or altered digests fail the hash check; malformed digests are refused.
- Add an independently assembled repair golden vector. Existing primitive vectors are unchanged, and existing tessera-derived aggregate vectors verify every MMR root from size 0 through 2048, including resume from peaks at each size.
- Reject reserved `audit.*` keys throughout unhashed resource/scope context with the shared validator at both writer and reader boundaries; document the rejection table and mark amendment 2 Accepted on 2026-10-11 by PR #77.
- Extend round-trip properties and regenerate the 256-line Collector corpus, including 98 normal and 31 resume checkpoints. Restore weighted control/Unicode context generation and exercise finite doubles inside arrays and kvlists.
- Update rustdoc, the ADR-backed API allowlist and snapshot for the additive context builder. No dependency changes; no B2 sink code.
