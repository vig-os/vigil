# [PR 196](https://github.com/vig-os/vigil/pull/196) test(audit): pin decode precedence and close #13 verifier test gaps (#191, #193, #195)

## Summary

Pins ADR-0005 decision 11's record-level finding precedence per architect ruling 191-d1 (envelope -> version -> identity -> rest), closes the #13 V3b-1 test gaps from #193, and settles the V3b-2 follow-ups from #195. No new finding kind, no public API change, no behaviour visible to users beyond the pinned precedence.

Round 2 (fc8febe) addresses the fresh review's verdict blockers: ADR step 0 now describes the actual pre-identity decode path, the #193 integration mark test is rewritten so the `.find(|i| i.native)` -> `.next()` mutant exits 101, A13 kills the `on_trail` filter mutant, and two nits are fixed.

### #191: decode precedence (ruling 191-d1 as amended by addendum 6-7)

Pre-dispatch probe on `a70e01c` (results agree with the amended ruling, so no decoder reordering is needed):

| combination | `FindingKind` | `seq` |
| --- | --- | --- |
| unknown attribute key + `audit.v=2` | `UnknownVersion` | `None` |
| unknown attribute key + missing `audit.seq` | `MissingField` | `None` |
| missing `audit.trail` + missing `audit.seq` | `MissingField` | `None` |
| malformed `audit.seq` + unknown attribute key | `InvalidField` | `None` |
| missing `audit.v` + unknown attribute key | `MissingField` | `None` |
| `audit.v=2` + duplicate attribute key | `InvalidField` | `None` |
| `audit.v=2` + `droppedAttributesCount=1` | `UnknownField` | `None` |
| duplicate attribute key + `droppedAttributesCount=1` (R2) | `InvalidField` | `None` |
| unknown log key + attribute without `value` (R2) | `MissingField` | `None` |

- **ADR-0005 decision 11 step 0 rewritten (R2):** the ordered list now describes the real pre-identity path `decode_complete_json` -> `Record::from_json` -> `contexts()` -> top-level/resource/scope `message()` -> `parse_record` (`src/audit/codec.rs` and `src/audit/validation.rs`). JSON duplicate object keys fire in `decode_complete_json`; the per-log attribute list (missing `value`, dup attribute keys, unknown attribute fields) is decoded in `contexts()` BEFORE `parse_record` sees the log, so a duplicate attribute key and a missing attribute `value` are both decided earlier than any `parse_record` envelope check. The remaining steps 1-4 (version, identity, everything else, HashMismatch) stay as in round 1.
- One unit test per combination in `src/audit/codec_tests.rs`.
- **R2 nit:** `precedence_malformed_seq_and_unknown_attribute_key_is_invalid_field` now uses `audit.seq = "-1"`. The `integer` validator rejects a leading sign in identity step 2 (`InvalidField`), kept observably distinct from the step-0 attribute decode. Under the whitelist-before-identity mutant this flips to `UnknownField`, so the mutant exits 101.
- The honest-crash integration test still asserts the exact gap byte count (fragment length + the writer's repair LF, `870 + 1 = 871`).

### #193: #13 V3b-1 verifier test gaps

- `no_crash_mark_takes_next_native_input_not_a_shipped_copy` - a shipped copy between archive and native successor; the mark must come from the next NATIVE input.
- **R2 rewrite:** `no_crash_mark_absent_when_only_successor_is_a_shipped_copy` replaces the vacuous `_set_on_real_writer_archive_with_trailing_fragment` row. `verify::input::collect` orders inputs by `(rank, segment_key, path)` with rank 0 for sealed native segments, 1 for `audit.jsonl` and 2 for every non-native filename (`src/audit/verify/input.rs:95-108`), so a shipped copy always sorts AFTER every native input. The only integration-level layout in which the `.find(|i| i.native)` -> `.next()` mutant observably diverges is: a sealed native archive with a trailing fragment, followed in `inputs` by a non-native shipped copy whose first record happens to be the opening checkpoint the real successor would carry (because it is a verbatim copy of the live file), and NO native successor among the explicit inputs. Production returns `None` from `.find(|i| i.native)` and leaves the mark absent (ADR-0005 §19.6: "An archive verified alone, without the file after it, cannot set the mark"); the mutant takes the shipped copy as the successor, every structural condition passes, and the mark would be incorrectly set.
- `first_broken_link_returns_first_error_in_ruled_order` rewritten to drive `engine::check` with a decoder finding at `seq=10` emitted first and a chain-link error at `seq=0` emitted second, so the engine's final `sort_by_key` is what moves the earlier finding to the front.

### #195: #13 V3b-2 follow-ups (ruling 13-V3-d5 point 10)

- `src/audit/verify/resume.rs` now computes each declaration's structural outcome **once** per `(resume_seq, resume_hash)` through a private `declarations(&Collection, trail)` function; both the `Resumed` detail and the candidate list derive from it, so native and shipped copies of the same resume always show the same suffix (d5 point 10).
- `collect_candidates(&Collection, trail)` is kept as a `#[cfg(test)]` wrapper so A13 and A17 stay unchanged; nothing else is test-only.
- `_pending_resumes` and the per-field `#[cfg_attr(not(test), expect(dead_code, reason = "consumed by #13 V<n>"))]` pattern on `ResumeCandidate` fields still clear `cargo clippy --all-targets --all-features --locked -- -D warnings`.
- New rows: `v3b2_head_not_last_at_k_minus_1_marks_structural_invalid` and `v3b2_genesis_not_first_at_k_minus_1_marks_structural_invalid`.
- **R2 extension:** A13 (`v3b2_foreign_trail_resume_does_not_affect_own_trail_candidate`) now also carries a foreign-trail record at `seq=3`, in the open interval `(h=1, k=5)` of the own-trail declaration. Not a checkpoint, so S1a (opening at `k`) is unaffected; the record only matters through `on_trail`'s S2b. With `on_trail`'s trail filter removed in `structural_check`, S2b (`on_trail().any(|r| r.seq > head_seq && r.seq < k)`) now sees the foreign record and the outcome flips from `structural=valid` to `structural=invalid(head-not-last)`, killing the previously 'unobservable by design' mutant.
- A7w asserts full-string equality on the writer-driven genesis `Resumed` detail.
- A16 asserts byte-identical `Report::findings()` across the two input orders.
- Line wraps: `src/audit/verify/mod.rs:249`, `engine.rs`'s `Resumed` `format!` (now a string continuation, byte-identical), and the `UncoveredTail` `format!`.
- ADR §19.9: the duplicated `§19.6 stays Proposed` sentence is removed.
- R2 typo fix: 'dedupeded' -> 'deduped' in `src/audit/verify/resume.rs`.
