# [PR 228](https://github.com/vig-os/vigil/pull/228) test(audit): second killer for per-directory run classification

## Summary

Adds R20, a second distinct literal killer for the per-directory
classification mutant "in `src/audit/verify/fold.rs`, call
`classify` once per `path.parent()` group of `natives` instead of
once over all of them" (ruling 13-V4-d8 point 2: verifier run
detection classifies all native segments of one verify call
together).

Tests only. One row, no production change.

## The row

R20 — `r20_227_cross_dir_a3_archive_plus_trail_dir_one_classify`:

An A3-layout trail split across two directories, verified in one
`Verifier::verify_files` call:

- `archive_dir` holds A3's sealed segments S0, S1, S2 (including
  the run's first segment S1).
- `trail_dir` holds the live `audit.jsonl` (the run's closer).

Asserts the full sorted literal finding list, with paths rebased
onto a common base so both directories' basenames line up (R10's
`relative` pattern). The one run finding sits at the archived first
segment S1, `(line=1, seq=4)`, with A3's pinned digest
`blake3:78d5088883d54faa6aefe350948c217bb5ef3c32a468f22184bc07e56d84c63d`
and detail `loss seq 4 first 3 count 1; loss seq 7 first 6 count 1;
digest blake3:78d5088883...`.

The row is distinct from R10: R10 splits the R7 archive layout
(A1's digest `79d8cb1c…`, closer in a sealed segment in the trail
directory), R20 splits A3 (A3's digest `78d50888…`, closer on a
live file).

## Mutant measurement

Mutant: group `natives` by `path.parent()` and call `runs::classify`
once per group in `check_runs` instead of once over all of them.
Under the mutant, the archive group has no closer (the live file is
in a different directory) and the trail group has no run opener, so
neither emits the run finding; the literal list drops the R20 run
row.

```

$ cargo test --features audit --lib "audit::verify::runs_tests::r20_227" --no-fail-fast
test result: FAILED. 0 passed; 1 failed; ...
exit 101
$ cargo test --features audit --lib "audit::verify::runs_tests::r10_ss8" --no-fail-fast
test result: FAILED. 0 passed; 1 failed; ...
exit 101

# revert the mutant:
$ cargo test --features audit --lib "audit::verify::runs_tests::r20_227" --no-fail-fast
test result: ok. 1 passed; 0 failed; ...
exit 0
$ cargo test --features audit --lib "audit::verify::runs_tests::r10_ss8" --no-fail-fast
test result: ok. 1 passed; 0 failed; ...
exit 0
```

Regression row for the mutant: R20 also passes on base `origin/dev`
without the mutant, because the current `check_runs` already runs
one classify pass over the merged `Collection` (ruling 13-V4-d8
point 2).
