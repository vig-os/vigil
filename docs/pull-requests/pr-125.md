# [PR 125](https://github.com/vig-os/vigil/pull/125) feat(audit): settle and reader rules for resume (B3d2a)

## Description

A resumed trail must seal exactly the filename committed by its declaration, and a genesis resume must use a leaf every reader can compute. Settle now validates the recorded `file=` and directory state through one shared promotion helper, completes hard-linked live-name recovery first, and fsyncs once after its last directory mutation. Both reader paths enforce the MMR obtained by pushing the genesis digest through the existing fold.

ADR-0005 amendment 9 part 1 is Proposed, incorporating rulings B3d2-d1 through B3d2-d5. Amendment 10 and its follow-up were already merged in #120 and #124; their sections remain unchanged.

## Changes Made

- Extract `pub(crate) promote_resume`; **shared helper is the sole promote callsite** for resume settlement, ready for B3d2b's inline caller. The normal sealing path remains separate.
- Expose the existing `next_segment_name` and `parse_segment` within the crate; keep one naming/parser implementation.
- Reject reserved, invalid, older, absent, ambiguous and non-newest `file=` resolutions. Preserve the already-renamed and missing-live recovery cases.
- Unlink a live hard link before any staging rule. Batch both staging names and the unlink behind one final fsync, retaining poison handling after live-name mutations.
- Add a test-only fallback-rename crash seam. Production still uses `rename_new` unchanged.
- Authenticate genesis peaks/root through `Mmr::push`, shared by amendment-4 staging scans and amendment-6 history scans.
- Include ADR-0005 in both Nix source allowlists so the ADR presence test runs in filtered builds.
- Replace the three ADR sentences and add the R9 rule. Public API snapshot and allowlist remain unchanged.

- (b) Honest sealing step-4 `linkat`/`unlink` crash, with step-2 staging already durable: `honest_fallback_sealing_crash_still_promotes`. This regression passes with both original and current settle.

- (e) `foo.jsonl`, a parseable older name, `.audit-next.jsonl`, `audit.poison`, `../x`, and a present but non-newest named segment: `resume_filename_validation_and_directory_states`.
- `resume_hard_link_is_unlinked_before_directory_validation` pins R9-before-R5 ordering; `settle_batches_both_staging_discards_after_hard_link` pins one fsync across both staging names, with and without R9.

### Fixture migrations

| Fixture | Why / new assertion |
| --- | --- |
| `resume_promotes_over_live_opening_checkpoint` | Replace `file=-` beside live with its actual seal name; read back and match the newest segment. |
| `resume_staging_every_prefix_with_and_without_gap` | Keep byte-prefix rejection while the complete staging names its seal; match the on-disk declaration to the actual segment. |
| `resume_discards_sequence_below_next` | Supply a valid filename/layout so rejection comes from sequence, then confirm a valid sibling promotes; match the initial declaration to its segment. |
| `resume_settlement_promotes_over_archived_live_prefix` | Name the live prefix's actual seal rather than `-`; match the on-disk name. |
| `poison_835_rename_directory_fsync` | Resume poison cases now seal to the declared filename; read it back before durable replay. |
| `poison_844_check_before_settlement` | Staging held behind poison now names its eventual seal; assert the recovered declaration names the actual segment. |
| `resume_without_predecessor_promotes_genesis_link` | Replace the unavailable creation leaf with `Mmr::push(genesis)`; reader-path rejection proves the leaf. |
| `genesis_resume_requires_immediate_matching_declaration` | Keep immediate-declaration checks while using the computable genesis fold; reader-path rejection proves the leaf. |
| `runs::genesis_resume_after_fragment_only_first_segment_keeps_creation_leaf` | Keep the legacy test name; replace creation seeding with the genesis fold; reader-path rejection proves the leaf. |
| `runs::never_rotated_creation_loss_requires_moving_evidence_then_settles_resume` | Preserve the evidence-moving procedure while using the genesis fold; reader-path rejection proves the leaf. |

`assert_resume_discard` is the single discard helper; callers supply the rule and whether sealing already happened. Its three callers are `resume_discards_sequence_below_next`, `resume_discards_right_sequence_wrong_previous`, and `resume_discards_wrong_action`. Each now tests its own rule with a valid R5 layout, and checks a valid sibling that must promote. Passing a valid candidate through the discard assertion fails at runtime.
