# [PR 103](https://github.com/vig-os/vigil/pull/103) test(audit): crash matrix, SIGKILL and truncation properties (B2b2b)

## Description

Add the writer-side crash and concurrency evidence required by ADR-0005 and fix signer-outage reporting: an unavailable signer with unwritable stderr now leaves `record` returning normally.

## Type of Change

- [x] `fix` -- Bug fix
- [x] `test` -- Adding or updating tests

## Changes Made

- **Do 0 / #100:** use a non-panicking locked stderr write, including the existing diagnostic hook. A real child with stderr redirected to `/dev/full` and `checkpoint_every=1` reproduces exit 101 before the fix and succeeds after it ([ADR lines 488–495](https://github.com/vig-os/vigil/blob/dev/docs/adr/0005-audit-trail.md#L488-L495), signer failure does not fail the record). The test also runs on macOS using a read-only stderr descriptor, since that platform has no `/dev/full`.
- **Do 1:** SIGKILL after sealing steps 1–6, with both an already-open writer and a fresh child opening the trail. Step 1 has no staging file; step 2 discards it; steps 3–4 promote it; steps 5–6 follow the replaced live inode. Creation covers steps 1–4 plus empty/torn/complete staging and promotion boundaries. No marker means `MissingTrail` and creation succeeds; marker without a complete trail means `CorruptTrail` / `TrailExists`; complete staging is promoted. Exact byte multisets and a zero `CountingSigner` count prove recovery writes no new record/signature ([ADR lines 525–575](https://github.com/vig-os/vigil/blob/dev/docs/adr/0005-audit-trail.md#L525-L575), 740–744 and amendment-3 line 832).
- **Do 2:** 20 real-process runs, each with eight healthy writers and three writers killed while holding the lock after half a line. Every returned seq/hash appears exactly once; the writer read path reopens each trail, and structural assertions check genesis, sequence/hash links, every fragment and its domain-separated repair digest. A separate two-kill case crashes during repair and checks a single attestation over the combined gap, for running and fresh writers ([ADR lines 122](https://github.com/vig-os/vigil/blob/dev/docs/adr/0005-audit-trail.md#L122-L122), 408–414 and 793–796).
- **Do 3:** eight writer processes record and close in a random permutation; the highest returned seq/hash equals the checkpoint at the disk head. Kill another process after `write(2)` but before `Ok`: the held maximum is below disk head, and a restarted writer's close returns the new head ([ADR lines 757–761](https://github.com/vig-os/vigil/blob/dev/docs/adr/0005-audit-trail.md#L757-L761)).
- **Do 4:** reuse B1's `generated()` without changing its Unicode weighting. Only entry payloads go to `record`; checkpoint and `TooLarge` samples are dropped. Each generated trail tests every record boundary, every removed-LF boundary (including genesis), empty/mid-genesis cuts, and a random byte. Surviving acknowledgements retain their order; complete unterminated records get no repair attribute; fragments get the exact digest ([ADR lines 412–414](https://github.com/vig-os/vigil/blob/dev/docs/adr/0005-audit-trail.md#L412-L414), 571–573, 738 and 747).
- Reusable process fixtures live in `src/audit/crash_fixtures.rs`, accessible to #13. Crash observers park and cannot return a rollback-triggering error. Child cleanup kills and reaps owned processes. No dependency, public API or error-kind changes; 58 changed lines outside test files (including all sink hook sites), below the 400-line cap.
