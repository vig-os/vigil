# [PR 81](https://github.com/vig-os/vigil/pull/81) feat(api)!: freeze the stable public API

## Description

Freeze the stable API required by ADR-0004, part 3/3 of #42. Direct SDK exporters and sinks now require `--cfg vigil_unstable`; stable builds expose vigil-owned lifecycle, composition, rotation and audit primitives. CI compares the all-features public API snapshot and enforces the ADR allowlist, including declaration kinds, hidden items and macro expansions.

## Changes Made

- Make exporter and sink modules private in stable builds; expose their SDK integration under `vigil_unstable`, with visible re-exports of vigil's exact OpenTelemetry API and SDK versions. Keep `NON_FINITE` private. Global-provider installation and the tracing integration re-export remain deferred to #7/#8.
- Declare the cfg, enable all features and unstable documentation on docs.rs, and label the unstable modules and types. Compile/test both stable and unstable builds in CI; run the exporter, golden, property and short-write suites with the unstable cfg.
- Commit `api/public-api.txt`, generated with pinned rustdoc JSON and `cargo public-api -sss`, including hidden public items. Check normal and hidden listings against the independent ADR-justified item/kind list and external-crate allowlist. Resolve forbidden public `extern crate` origins even under aliases; prevent macros or other kinds from reusing approved function/constant names. Reject empty/root-only listings and forbidden upstream re-export targets, including macro expansions. Snapshot drift fails independently of allowlist membership.
- Retain the semver gate's merge-base comparison, stable flag sanitization, `--release-type minor`, and positive executed-check assertion. List every major finding in the job summary. Only complete major findings at version exactly `0.0.0` with a live, authorized `semver:major` label pass; missing labels, incomplete output, tool failures and published versions fail. Read current labels after the heavy lanes and verify the latest labeled event's actor has current admin or maintain permission. API failures and stale heads fail closed. A separate label-change workflow reevaluates semver and CI Summary without rebuilding heavy lanes; it requires successful full-run evidence for the same PR number and head SHA and cancels superseded runs. Unfinished cancelled heavy lanes require a full rerun. Semver uses a cancellation-aware condition so superseded runs release the concurrency slot promptly while failed/skipped dependencies still allow evaluation. Unrelated labels cannot publish a skipped required summary. The snapshot/allowlist gate has no exception.
- Request `pull-requests: read` explicitly in the semver job and both callers; request `actions: read` only for the label summary. Preserve the caller grant through the exact, reviewed `.github/ci-permissions.patch`; Scaffold Drift still regenerates and compares all managed files. Document reapplication on devkit upgrades. Include the new performance lane in full-run evidence, and skip it on label-only runs.
- Probe label renaming using a temporary label on this PR: REST event 32983514572 retained its apply-time name after rename. Remove/delete the temporary label and document the observation and regression fixture in ADR-0004.
- Clarify empty `RUST_LOG` fallback and immediate unnamed-guard Drop. Preserve the library child-process isolation already merged in #72; require one passed child test in integration helpers, including the short-write subprocess.

## Reviewed Major Findings

The unchanged minor-release semver probe reports **196 checks: 192 pass, 4 fail**, with these four major findings. The architect/owner has applied `semver:major` under ADR-0004 decision 12; the gate now verifies that review through the live label and actor-permission APIs:

1. **`module_missing`: `vigil::logs`, `vigil::sink`.** ADR-0004 decision 4 requires exporters and sinks to be crate-private without `vigil_unstable`; decision 1 excludes upstream SDK types from the stable surface.
2. **`pub_module_level_const_missing`: `vigil::logs::NON_FINITE`.** ADR-0004 decision 4 explicitly makes this documentation constant crate-private; its spellings remain documented in the logs module and ADR-0001.
3. **`struct_missing`: `vigil::logs::OtlpJsonLogExporter`, `vigil::sink::AppendFile`, `vigil::sink::MemorySink`.** ADR-0004 decision 4 puts these types outside stable semver behind the compiler cfg. They remain available to applications opting in; no Cargo feature can opt applications in transitively.
4. **`trait_missing`: `vigil::sink::LineSink`.** ADR-0004 decision 4 places this custom-storage trait and its implementations under the same unstable surface and keeps the trait unsealed.

No major finding is suppressed, and no change is made to the release type. The dated ADR amendment documents the auditable label mechanism and the architect/owner's review responsibility. Live API state replaces event-payload labels, including on reruns. Adding/removing this label triggers its own evaluation; stale payloads cannot retain approval after evaluation completes. The ADR explicitly documents the removal merge window: the old green Summary can remain current until the removal run finishes semver and starts its failing summary; the owner must wait for the latest label evaluation before merging.
