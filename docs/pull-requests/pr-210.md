# [PR 210](https://github.com/vig-os/vigil/pull/210) refactor(audit): Strict×Collect via runs::scan_segment + Record(Err) Collect entry (#197 R2b S3a′)

## Summary

Moves `storage::scan_inner`'s strict single-pass loop into `runs::scan_segment`, a sibling of `runs::history_segment` (ruling 197-d1 addendum 24, option A). `storage::scan_inner` is now a thin shim (byte I/O + `on_feed` only). The per-line `LineEventKind` dispatch is factored into one shared `dispatch_line` helper used by both `scan_segment` AND `history_segment`'s tolerant fallback; after this PR `runs.rs` contains exactly one `match` over `LineEventKind` outside `#[cfg(test)]` (addendum 24.3). The `Line` -> `LineEventKind` decode is a single `decode_line_kind` helper in `storage.rs` (addendum 24.3 / 20.1), replacing two copies in `storage.rs`.

Adds the Strict x Collect surface: `new_collect_strict`, `finish_collect_strict`, `feed_record_err_strict`, and four `feed_*_collect_strict` wrappers; plus `feed_record_err_collect_tolerant` for the tolerant Collect walk's `Record(Err)` entry (addendum 17.1). A shared `finish_strict_check` helper means `EmptyLiveFile` / `MissingHead` / `ResumeCheckpointLacksDeclaration` have exactly one construction site each across Stop and Collect; the gate's `corrupt`-site count stays at 50.

Base: `a1c2461` (S3a merged as #206). Addendum references: 16, 17.1, 17.4, 17.5, 18, 19, 20, 21, 22, 23, 24.

## M4 statement

Mutant M4 removes `count += 1` from the duplicate-fall-through branch of `Classifier::feed_record_apply_tolerant` (runs.rs line ~1584). The whole test suite passes 194 / 0 with M4 applied, so M4 is **not expressible by any row** on the tolerant walk. Proof (also stated in-source at runs.rs ~1584):

- For `apply_checked` to return `Ok(None)` and reach that branch, the record must satisfy `head == state.head` (same hash AND same seq); the only path there is from `feed_record_apply_tolerant`'s `General` prep.
- `feed_record_prepare_tolerant` short-circuits any `allow_dup && state.head == head` to `TolerantPrep::Duplicate` (the duplicate arm, which does not call `feed_record_apply_tolerant`). The only `General` escape with `state.head == head` is `allow_dup = false` (i.e. `first || (closing && count == 1)`).
- In both those cases `record.context.seq <= state.head.seq` (because `head.seq == state.head.seq`), and the **next** check in `feed_record_prepare_tolerant` returns `Violation::SequenceDidNotIncrease` before the General branch ever reaches `feed_record_apply_tolerant`.
- Strict's `feed_record` has no equivalent fall-through: its own duplicate branch returns `Advance::Duplicate` directly and does not touch a `count` counter.

The branch is retained (per "don't delete S3a code") so the tolerant invariant stays local, with the proof in a code comment that names the guarantee site. S3b's `classify` iterator will drop the branch when the iterator obviates the duplicate short-circuit.

## M5 statement

Mutant M5 is killed by the new **SC-M5** row (`sc_m5_reset_at_boundary_carries_saved_prior`): a two-segment Collect walk through `reset_at_boundary`. Segment 0 is `[cp0, e1]` with `inherited=false`; its epilogue records `(0, 1, InvalidUndamagedSegment)`. Segment 1 is `[cp2, e2]` with `inherited=true`. Correct behaviour: `saved_prior = state_after_e1` is carried forward, cp2's first-record trial succeeds, `closing=true`, and e2 (non-resume) fires `(1, 1, FirstSuccessorLacksImmediateResume)`. Under M5 (`saved_prior = None` in `reset_at_boundary`), cp2's trial fails as genesis, `closing=false`, and `(1, 0, FirstSuccessorDoesNotCloseRun)` is recorded instead - exact list differs.

A reader-side pin is not reachable: the reader never drives `reset_at_boundary` (Stop reaction runs one segment per `history_segment`/`scan_segment` call), and the row is Collect-only.

## MSTOP statement (Stop-reaction mutant on the shared walk)

Mutant MSTOP adds a `let stop_after = matches!(line.kind, LineEventKind::RecordErr);` at the top of `history_segment`'s loop plus a `break` after `record_index += 1`. Under Stop the mutant never fires (Stop's tolerant pass propagates `Err` on `Record(Err)` via `feed_record_err_tolerant` before `record_index += 1`, so `break` is unreachable); its target is Collect, where `feed_record_err_collect_tolerant` simply records and the loop must continue.

Killed by **SC5**: on `[cp0, e1, X, e3]` the `events()` closure must return `Some` 4 times. The test wraps its counter in a `std::cell::Cell` captured by reference and asserts `consumed == 4` on return. Under MSTOP only 3 events are consumed (the loop breaks right after `X` and never pulls `e3`), so the assertion fails with exit 101. Revert, test passes 0.

## Changed

- `storage::scan_inner` is a thin shim over `runs::scan_segment(Reaction::Stop, ...)`: byte-level I/O, writer-only `cp_time`/`since_cp`/`last_offset`/`last_newline`, and the `expected`/`found` writeback. The `found` writeback fires on BOTH strict advances (base-identical to `a1c2461`).
- `history_segment`'s tolerant fallback replaces its inline `LineEventKind` match with `dispatch_line`; duplicate-arm `on_feed` still fires through the shared helper.
- Two copies of the `Line` -> `LineEventKind` decode in `storage.rs` (addendum 24.3 / 20.1) fold into a single `decode_line_kind(Vec<u8>) -> LineEventKind` helper. A mutant on its `Fragment` arm (swap to `Unparsable`) fails 16 storage pins, hitting hist and strict reader paths together (see the MDEC row above).
