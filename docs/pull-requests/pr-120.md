# [PR 120](https://github.com/vig-os/vigil/pull/120) docs(adr): ADR-0005 amendment 10, archiving and run review (#107)

## Description

ADR-0005 amendment 10 (#107, architect ruling 107-d1 / R3): how deletion of a trail's prefix or tail is detected across archiving, and how a reviewer signs off a run sealed by `resume`. A decision document; no code.

## Type of Change

- [x] `docs` -- Documentation only

## Changes Made

- **Decision 2, archiving:** seven steps. Copy from the verified snapshot (4), remove (5), verify in place per batch with the previous batch's start (6), scheduled end check of each batch (7). Step 1's criterion is "no error and no warning a reviewer has not accepted".
- **Decision 11:** `--end-before` (library `end_before`) and finding `UnanchoredEnd` for step 7; the `accept-run <seq> <hash> <ranges digest> <reviewer> <reason>` review line with its exact finding list; the run's `SegmentStructure` names every loss point's missing `seq` range; the ranges digest encoding; exit codes return to 0 with an accepted run.
- **Decisions 5, 6, 8, 10, 16 and amendment 6:** the sentences R2 item 4 lists (and the few others the greps found) reworded; `open` is structural, `verify` decides.
- **New decision 18:** pre-mortem findings against the rules that close them, why `accept-run` does not reopen P1, ten named residuals with who catches each, README duties for B3e, threat-model table, a table of every changed sentence.
- **Tests** (decision 11 list): ten scenario groups (H1 layout, tail cut, batch 2, inputs outside a batch, run laundering, `accept-run` digest mismatch, exact list, archive criterion with a run, digest vector, Collector copy, `open`), named as #13 acceptance items.
- Index row in `docs/adr/README.md` (also adds the missing amendments 6 and 8).

**Choices R3 left open (see Alternatives considered):** step 7 uses the archive record (start line, plus the resume line for a resume start) rather than an explicit `--expect-end <seq>:<hash>`. It is passed with `--end-before`, which also ends the verified range, so inputs above the end are `OutOfRange` (anchored end) or `UnanchoredEnd`. Without that rule a batch cannot be verified alone against the full trust, anchor, receipt and review files (a later key rotation's `through=` pin would be `RevocationMismatch`). This is the one rule beyond the ruling's wording; it mirrors the anchored start and weakens nothing, since inputs above the end are checked by the live trail's verification.

## Round 2 (architect ruling 107-d2)

- Step 7's expected end is the batch-start anchor entry from the anchor store (`--end-anchor`); the archive record must byte-equal it (`AnchorMismatch`), no entry is `UnanchoredEnd`; a record at or above the end's `seq` is `TrailEnded`, not `DuplicateRecord`. New residual 11 (compromised anchor store); residuals 1 and 2 corrected.
- `accept-run` digest renamed run digest: also commits `Unparsable` spans (decision 5 gap digest reused) and anchored entries; anchors and pins in a named range accepted only with the closing opening checkpoint anchored (both halves of decision 5's gap rule cited). Residuals 4 and 5 updated; exact encoding given.
- Corrected `--end-before` rationale (needed after a later key rotation); `--start-from` reads one line; missing 107-d1 markers added; 18.6 table extended; test bullets added.
- Reader/amendment-9 sentences untouched.

## Round 3 (architect ruling 107-d3)

- A span is defined in its own right: a maximal run of non-record bytes (fragments, repair newlines, `Unparsable` lines); the gap digest is only the construction pinning it.
- The run digest commits ranges and spans only (no anchored entries). Anchors and pins in a named range are `Accepted` when the closing opening checkpoint is anchored in the verification and the digest matches; why that keeps 107-d2's security is stated.
- Four contradictions removed (decision 6, 18.6 row, test list); `--end-anchor` in the CLI synopsis and counted as an anchor for every rule; `--start-from` takes the batch-start anchor entry; residual 5 states what stays open; markers and 18.6 table complete.
- Rebased onto dev (`cd54d60`).

#### Ruling 107-d2 (architect): record it in the amendment, citing "architect ruling 107-d2"

**A. The step-7 end comes from the anchor store, not only from the archive record.** The archive record is kept with the archive (l.186), so an attacker who can delete inside the archive (residual 1) can also rewrite it.

The attack:
- delete batch n from an anchored periodic checkpoint P onwards;
- replace the record with P's own line;
- step 7 then links cleanly (l.735);
- the real start is `OutOfRange`, because P is anchored (l.736), and the run exits 0.

Rule:
- Step 7's expected end is the **batch-start anchor entry** (`seq`, hash) held in the anchor store, which archiving already writes per R3.
- The archive record must byte-equal the line that anchor names. A mismatch, or no batch-start anchor at all, is an error, not a warning.
- State the trust assumption: step 7 relies on the integrity of the anchor store, as every anchored check does. Add a residual row for a compromised anchor store. Then correct residual 1 (l.1111) so it says truthfully who catches what.
- Also state that a record at or above the end's `seq` in the checked range is an error, not `DuplicateRecord`. Fix l.735's "files ending later give `ChainBroken`" claim to match: verification orders by `seq`.

**B. `accept-run` coverage, decided now, before #13 freezes `vigil.audit.v1.run-ranges` (l.1228).** l.464 makes an `Unparsable` line, sealed by resume, the archetypal run. Leaving it uncovered means the typical honest run can never be archived.
- **(i) `Unparsable` spans.** The run digest also covers every byte span in the run's segments that holds no record. Each span is pinned by:
  - the `seq` of the last complete record before it (or the segment start);
  - its byte length;
  - blake3 of its bytes.

  This is the same construction as the `TornWrite` gap digest; cite it and reuse its encoding (DRY). `accept-run` accepts `Unparsable` only for the spans it commits. A later keyless append, removal or edit is `AcceptMismatch`. Update residual 5 to say what this closes.
- **(ii) Anchors and revocation pins inside a named range** are accepted only when both of these hold:
  - the run's closing opening checkpoint is anchored;
  - each (`seq`, hash) is committed in the digest.

  This mirrors decision 5's rule for resume gaps (l.402, l.915). Cite both halves of that rule, the unconfirmed and the anchored route; today l.798 and l.1105 cite only the first.
- Give the digest encoding exactly: domain tag, ranges, spans, anchored entries, in a fixed order and big-endian. Add test bullets to the amendment's test list:
  - an `Unparsable` span accepted, then the span edited → `AcceptMismatch`;
  - an anchor inside the range without the closing checkpoint anchored → error.

**C. Your choices beyond R3:**
- (a) the archive record, now tied to the anchor per A: accepted.
- (b) the syntax: accepted.
- (c) `--end-before` and `UnanchoredEnd`: accepted. Correct the rationale: it is needed for any trail whose key was rotated after the batch end (a `through=` pin is `RevocationMismatch` (l.653), and the trust file can't be cut per trail (l.694)); without a later rotation, passing only the two batch-start anchors works. Don't claim it fails on any real trail.
- (d) keep the snapshot until step 6 passes: accepted.
