# [PR 206](https://github.com/vig-os/vigil/pull/206) refactor(audit): every-violation collector (tolerant) on the shared runs::Classifier (#197 R2b S3a)

## Scope (ruling 197-d1 addendum 19)

S3a lands the every-violation collector as a reaction mode of the one
`runs::Classifier` (addendum 16 point 1), wired to **tolerant mode
only**. Behaviour on every reader path is unchanged; the collector is
a `pub(crate)` surface that nothing in `storage.rs`'s reader paths
calls.

Round 3 (addendum 19): `history_segment`'s strict-pass-then-tolerant-
fallback-from-saved-state sequence, the end-of-segment epilogue, and
the tolerant-mode duplicate-line arm each live in ONE function
parameterised by `Reaction`. The reader calls each with `Stop`; the
collector's `history_segment` entry calls them with `Collect`. A
fold-(iii) mismatch now marks its segment damaged for the end-of-
segment checks, so no derived `InvalidUndamagedSegment` follows.

What this PR ships (unchanged from round 2 except where noted):

- The one-classifier `Reaction{Stop, Collect}` with a single
  `on_violation` dispatcher (addendum 16 point 1).
- `enum Violation` (35 variants), `fn detail`, `const ALL`, and
  `impl From<Violation> for AuditError` (addendum 16 point 3).
- Tolerant-only Collect surface: `new_collect`, `reset_at_boundary`,
  `feed_record_collect`, `feed_fragment_collect`, `feed_unparsable_collect`,
  `finish_collect`.
- **ADDED round 3:** `runs::history_segment` dispatch function
  parameterised by `Reaction` (addendum 19.1): strict-first, on
  `CorruptTrail` fall through to tolerant with the supplied reaction,
  on any other `Err` propagate. The reader (`storage.rs::history_segment`)
  uses it with `Reaction::Stop`.
- **ADDED round 3:** `Classifier::feed_record_tolerant_entry` -- the
  ONE tolerant duplicate-line entry (prepare -> take_gap ->
  check_attestation) shared by the reader (`storage.rs::history_segment`
  fallback) and the collector (`Classifier::feed_record_collect`).
- **ADDED round 3:** `Classifier::run_end_of_segment_epilogue` -- the
  ONE end-of-segment epilogue (first-successor-lacks-resume ->
  count==0 damaged latch -> invalid-undamaged-segment -> damaged
  promotes run_flag -> resume-lacks-declaration) shared by
  `finish_tolerant` (Stop), `finish_collect` (Collect) and
  `reset_at_boundary` (Collect at every boundary).
- **ADDED round 3:** On a fold-(iii) salvage, `self.damaged = true`
  (addendum 19.2): the recorded mismatch marks its segment damaged so
  no derived `InvalidUndamagedSegment` is produced.
- The duplicate-line handling (addendum 17.2) is the reader's own code
  path with only the reaction differing.
- Fold (iii) "as if matched" (addendum 17.3): on a
  `Violation::CheckpointMmrDiffers` from `apply_checked`, the record-
  apply callsite under `Reaction::Collect` records the mismatch
  without latching and re-applies through `apply_checked(.., compare_mmr = false)`,
  so classification continues as the **computed fold including every
  record's leaf** (the module doc at `runs.rs` ~34-37 now says this
  verbatim).
- End-of-segment checks (addendum 17.4): the three tolerant finish-
  time checks run inside `reset_at_boundary` at every boundary and
  inside `finish_collect` at the last segment, and are skipped once
  the run has been ended by an earlier violation (`recovery_pending`).
- Coverage gate (addendum 17.5): the gate derives the `Violation`
  variant set by `syn`-parsing `enum Violation` in `runs.rs`, requires
  `Violation::ALL` to mirror it, and excludes `#[cfg(test)]` code
  from site counting. **ADDED round 3:** the exclusion now also
  covers `ImplItemFn` -- a `#[cfg(test)] fn` inside an `impl` block
  was previously counted as a product site. The gate still asserts
  9 + 41 = 50 sites.

### Reader differential (addendum 19.1)

The reader-side changes in `storage.rs` are a **lossless refactor**:

1. The strict-pass-then-tolerant match is replaced by
   `runs::history_segment::<State, _>(Reaction::Stop, || scan_inner(...))`.
   The dispatch is byte-identical: `Ok(s)` -> Strict, `Err(CorruptTrail)`
   -> Tolerant, other `Err` -> propagate.
2. The inline `prepare + check_attestation(Duplicate)` / `prepare +
   check_attestation(General)` pair is replaced by
   `classifier.feed_record_tolerant_entry(..)` which runs `prepare`
   -> `take_gap` -> `check_attestation`, then returns the
   `TolerantPrep` so the caller branches (Duplicate: continue;
   General: `feed_record_apply_tolerant`). Each branch calls
   `check_attestation` exactly once, same order as before.

Behaviour equivalence is pinned by the 160 history_segment /
scan_inner / refresh / resume path tests + the 26 audit_verify
tests + the 853 lib tests all passing on this head (same count and
set as on base after accounting for the six new collector rows
added this round). An exhaustive layout-level sha256 differential
is deferred to the independent fresh-context reviewer.

### Tolerant first-equality over `history_segment` x4

Per ruling 197-d1 addendum 19.1: Collect on `history_segment` runs
the strict trial first; on strict Ok records NOTHING (empty
violations), exactly as the reader returns Ok. Pinned by:

- `collector_history_segment_entry_matches_reader_on_strict_pass_ok`
  -- D1 (`[cp0, e1, cp2]` on `history_segment(true, false)`): strict
  passes, collector records empty -- 0 mismatches versus reader Ok.
- `collector_history_segment_entry_salvages_fold_iii_mismatch` --
  `[cp0, e1, bad_cp2, e3, cp4]`: strict fails at bad_cp2 with
  `CheckpointMmrDiffers`, tolerant Collect records exactly
  `[CheckpointMmrDiffers]`, final MMR is the computed fold including
  bad_cp2's leaf.
- Four `collector_fold_iii_mismatch_on_history_segment_*` rows
  (one per (opening, run) combination) replace the previous single
  `collector_fold_iii_mismatch_continues_full_list` row and pin the
  exact full recorded list on each `history_segment` path:
  - `(true, false)` / `(false, false)` / `(false, true)`: exactly
    `[(2, CheckpointMmrDiffers)]` plus final MMR = computed fold
    including every record's leaf (addendum 17.3 / 19.2).
  - `(true, true)`: strict `UnclosedSegmentLacksResume` at e1 then
    tolerant Collect's `FirstSuccessorLacksImmediateResume` at
    record_index=1 latches `recovery_pending` so bad_cp2 is not
    reached; recorded list is exactly
    `[(1, FirstSuccessorLacksImmediateResume)]` and this matches the
    reader's first `Err` on the same layout and path.

The 853 lib tests (including every `pin_hs_*`) all pass, which
confirms the reader's per-path first `Err` detail is unchanged on
every short layout the fixture suite exercises. An exhaustive
`history_segment` x 4 layout-level first-equality sweep is deferred
to the independent fresh-context reviewer.
