### Round 4 code changes (addendum 22, fixed list)

1. **Duplicate arm advances the offset (addendum 22.1).** The tolerant
   fallback's duplicate-line arm now flows through the shared `on_feed`
   callback as `FeedEvent::Duplicate`: `final_offset` advances past the
   duplicate (so `s.length` is byte-identical to base), while `state.offset`
   and `state.newline` stay untouched (addendum 17.2). Pin
   `pin_hs_fallback_duplicate_advances_length_through_feed_callback` on
   `[cp0,e1,cp2] + [e3,e3]` with `history_segment(true,false)` asserts
   `s.length == 2 × line(e3).len()`. The pin passes on base **and** on
   head; mutant M3 (`on_feed` skipped on the duplicate arm) fails the
   pin with exit 101.

2. **`found` is one shared buffer across both passes (addendum 22.2).**
   `storage::history_segment` now threads a single `RefCell<Option<Record>>`
   through the strict closure and the `on_feed` closure, base-identical to
   the one `&mut found` base passed through both passes. The writeback runs
   **before** the `?`, so the strict pass's partial writes survive both on
   `CorruptTrail` (tolerant Ok) and on a tolerant-side `Err`. Three pins
   (two from round 4, one added in round 7 per addendum 23):
     - `pin_hs_found_persists_on_strict_write_before_tolerant_duplicate`
       covers the Ok path (strict writes `*found` on the Advance::Duplicate
       in `scan_inner`, then the trailing `not json` line trips strict;
       the tolerant fallback encounters the duplicate as `TolerantPrep::Duplicate`
       and `on_feed` is `FeedEvent::Duplicate`, so `found` is NOT re-written
       and strict's write survives).
     - `pin_hs_found_persists_on_err_after_strict_partial_write` covers
       the Err path (strict writes `*found = Some(e1)`, then `broken_e2`
       errors; the writeback runs before the `?` propagates).
     - `pin_hs_on_feed_writes_found_on_opening_tolerant_walk_at_seq_max`
       (round-7 F1, addendum 23) covers the `on_feed` writeback branch
       itself: `history_segment(opening=true, *)` on a layout where the
       opening fragment makes strict fail without reaching any record and
       the tolerant fallback is the only writer of `found`. The matching
       head is an archived-prefix checkpoint pinned to the saturated-seq
       ceiling (`i64::MAX as u64`, the largest `head.seq` the on-disk
       wire format admits; addendum 15's saturated-seq branch). Deleting
       the writeback or negating `expected == Some(head)` leaves the
       shared buffer empty and `found` returns to the caller as `None`;
       on base the fallback wrote `*found` directly in the same loop,
       so base keeps `Some(cp_max)` here too.
   All three pins pass on base **and** on head; a revert of either fix,
   or any of the two round-7 mutants on the writeback branch
   (delete / negate), flips its named pin to exit 101.

3. **Collector rows exercise a non-empty prior and `unsealed_boundary=true`
   (addendum 22.3).** A new helper
   `run_orchestration_collect_with(opening, genesis, run, records, prior_run,
   unsealed_boundary)` drives the shared walk under `Reaction::Collect` with
   the two parameters that round-3 rows left at `None` / `false`. New row
   `collector_shared_walk_mutants_fail_on_prior_and_unsealed_boundary` on
   `prior_run=Some(cp0.run)` + `unsealed_boundary=true` + `records=[cp1, e2]`
   pins the exact collected list `[(1, FirstSuccessorLacksImmediateResume)]`.
   Mutant M1 (`inherited = run_in`, dropping `unsealed_boundary`) and
   mutant M2 (`saved_prior = None`) each change this list; both now fail
   a collector row **and** a reader pin.

4. **Argument struct replaces `#[allow(clippy::too_many_arguments)]`
   (addendum 22.4).** The five segment-shape inputs
   (`ctx`, `prior_run`, `unsealed_boundary`, `run_in`, `trail`) move into
   `pub(crate) struct HistorySegmentArgs { … }`. `runs::history_segment`
   is now a 5-argument function; `cargo clippy -D warnings` stays clean
   on `--all-features` and on `--no-default-features --features audit`.
