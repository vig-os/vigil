# [PR 250](https://github.com/vig-os/vigil/pull/250) feat(audit): set aside inputs above the end of an archive batch

## What changed

Inputs (anchors, `through=` pins, trust-file `end=`) whose `seq` is strictly above the end record's last line's `seq` under `Verifier::end_before` are **set aside** instead of being checked against the batch, because nothing above the end can be checked (ADR-0005 decision 11 "It ends the range" and "Inputs outside a batch"; ruling 13-V6-d7).

- `position::Classifier` gains the `AboveEnd { anchored }` arm. The classifier is the one place that decides position, and `set_aside` builds both suffixes (`below start seq <s>` and `above end seq <E>`) from one place through the shared `position::above_end_finding`. `E` is the end record's last line's `seq`: the resume line when present, otherwise the checkpoint.
- A trust-file `end=<s>` is routed through a new `Classifier::set_aside_above_end` helper, so an `end=` below an accepted start keeps its 13-V5-d5 behaviour (decision 11 does not list `end=` among the below-start inputs; ruling 13-V6-d7 clarification 13-V6-d7a). Only `end.rs` calls `set_aside_above_end`.
- "Anchored" now includes "the anchor matches": `Context::is_anchored` combines presence, byte-equality (one place, `Context::bytes_match`) and the result of the shared anchor rule for the end anchor. The end anchor is evaluated once via `anchors::match_only`; the result flows through `Context::end_anchor_matches` and the mismatch finding (if any) is pushed before the classifier is built. `anchors::check` skips that identity so the rule runs in exactly one place.
- The end anchor is never set aside (ruling 13-V6-d7 clarification 13-V6-d7a): `anchors::evaluate` skips the position step for the end anchor. Mismatched end anchors flow through the ordinary rule (`no record`, `seq is forked`, `hash differs`), so `E3a` of `end_before_tests` is back to its base value.
- `RevocationUnconfirmed` is not reported in an end-bounded verification (a confirming checkpoint may lie above the end); the pinned and bounded checks still run. One place in `revocation::confirmation`.
- A trust-file `end=<s>` with `s > E` replaces both `TrailEnded` conditions and grants nothing from ruling 13-V5-d5; at exactly `s == E` it is in range and checked as usual.
- Another trail's anchor stays `AnchorMismatch … trail differs`: the trail check runs before the position classifier.
- ADR-0005 decision 11 "It ends the range" gets one amendment line; `OutOfRange`, `UnanchoredEnd` and `Verifier::end_before` rustdoc gain the above-end grammars and rule.
