# [PR 76](https://github.com/vig-os/vigil/pull/76) test(properties): cover log bounds and segment ordering

## Description

Add generated regression coverage for bounded OTLP/JSON log export and chronological segment naming. Production behavior and public API are unchanged; the only source edit is a private test module in `rotate.rs`, as approved in the issue follow-up.

## Changes Made

- Add `proptest` as a dev dependency with only `std`; generators and shrinking justify the dependency. Disable default fork/timeout/bit-set features to avoid unnecessary dependencies. The existing lock already contains its dependency graph; no unrelated packages are updated.
- Check payload caps, valid UTF-8/JSON, deterministic bytes, record conservation and byte-identical fitting bodies/attribute arrays across splits, immutable envelopes/keys/event names, largest-first exact escaped-byte overflow removal, nested map/list values, base64 quartet boundaries, identity-preserving diagnostic markers, and NaN/±Inf spellings. Each batch uses 3–6 generated scope names and includes healthy and oversized neighbours.
- Put the largest attribute at generated positions in both insertion orders, alongside a comparably large value. Equal-size tie-breaking is unspecified by ADR-0001 and documented in the test module: either maximum may absorb the exact overflow, with deterministic output.
- Generate non-zero timestamp nanos and compare same-second segments as well as full timestamp/counter keys.
- Ignore generated failure seeds in the durable project ignore fragment and its generated root counterpart: minimized invariant examples are kept as reviewed tests.
- Use an unwind-safe temporary-directory guard, verified with an intentional panic, for public segment-order tests.
- Exercise the private production name generator/parser and integer ordering, plus public `segments()` ordering over generated files, including counters 999999 and 1000000. Validate both arbitrary and valid signal names.
- Use 64 cases per property (11 properties / 704 cases per feature configuration). The expanded debug property run takes approximately one second excluding compilation; current release measurements are listed below.
- No separate fuzzing: structured generators cover Unicode, escape classes, nesting, base64 residue classes, immutable structural oversize, non-finite values, and wide integer counters. These APIs take typed SDK records and filenames; there is no remaining unstructured parser gap in this change's scope that would justify a second harness.
