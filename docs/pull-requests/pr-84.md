# [PR 84](https://github.com/vig-os/vigil/pull/84) fix(logs): make JSON key order independent of consumer features

## Description

Fix OTLP/JSON byte order changing when a consumer enables `serde_json/preserve_order`. A shared custom serializer applies declarative priority keys and sorts remaining keys alphabetically. Logs now apply ADR-0006 decision 3: scope arrays, record arrays, observed time, then event time come first, including split, shortened and diagnostic records.

## Type of Change

- [x] `fix` -- Bug fix

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- Add one reusable ordered serializer; logs supply the priority-key table. No stable public API changes.
- Keep upstream OTLP field encodings and non-finite patching through direct `to_value` projection; only the explicit ordered writer emits final bytes. Reuse that projection during splitting, eliminating both text parses and their precision/depth costs. A pre-conversion depth guard limits AnyValues to 16 container edges; deeper records are counted as lost while healthy neighbors are exported. Rustdoc and ADR-0001 decision 10 document this choice. Boundary tests cover 16, 17 and 10,000 edges for list/map bodies and attributes.
- Emit split-line metadata as suffixes without serializing growing batches.
- Retain the old golden as a semantic baseline and test content equality, timestamps within 128 bytes, deterministic object ordering, splitting, shortening, stubs, deep nesting and finite-double preservation. Two blocking CI matrix jobs run golden/determinism tests with default maps and with `test-preserve-order`; the preserve-order lane also runs audit shuffle/hash and committed-corpus tests.
- Record dated ADR-0001 and ADR-0006 amendments. Metrics/traces tables remain in #7/#8; fingerprint conformance #60 is outside this change.

Both builds and all six perf runs exited 0. The 1.05x target is narrowly missed. The serializer now emits single-field objects directly, compares two-field objects once, resolves rules once per array, and avoids collecting/sorting already alphabetically ordered maps after priority lookup. The remaining cost includes the mandatory SDK depth validation and explicit priority-key emission around the upstream OTLP projection. A scratch-only ablation without the SDK guard measured 1.056x (629,063 base versus 664,066 head instructions/export), so most residual overhead is explicit ordered emission. Eliminating that work would require duplicating the upstream OTLP serializer or bypassing the depth guard; this implementation keeps the format contract and bounded input processing explicit.

`serde` is a direct dependency for serialization traits and was already transitive. `serde_json/raw_value` is retained for the strict audit reader; `float_roundtrip` and `unbounded_depth` are removed. Direct projection preserves finite doubles, and splitting reuses the same value tree. Both paths now share the explicit depth bound. The new SDK depth test fails against the previous head with exit 101 (the over-deep record is exported), and passes here. SDK inputs are borrowed: the exporter avoids recursive conversion of over-deep input, while caller-owned SDK destruction remains outside its contract.

The opt-in `test-preserve-order` feature adds the existing crates.io `indexmap`, `hashbrown` and `equivalent` dependencies only for consumer-feature regression coverage. The default dependency graph has neither `preserve_order`, `float_roundtrip` nor `unbounded_depth`.

Rebased onto dev after PR #75 and PR #85 merged; the final corpus includes amendment-2 normal/resume checkpoints and authenticated repair fields. Regenerated the logs golden and 256-line audit writer corpus; comparison against the previous corpus confirms identical decoded JSON content. New tests verify shuffled record/checkpoint keys preserve canonical protobuf bytes and hashes, and decompress the committed corpus to check its digest, every `Record::parse_line` result, and time-first order. The stale corpus proof fails with exit 101. Independent codec/primitives format vectors remain valid and unchanged.

The new crates.io dev dependency `flate2` (and its compression/checksum dependencies) lets ordinary audit tests verify the committed gzip corpus directly, without relying on an external decompressor. It adds no production dependency.
