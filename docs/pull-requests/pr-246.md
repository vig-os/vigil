# [PR 246](https://github.com/vig-os/vigil/pull/246) feat(audit): add Verifier::end_before with the end record as the following segment

## What

`Verifier::end_before(&str, Option<Checkpoint>) -> Result<Self, AuditError>` verifies one archive batch against its end record and that record's batch-start anchor entry (ADR-0005 decision 11 `.end_before`; ruling 13-V6-d4):

- the record (one or two LF-separated lines, one optional final LF) parses through `Checkpoint::parse` and one unified resume filter that rejects an unparsable, multi-record or non-`vigil.audit.resume` second line with the same reason; its lines go in as one in-memory native segment that follows the files, walked by the shared classifier so every existing rule applies to them;
- file records of the verified trail with `seq` at or above the end checkpoint's `seq` yield one `TrailEnded` (error) at the first such record with detail `end_before seq <e>: records seq <a>..=<b> at or above the end`; a byte-identical file copy of an end line never becomes `DuplicateRecord`, and a different record at such a `seq` is still `SeqConflict`;
- without an end anchor one `UnanchoredEnd` (error) fires; with an end anchor whose line is not byte-equal to the record's first line (each side without its LF; whitespace counts) one `AnchorMismatch` (error) fires; every end-record finding carries no file and no line;
- the end anchor also joins the ordinary anchors;
- `end_before` and `max_age` are mutually exclusive; a second `end_before` call replaces the first.

### End-record identification without a sentinel path

`input::Summary` and `input::Input` carry a `bool is_end_record` set exactly where the end-record input is built (`input::end_record_input`). The engine's per-`seq` copy order (`engine::check`) and the shared `verify::first_copy` sort by `(is_end_record, path, line, hash)`, so at a shared `seq` the end-record copies always sort strictly after every file copy and "first copy" is a file copy whenever one exists (ruling 13-V6-d4 point 3). File-only ordering stays `(path, line, hash)` exactly as on dev; the previous `(path, line, hash)` test (`ordering_is_seq_then_path_line_kind_with_unlocated_seq_last`) keeps its original `"a"` expectation. `end_before::first_file_copy` filters by `!r.is_end_record` (no path equality against a sentinel), and the engine's strip-location pass iterates `collection.inputs` for `Input::is_end_record` and unlocates findings whose file is one of their paths. No empty path is used as a marker anywhere.

Reader untouched: `git diff origin/dev -- src/audit/runs.rs 'src/audit/storage*.rs'` is empty.

### Known limit (follow-up, not addressed here)

A shipped file whose on-disk file name is literally `<end record>` collides with the diagnostic label `end_record_input` passes for the in-memory end-record segment. The strip-location pass identifies end-record segments by `Input::is_end_record` (not by path) so no false in-memory record is invented, but a file with that name *would* lose its own location if included in the same verify call. The collision is harmless for every honest layout (vigil writers never produce that file name) but the maintainers will file a follow-up to resolve the label clash.

## Rows

All rows are literal: each acceptance row asserts the full sorted `Vec<Finding>` with `assert_eq!` through `assert_findings`; parse rows use `assert_invalid`. Every digest, key and trail id in an expected detail is a written-out hex constant pinned by `fixture_hashes_match_literals`. Rows live in `src/audit/verify/end_before_tests.rs`.

Writer-built: E1 and E10/E10b use `AuditConfig`/`AuditTrail` (`create`, `close`, `resume`) and archive the batch by moving its segment bytes to a fresh directory. E10 pre-seeds `audit.trail` with `TRAIL` and calls `AuditConfig::resume`, so its loss-layout run digest stays pinned; E10b reuses that same loss layout under a different operator/reason. Hand-built: E3a/E3b and the rows whose scenario the real writer cannot produce (forged, parse-error, foreign, untrusted). E3a/E3b are hand-built at the fixture `TRAIL` and signer because `AuditConfig::create` always draws a random trail and the writer's wall-clock timestamps vary per run, so the writer cannot produce the E3 layout with the literal P, E2, E4 and S record hashes this PR pins in `fixture_hashes_match_literals`.
