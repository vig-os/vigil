# [PR 246](https://github.com/vig-os/vigil/pull/246) feat(audit): add Verifier::end_before with the end record as the following segment

## What

`Verifier::end_before(&str, Option<Checkpoint>) -> Result<Self, AuditError>` verifies one archive batch against its end record and that record's batch-start anchor entry (ADR-0005 decision 11 `.end_before`; ruling 13-V6-d4):

- the record (one or two LF-separated lines, one optional final LF) parses eagerly through `Checkpoint::parse` and the resume-line rules;
- its lines go in as one in-memory native segment that follows the files, walked by the shared classifier through the existing in-memory byte source, so every existing rule (chain, signatures, trust, resume declarations, run sealing, run digest) applies to them;
- file records of the verified trail with `seq` at or above the end checkpoint's `seq` yield one `TrailEnded` (error) at the first such record with detail `end_before seq <e>: records seq <a>..=<b> at or above the end`; a byte-identical file copy of an end line never becomes `DuplicateRecord`, and a different record at such a `seq` is still `SeqConflict`;
- without an end anchor one `UnanchoredEnd` (error) fires with detail `end_before seq <e>: no end anchor`; with an end anchor whose line is not byte-equal to the record's first line (each side without its LF; whitespace counts) one `AnchorMismatch` (error) fires with detail `end record differs from end anchor`; every end-record finding carries no file and no line;
- the end anchor also joins the ordinary anchors and goes through the four-step precedence against the verified set;
- `end_before` and `max_age` are mutually exclusive: the error is `InvalidConfig` from whichever call comes second, and a second `end_before` call replaces the first.

Reader untouched: `git diff origin/dev -- src/audit/runs.rs 'src/audit/storage*.rs'` is empty.
