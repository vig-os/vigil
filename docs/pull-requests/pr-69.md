# [PR 69](https://github.com/vig-os/vigil/pull/69) ci(semver): gate stable API compatibility against dev

## Description

Gate stable API compatibility against the full merge-base SHA with `origin/dev` before the first publish. An explicit minor release type prevents 0.0.0 → 0.0.0 from silently skipping every check; missing or zero-check summaries fail independently of the tool's exit status.

## Type of Change

- [x] `ci` -- CI/CD pipeline changes

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

- Add a consumer-owned CI extension job, using full Git history and the flake-pinned cargo-semver-checks 0.47.0 inside the dev shell.
- Check all Cargo features with inherited Rust/rustdoc environment flags removed and build flag overrides that suppress target and user-level Cargo configuration, so `vigil_unstable` stays off.
- Keep Git baseline generation outside the Nix derivation sandbox because it needs repository history and writable checkout storage.
- Assert positive executed-check summaries, including singular `1 check:`, and test zero-check, missing-summary, failure-summary and multiple-summary cases.
- Refuse a merge base equal to HEAD before invoking Cargo; dispatches on `dev` and dev-to-main comparisons cannot silently check the tree against itself.
- Exercise ten flag/config sources with a real no-dependency fixture that removes a cfg-gated function, verifying it remains excluded from rustdoc JSON.
- Add a dated ADR-0004 amendment assigning the allowlist gate to #42 part 3/3.
- The public-API allowlist gate arrives with #42 (part 3/3), per the agreed scope split; this PR only supplies the semver gate.

## Changelog Entry

- Semver CI compares the stable API against the merge base with `dev`, excludes unstable items despite inherited Cargo flags and rejects self-comparisons and zero-check passes ([#43](https://github.com/vig-os/vigil/issues/43)).
