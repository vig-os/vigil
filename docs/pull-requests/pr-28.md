# [PR 28](https://github.com/vig-os/vigil/pull/28) feat(init): bridge tracing into rotating OTLP logs

## Description

Implement `vigil::init("my-service")` and a configuration builder to send tracing events through a background batch processor into rotating OTLP/JSON logs. Dropping the returned guard drains the processor; storage initialization failures install a stderr subscriber and emit one warning.

## Type of Change

- [x] `feat` -- New feature

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- Attach service name, optional caller version and VCS revision, hostname, and process ID.
- Resolve XDG/HOME state paths, environment overrides, and explicit builder precedence. Reuse the rotating writer through `LineSink` without changing `rotate.rs`.
- Apply `RUST_LOG` (default info), exclude internal telemetry targets, and return a clear error for duplicate initialization or invalid service names.
- Compile the README example and document queue overflow, process-exit loss, stderr fallback, and absent trace correlation.
- Add crates.io dependencies: `tracing` supplies the caller event API; `opentelemetry-appender-tracing` 0.33 bridges events into SDK logs; `tracing-subscriber` supplies registry, environment filtering, and stderr formatting.

- Route SDK WARN/ERROR diagnostics exclusively to stderr, even when `RUST_LOG` suppresses application logs. Stderr write failures never panic.
- Set queue capacity to 65,536 records, export batches to 512, and scheduled delay to one second. `VIGIL_QUEUE_SIZE` and `Config::queue_size` override capacity.
- Warn on malformed numeric environment settings, ignore empty directory overrides and relative XDG paths, name failed paths, and reject existing global subscribers before side effects.
- Name the bridge scope `vigil`, and report shutdown failures after a five-second wait.

- Reserve the global subscriber before opening storage, then attach the destination with a reload handle. An existing `log` logger produces one warning and keeps tracing working. Concurrent losing initializers create no storage.
- Cap queue capacity at 1,048,576 slots and warn when clamping. Document approximately 16 B per reserved slot and 0.4 KB per queued small record.
- Treat empty `VIGIL_*` values as unset, reject relative HOME paths, and explain rejected fallback paths.
- Isolate file-size-limited test child stdout/stderr from inherited redirected files.
- Direct crates.io dependency `tracing-log` makes logger bridge installation explicitly best effort; dev dependency `log` tests coexistence with an existing logger. Both were already transitive dependencies.

## Additional Notes

The entered-span probe confirms empty OTLP trace/span IDs. Follow-up #26 is in milestone 0.2.0 — metrics + traces; no trace bridge is added here.

Finite batches parse as protobuf `LogsData`. NaN batches are checked with `serde_json`: the existing exporter deliberately emits the OTLP-required string spelling, which the upstream protobuf JSON reader rejects (documented in `logs::NON_FINITE`).

Regression evidence before fixes: seven review tests failed (exit 101), including only 3,096/10,000 burst records and a panic with stderr redirected to `/dev/full`. The held-directory-lock regression also failed separately (exit 101) because no shutdown-loss warning appeared. All now pass. Tests re-execute child processes for subscriber isolation.

Round-three regressions also failed before fixes (exit 101): logger coexistence, oversized queue capacity, empty environment settings, relative-path diagnostics, concurrent losing initialization creating storage, and short-write output redirected to a file exceeding 1 KiB. All now pass.

Validation: three `cargo test` runs (one redirected to `/tmp/vigil-5-r3-cargo-test.log`), `nix flake check -L` inside `nix develop`, and `just precommit` all exit 0.
