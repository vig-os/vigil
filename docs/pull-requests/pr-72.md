# [PR 72](https://github.com/vig-os/vigil/pull/72) feat(init): add fallible lifecycle and log loss reporting (2/3)

## Description

Add fallible lifecycle methods and per-period log loss reporting, part 2/3 of ADR-0004. A live pipeline can flush repeatedly or shut down with a chosen timeout, returning typed outcomes and lower bounds on missing records. Every successful flush counts queue overflow independently of SDK diagnostic events and consumer filters.

## Changes Made

- ADR-0004 decisions 2, 3 and 5: add `Guard::flush`, `shutdown`, `shutdown_with_timeout`, `FlushError`, `FlushErrorKind` and `Signal`; outcomes prefer `Timeout`, then `Failed`, then `DataLost`. Preserve typed SDK timeouts separately for concurrent callers.
- Amend decision 3, dated 2026-10-11: count completed processor emits and records reaching the exporter. A successful drain subtracts exporter arrivals from its acceptance watermark, then subtracts overflow already counted. Concurrent newer arrivals deliberately reduce the lower bound; outstanding records on failed/timed-out drains are not assumed lost. The SDK shutdown total supplements this accounting without duplicates. This fixes both later overflow periods and consumer filters hiding the SDK's one-time diagnostic.
- ADR-0003 decisions 3, 4 and 23: stop recording before draining and capture the SDK shutdown overflow event on the shutdown thread, forwarding every other event. Drop prints only loss counts not already printed by runtime summaries and names the actual outcome. Explicit shutdown returns countable losses without repeating their stderr summary. Thread creation is fallible and falls back to inline shutdown.
- Count failed durable lines in records, excluding originals on earlier successful split lines and including diagnostic replacements once. Preserve encoder bytes and ordering.
- Document the SDK's 64-slot control channel: enough simultaneous flush requests can return `Failed` before the timeout. Document nextest isolation and shared-static tests in rustdoc and README; make the rotation doctest assert non-default values and zero clamping.

- Run each subscriber-sensitive library test in its own child process, including inline Guard shutdown. Audit all library tests for direct and indirect subscriber installation. CI now gates plain Cargo tests for all targets and features with default threads and with one test thread, in addition to nextest.

`tracing-core` becomes a direct dependency to forward `Subscriber::current_span` with its exact type. It was already transitive; no new crate or version enters the graph.

## Changelog Entry

### Added

- Fallible `Guard::flush`, `shutdown` and `shutdown_with_timeout`, with `FlushError`, `FlushErrorKind` and `Signal` reporting period loss lower bounds, timeout precedence and queue overflow on every flush independently of consumer filters; Drop prints only unreported losses and shutdown falls back inline if thread creation fails (ADR-0004 decisions 2, 3 and 5; [#42](https://github.com/vig-os/vigil/issues/42)).

### Changed

- Shutdown stops recording before draining; explicit shutdown reports losses to the caller without repeating them on stderr, and Drop reports them once. Failed durable log lines count only records not already written, plus diagnostic replacements (ADR-0003 decisions 3, 4 and 23; [#42](https://github.com/vig-os/vigil/issues/42)).

### Fixed

- Isolate subscriber-installing library tests in child processes; CI also runs plain Cargo tests for all targets and features with default and single test threads ([#42](https://github.com/vig-os/vigil/issues/42)).

## Testing

The latter composes a consumer-owned subscriber with `EnvFilter("info,opentelemetry=error")`; the old flush returns `Ok` despite drops. After the fix, both pass and verify two lossy periods, total lost plus exported records equals 100, and shutdown does not count flushed overflow again. Drop also reports pending overflow after its value was consumed by flush.

The shutdown fallback test requests a page-aligned, impossibly large thread stack, causing thread creation to return an OS error without exhausting host resources; inline shutdown succeeds and the retained SDK provider confirms it is shut down. ## Additional Notes

Part 1/3 merged as #67. Part 3/3, after this PR merges, covers unstable exporter/sink visibility, unstable documentation and metadata, the stable API snapshot and enforcement, and remaining #36 documentation. Metrics/traces and `Config::install_opentelemetry_globals` remain deferred to #7/#8; their counters currently return zero.

Losses remain lower bounds with concurrent arrivals or incomplete drains. Concurrent records during shutdown may arrive after its watermark/counter read or worker disconnection. Compiling WARN out removes only the supplemental SDK shutdown reconciliation; boundary accounting remains independent. Timeout can leave the SDK worker running until storage unblocks. These limits are documented publicly.
