# [PR 149](https://github.com/vig-os/vigil/pull/149) feat(traces): wire traces into init and Guard (#8 8c-2)

## Round 3: prove overlap

The previous test checked distinct thread IDs, which still allowed logs to finish before traces was spawned. Both flush callbacks now announce entry and wait to observe the other entering before returning. Successful receives establish overlap without an elapsed-time assertion; the two-second receive timeout only bounds failure of serial implementations. The exact review mutant (finish logs, then spawn and join traces) fails at runtime with exit **101**, rather than hanging; reverting it restores exit **0**. Product scheduling is unchanged.

## Round 2: CI failure diagnosis and correction

CI run 38404829459 failed before reaching any concurrency assertion: `DirectoryBlock::new` spawned `flock`, but the hermetic Nix test PATH did not contain that executable (`ENOENT` at `src/init.rs:3454`). The host development environment provided `flock`, so ordinary Cargo/nextest runs passed. Reproduced at the original bb46471 head with both `nix flake check -L` and `nix build .#checks.x86_64-linux.nextest -L`: default nextest profile, one process per test, identical runtime failure. This was an undeclared external test dependency, not a product concurrency failure.

The directory-lock holder now runs the same Rust test executable in a separate process, uses `File::lock`, and handshakes over stdin/stdout. Completion uses the shared child verifier and checks `1 passed;`. No external locking utility or shell is required. The actual blocked flush/shutdown deadline tests remain. Flush scheduling is extracted into one private production seam. Round 3 replaces the insufficient thread-identity assertion with a two-way channel rendezvous: each callback must observe the other entering before it can return. A bounded receive timeout is only a deadlock fail-safe. The mutant that finishes logs before spawning and joining traces fails at runtime with exit 101; restored code exits 0. No retries, sleeps, widened timeouts or relaxed assertions were added.

All acceptance tests remain present, including non-blocking `TraceStorage::close`, refused later writes counted as four lost spans, and both metrics-off and metrics-on blocked shutdown contracts. Round 2 preserves the CHANGELOG entries from both #147 and #148. The final rebase includes #147’s operator CLI; its README introduction is reconciled with implemented traces and pending verifier/propagation work. The metrics close flaw is confirmed and documented below; it remains outside this slice.

## Description

`init` and consumer `Config::layer` now export spans to `traces.jsonl`, and entered spans supply IDs to log records. `Config::traces` and `VIGIL_TRACES` disable the entire trace pipeline. Guard flush and shutdown cover all three signals concurrently with typed outcomes and final stderr lines.

## Changes Made

- Resolve Ready/Disabled storage before constructing the tracer; preserve correlation and discard without losses after a storage-open failure (ADR-0003 d5/d15, OQ1/OQ8).
- Install the directly filtered OTel layer between diagnostics/after-shutdown and the destination; share the resource, shutdown gate, environment filter and SDK-target exclusion (d7/d14/d15).
- Run span flush on a scoped thread concurrently with logs; capture `SpansDropped` in its shutdown thread and run inline if creation fails (d4, ADR-0004 d3, OQ4).
- Release the trace storage state lock before I/O. Closing cannot wait for an in-flight directory write; later writes fail and count as lost (d23).
- Add the independent once-only after-shutdown span warning and unprinted span-loss/timeout final lines (OQ6/OQ7).
- Document trace sampling, event deduplication, correlation, special fields and ignored OTEL settings; update the stable API snapshot/allowlist.
