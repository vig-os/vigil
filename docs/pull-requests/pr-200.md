# [PR 200](https://github.com/vig-os/vigil/pull/200) refactor(audit): extract the reader's per-record state machine into a pure RunState (#197 R1)

## Summary

Lifts the reader's per-record state machine into a crate-private pure module `src/audit/runs.rs`:

- `RunState` holds the pure parts (`head`, `mmr`, `checkpoint`, `pending_resume`, `run_loss`, `checkpoint_predecessor`, `checkpoint_previous`); `storage::State` keeps the walk cursor and writer bookkeeping (`checkpoint_time`, `since_checkpoint`, `offset`, `length`, `newline`, `gap`) and now embeds `run: RunState`.
- `runs::apply_checked` owns every per-record check `storage::apply_checked` fired before (ordered byte-for-byte); the reader-side `apply_checked` becomes a thin shim that threads writer bookkeeping around the pure state machine.
- `runs::resume_details` replaces `storage::resume_details`; `resume_header` calls through.
- `storage::Head::of` and `storage::corrupt` go `pub(super)` so `runs.rs` can emit the exact detail strings.
- Reader-side segment-level checks (fragment-gap attestation, run/boundary ordering) stay in `history_segment` / `scan_inner`; R2 moves them (197-d1 addendum 7).

Every `CorruptTrail` detail string is byte-identical (ruling 13-V4-d4 point 1). The 121 `audit::storage::tests` pass unchanged. No public API change (`cargo semver-checks`: 196/196 pass, no update required; `check_public_api.py`: 371-line snapshot unchanged). ADR-0005 §19.9 picks up one sentence of bookkeeping.

The coverage gate's `STORAGE_SRC` is now `concat!(include_str!("storage.rs"), ..., include_str!("runs.rs"))`; `sites.len() == 51` is preserved (34 in `storage.rs`, 17 in `runs.rs`).

Churn: 398 non-test lines (added + removed), under the ~400 hard stop.
