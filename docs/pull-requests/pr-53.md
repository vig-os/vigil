# [PR 53](https://github.com/vig-os/vigil/pull/53) docs(adr): ADR-0003 metrics and traces

## Description

Proposes ADR-0003 (Status: Proposed): the metrics and traces design that gates #7, #8, #26 and #9. Decision document only, no code.

## Type of Change

- [x] `docs` -- Documentation only

## Changes Made

- `docs/adr/0003-metrics-and-traces.md`: 20 decisions with evidence (probes P1–P13), alternatives, consequences, and explicit deferrals.
  - Shared seam: per-signal crate-private exporters reuse the logs pipeline (ordering, non-finite sanitizing, line bounding, `RotatingFile` under the one dir lock); losses reported per signal; concurrent shutdown inside one 5 s budget.
  - Per-process `service.instance.id` (UUID v4 via `getrandom`, already in the lockfile) on all three signals.
  - Metrics: cumulative only, not configurable; 60 s interval; documented Prometheus name mapping; NaN sanitizing.
  - Traces: `tracing-opentelemetry` 0.34 (no default features), moved in lockstep with the opentelemetry family; dedup via an OTel-layer filter (spans + ERROR events, behind `RUST_LOG`) plus `max_events_per_span = 0`; open spans at shutdown reported on stderr; a stdout-silence test.
  - Logs: span fields on log records via the experimental appender feature, with vigil-owned semantics (unique keys, event wins, inner span wins).
- `docs/adr/README.md`: index row; fixes the stale "ADR-0003 = audit" note (the audit ADR is ADR-0005, #10).
- Assumptions A1–A5 about ADR-0004 (#37: features `metrics`/`traces`, no new public exporter types, meter access, config shape, composition) are stated for reconciliation.

## Changelog Entry

No changelog needed: this is a proposed design document with no user-visible change (and CHANGELOG.md is being reworked in #40).

### Manual Testing Details

Probes in a scratch crate against otelcol-contrib 0.151.0 → Prometheus 3.12.0 (flake-pinned nixpkgs):
- Cumulative: exact values. Delta: 10/11 lines rejected with HTTP 500, the whole batch.
- Two producers without `service.instance.id`: silently merged into one series (20 instead of 20+12). With ids: two exact series.
- A NaN gauge (`"asDouble":null`) silently dropped every line. `"NaN"` round-trips.
- Span-event dedup variants measured. Found that `with_counting_event_filter` in 0.34.0 prints to stdout on every event. Found duplicate attribute keys with span-field enrichment.
