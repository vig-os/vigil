# [PR 135](https://github.com/vig-os/vigil/pull/135) feat(traces): add the OTLP/JSON span exporter (#8 8a)

## Description

Add the default `traces` feature and an unstable OTLP/JSON span exporter, without provider or layer wiring. Spans use the shared envelope pipeline with deterministic resource/scope ordering, batch order within scopes, non-finite attribute sanitization, span-boundary splitting, value shortening and identity-preserving diagnostic stubs. A stub that cannot fit rejects the complete batch before writing.

## Changes Made

- Expose `span_export::OtlpJsonSpanExporter` only under `vigil_unstable`; retain an empty resource until `set_resource`, flush the sink synchronously, and count stubbed/failed spans with a consuming counter.
- Reuse the existing log shortening helpers; preserve names, IDs, trace state and attribute keys. Apply trace fingerprint key ordering independently of serde map features.
- Add SDK fixtures, trace golden bytes, Collector semantic round trips and both map-order CI lanes; the flake discovers all eight user feature sets with and without the unstable cfg.
- Amend ADR-0001 decision 5 for ruling 8-d2 (#8): log records and spans retain batch order.

- Round-two review: pin event/link attribute sorting, sorted shortening markers and reserved-marker replacement; empty batches write nothing, and the fingerprint assertion checks the actual written span ID.
- Retain the trace `field_order` arms: SDK scopes with absent versus explicit empty versions are distinct but project to identical OTLP metadata. Test that reachable tie and child-first ordering before remaining resource/scope metadata; metrics/logs have analogous arms.
