# [PR 261](https://github.com/vig-os/vigil/pull/261) feat(audit): add Verifier::accept for reviewed warnings

## Summary

Adds `Verifier::accept` so a recorded human sign-off promotes a reviewed
`TornWrite`, `Resumed`, `ClockWentBackwards` or `DuplicateRecord` warning to
`Accepted` (info). Every other outcome -- `AcceptMismatch`, `AcceptUnused`,
`OutOfRange`/`UnanchoredStart`/`UnanchoredEnd` set-asides, `LostRecord`
inside a confirmed resume gap counted by `lost_records=<n>` -- is routed
through the shared position classifier or the receipt match rule, so no
separate classifier lives in the review path. Implements ADR-0005
decision 11 "Review file" and ruling 13-V8-d1.

- Internal `TornWrite` pin kept in an engine-side side map (keyed by the
  finding's index), so the public `Finding` keeps its original shape.
- `review::check` runs in two passes: phase 1 classifies positions
  before `count_lost_records`, so an `accept` inside a confirmed gap
  becomes one `LostRecord` counted by that gap's `lost_records=<n>`;
  phase 2 matches the remaining lines against the warnings after
  `emit_resumed`.
- `Finding::accepted(by, reason)` promotes a warning in place: file,
  line and `seq` preserved; original kind in `accepted_kind`; detail
  `accepted by <by>: <reason>; was: <original>`.

Out of scope: `accept Resumed` as gap confirmation (V8b), `accept_run`
(V8c/V8d), review-file parsing and the CLI (C1).
