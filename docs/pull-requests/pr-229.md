# [PR 229](https://github.com/vig-os/vigil/pull/229) feat(audit): report rule-2 MMR mismatches from the shared fold and filter resume candidates fail-closed

## Summary

Reports ADR-0005 decision 5 rule 2 and amendment 6 (iii) refined by decision 11 `accept-run` item 3 as `MmrMismatch` findings from the shared classifier's **one fold** (ruling 13-V4-d10), and filters the private resume candidate list fail-closed to openings the fold compared and matched. Refs #13.

Mechanism:
- `runs::apply_checked` gains an `&mut Option<CheckpointFoldReport>` out-slot at the one fold-compare site; reader paths pass `&mut None`.
- Classifier records one `CheckpointFoldEntry { pos, seq, expected_size/root, declared_size/root, outcome }` per checkpoint-apply, with `outcome ∈ {Matched, Differs, DiffersAfterLoss}` per 13-V4-d10 points 2-3.
- `ClassifyOutput::fold_entries` exposes the entries only under `Reaction::Collect` (empty under `Stop`, so reader behaviour stays byte-for-byte the same).
- `verify::fold::check_runs` emits one `MmrMismatch` per `Differs`/`DiffersAfterLoss` entry (grammar: `expected size <n> root <digest>, found size <n> root <digest>`) and returns the matched-opening set.
- `verify::engine::check` renames `_pending_resumes` to `pending_resumes` and filters candidates through `filter_candidates(candidates, &matched_openings)`.

## Existing tests whose expected lists change

None. The existing A1/A3/A8/A9 run-finding rows (`runs_tests::r1`-`r4`) stay byte-identical: the honest fixtures sign their in-run checkpoints with the walker's reconstruction fold, so the fold entries at those checkpoints are `Matched` (no `MmrMismatch`). The pinned A1/A3/A8/A9 run digests do not change.

**Note on 13-V4-d10 point 3's "honest checkpoints count lost leaves, so they do differ":** the current `runs_v4a_fixtures` sign in-run post-loss checkpoints with the walker's reconstruction fold (not with a truly-honest writer's fold including lost records), so those in-run checkpoints are `Matched`, not `DiffersAfterLoss`. B3's `wrong-root cp5` and `wrong-size cp5` rows exercise the `DiffersAfterLoss` path by crafting a differing cp5.
