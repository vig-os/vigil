# [PR 229](https://github.com/vig-os/vigil/pull/229) feat(audit): report rule-2 MMR mismatches from the shared fold and filter resume candidates fail-closed

## Summary

Reports ADR-0005 decision 5 rule 2 and amendment 6 (iii) refined by decision 11 `accept-run` item 3 as `MmrMismatch` findings from the shared classifier's **one fold** (ruling 13-V4-d10), and filters the private resume candidate list fail-closed to openings whose `(opening_seq, opening_hash)` the fold compared and matched. One classifier pass per verify call (13-V4-d10 point 1); no second fold. Refs #13, #224.

Behaviour summary:

- `apply_checked` derives one outcome from what the fold did at each checkpoint: a mismatch under `compare_mmr=true` is `Differs` (paired with `Violation::CheckpointMmrDiffers`), under `compare_mmr=false` is `DiffersAfterLoss` (amendment 6 (iii); no violation), a self-consistent self-base is `Base`, everything else is `Matched`. A self-base whose declared fields disagree with the fold loaded from its own peaks lands under `Differs` (one enum value per compare outcome, ruling 13-V4-d10 point 2).
- `CheckpointFoldEntry` carries the checked record's hash; `check_runs` returns matched openings as `(seq, hash)` pairs; `filter_candidates` keeps a candidate only when `(opening_seq, opening_hash)` equals a Matched entry's `(seq, hash)` (ruling 13-V4-d10 point 4). A forged opening whose hash collides on `seq` with an honest Matched opening on the same trail is dropped.
- The per-walk Classifier threads `record_fold_entries = matches!(outer_reaction, Reaction::Collect)` via `ScanSegmentArgs::record_fold_entries` and `Classifier::set_record_fold_entries` (ruling 13-V4-d10 point 1). Reader-only paths leave the flag `false`, so no per-checkpoint blake3 hashing runs on the Stop path; the verifier's one classification (including the strict-Stop closure inside `storage::history_segment` on that outer Collect path) sets it `true`, so an honest-and-strict sealed segment contributes its matched entries to the fail-closed filter.
- Once a segment records a violation the classifier latches `segment_has_collected_violation` and `record_fold_entry` no-ops for the rest of that segment (ruling 13-V4-d10 point 6). The salvage walk continues unchanged under Collect, so violations and reader decisions are byte-for-byte the same; only the per-checkpoint fold-entry report stops.
