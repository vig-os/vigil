# [PR 212](https://github.com/vig-os/vigil/pull/212) refactor(audit): move multi-segment loops into runs::classify (#197 R2b S3b1b)

## Summary

Per ruling 197-d1 addenda 25.1 / 25.2 and 27.1-27.3, moves every multi-segment segment loop out of `storage.rs` into `runs::classify_stop` / `runs::classify_collect` driven from `initial_record` and `refresh` through a typed `ReaderPath` description. `storage.rs` now supplies only byte I/O, three Stop wrappers (scan_stop, scan_closing_stop, history_segment_stop) and the merged lazy-base-order `SegmentSource`; no walker trait, no `Box<dyn ...>`.

Addendum 27.1: `HeadMismatch` is a trail-level decision made in `classify_stop` / `classify_collect` (the Collect side records it on `ClassifyCollectOutput.head_mismatch`); no new `Violation` variant. The syn gate stays at 49.

Brief 197-r2b-S3b1b-r1c item 3: the Collect-vs-Stop distinction is encoded in the output types (`ClassifyStopOutput` has typed `final_state: State` / `live_file: File`; `ClassifyCollectOutput` has `Option<State>` / `Option<File>`). classify_stop returns from the Live arm so no post-loop expect or unreachable is reachable on the reader path.

## API (all `pub(crate)` or narrower)

- `pub(crate) enum ReaderPath { LiveOpen { expected: Option<Head> }, RefreshAppend, RefreshRotate }` (addendum 25.2)
- `pub(crate) struct ClassifyArgs { trail, prior_state }`
- `pub(crate) struct ClassifyStopOutput { final_state: State, live_file: File, found, sealed_before }`
- `#[cfg(test)] pub(crate) struct ClassifyCollectOutput { final_state: Option<State>, live_file: Option<File>, found, violations, sealed_before, head_mismatch: bool }` -- gated behind `#[cfg(test)]` at this head (addendum 25.5); V4a in S3b2 lands the non-test consumer.
- `pub(crate) fn classify_stop(args, path, source) -> Result<ClassifyStopOutput, AuditError>` -- the ONE multi-segment Stop orchestration (addendum 25.1).
- `#[cfg(test)] pub(crate) fn classify_collect(args, path, source) -> Result<ClassifyCollectOutput, AuditError>` -- Collect orchestration for the CC rows and first-equality sweep.
- Storage Stop wrappers: `scan_stop`, `scan_closing_stop`, `history_segment_stop`. The first two return typed `State` (scan_inner Stop invariant); `history_segment_stop` returns `Option<State>` because the tolerant fallback is still the Stop reader's second pass and may fold no complete record.
- `Reaction` parameter threaded through `storage::{scan, scan_closing, history_segment}`.
- `storage::Cache` fields are `pub(super)` with `#[cfg(test)] pub(crate) fn state(&self) -> &State` and `#[cfg(test)] pub(crate) fn new_for_test(state, file, sealed_before)` accessors for cross-module test code.

Addendum 27.1 HeadMismatch:
- Under Stop, `classify_stop` returns `Err(HeadMismatch)` where `storage::initial_record` did at e1c45a3.
- Under Collect, sets `ClassifyCollectOutput.head_mismatch = true` and preserves every collected violation.
- Only `ReaderPath::LiveOpen { expected: Some(_) }` can set it. No `Violation::HeadMismatch`.

`initial_record` / `refresh` are thin callers of `classify_stop`; the segment loops that lived in `storage.rs` are gone.
