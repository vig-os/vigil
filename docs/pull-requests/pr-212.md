# [PR 212](https://github.com/vig-os/vigil/pull/212) refactor(audit): move multi-segment loops into runs::classify (#197 R2b S3b1b)

## Scope

Move every multi-segment segment loop out of `storage.rs` into one `runs::classify`, driven from `initial_record` and `refresh` through a typed `ReaderPath` description. `storage.rs` keeps byte I/O and the lazy base-order `SegmentSource`; `classify` owns the per-segment walk choice, the segment order, the threading of `state` / `found` / `run`, and the `HeadMismatch` decision. Both reactions (`Stop` and `Collect`) run through the same `classify`, so there is no second copy of the walk.

## What landed

- `runs::classify(args, path, source, reaction) -> Result<ClassifyOutput, AuditError>` is the only multi-segment orchestration. `storage::initial_record` / `storage::refresh` are the only non-test entry points.
- `ReaderPath::LiveOpen { expected }` / `RefreshAppend` / `RefreshRotate` selects the per-segment walker (`history_segment` with its `opening` / `genesis` flags, or `scan_closing`). Open fallback is `LiveOpen` with a non-empty rotated listing in `SegmentSource::for_live_open`; it is data, not code.
- `ClassifyOutput { final_state, live_file, found, violations, head_mismatch, sealed_before }`. Under `Stop` the Ok path returns the final live `State`, the live file handle, `found` and `sealed_before`; `violations` is empty and `head_mismatch` is false. Under `Collect` the same output is populated plus `violations` (`Vec<(SegmentViolationPos, Violation)>`) and `head_mismatch`.
- `HeadMismatch` has exactly one construction site, inside `classify`. Only `ReaderPath::LiveOpen { expected: Some(_) }` can set it. The syn gate stays at **49**, measured at base and at head.
- `dispatch_line`'s `(Mode, Reaction::Collect)` arms route the storage shim's `on_feed` through the classifier's own `Advance`: `Record` folds the record, `Duplicate` leaves the writer fields in place but still writes `found`, and a rejected record feeds nothing. Collect's `final_state` / `found` equal Stop's bit-for-bit wherever the reader returns `Ok`.
- A structural source test (`coverage_gate_no_segment_loop_in_storage_rs`) parses `storage.rs` with `syn` and derives the walker set from the two seeds `runs::history_segment` and `runs::scan_segment`. Every `for` / `while` / `loop` in `storage.rs` whose body calls any transitive wrapper fails the gate; `initial_record` and `refresh` must each call `classify` and call no walker directly. `M-STRUCT1..5` plants all exit 101 against this gate.
