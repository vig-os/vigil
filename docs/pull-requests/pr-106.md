# [PR 106](https://github.com/vig-os/vigil/pull/106) feat(metrics): wire storage and bounded pipeline lifecycle

## Description

Wire the cumulative metrics exporter into `init` and `layer`, with independent storage fallback, explicit SDK configuration, shared loss accounting, and bounded lifecycle operations. `Guard` now flushes both signals and shuts them down concurrently; callers receive each signal's loss kind and stderr summaries retain the distinct log-record and metric-data-point units.

## Changes Made

1. Open independent `logs.jsonl` and `metrics.jsonl` writers under the existing directory-lock registry. The brief ruling 7b1-d1 corrects the former lock-file wording: tests assert no lock file exists and use test-only weak references to the Guard's own two files, with `Arc::ptr_eq` on their directory locks. Installation-race cleanup and per-signal rotation/retention are covered. A concrete metrics storage/exporter wrapper closes the file on the SDK worker before acknowledging shutdown, so a retained provider clone cannot keep files open; a timed-out worker can finish its write and close storage afterward. The installation-race test retains that clone while checking that storage handles are gone. Removing the close fails deterministically (exit 101).
2. Add feature-gated `Config::metrics` and `Config::metrics_interval`, including builder precedence, `VIGIL_METRICS` grammar, invalid-value warnings, the 60-second default, and the one-second clamp. A logs storage failure leaves metrics running; a metrics storage failure leaves logs running. R1 needs no ADR amendment: ADR-0003 decision 5 already specifies `0`/`1` and builder precedence; ADR-0004's configuration rules treat empty variables as unset.
3. Explicitly pin the periodic reader interval, including tests against `OTEL_METRIC_EXPORT_INTERVAL=1` millisecond and a zero builder duration. No OTel global provider is installed. The provider remains in `Guard` for this part; 7b2 moves it into the process-wide pipeline slot with the facade/registry, as the inline `7b2: d9 pipeline slot` note records.
4. Track per-signal Timeout/Failed/DataLost outcomes and metric export/data-point flags. `FlushError::Display` prints log counts only when nonzero, always retains source text, and names mixed log losses and metrics timeout/failure in logs-then-data-point-kind order. Metric-only outcomes carry no measurement count. The exporter uses the Guard's shared losses and shutdown flag; pending data points subtract runtime-reported counts.
5. Apply brief ruling 7b1-d2: register metrics flush callers before the logs flush, track collection generations under one mutex/condvar, and run only one detached metrics worker. Later callers require a later generation; timed-out waiters cannot leave orphan collections. Both signals share the flush's five-second budget. ADR-0004 now records the ruling and clarifies that the 64-request SDK channel bound belongs to logs.
6. Implement concurrent provider shutdown early from ADR-0003 decision 4, originally scheduled for #8. Each signal has its own scoped thread and inline spawn-failure fallback. Explicit logs shutdown now warns when it misses its deadline; this is new behavior for logs. Drop prints each signal's actual failure/timeout or pending losses, while explicit shutdown prints pending metric data points and deadline warnings. ADR-0003 d3's final-summary text is marked `(amended, #7)` and includes the zero-count Timeout/Failed exception.
7. Pin SDK defaults through the production builder: cumulative sums, 2,000-series cardinality plus the overflow series, and empty/absent exemplars. No views or aggregation overrides are added. A private concrete reader adapter preserves typed SDK shutdown timeouts before the provider stringifies them; this enables the existing SDK dependency's custom-reader feature, without its testing feature or any new packages. `Cargo.lock` is unchanged.

The facade, identity registry, globals option, traces and Prometheus end-to-end work remain in the later parts. Conservative non-test changed-line upper bound: 880, below 900.

Rulings 7b1-d3/d4 make stderr fallback a logs state: `Guard::dir()` can be `None` while metrics still write and return a failure. The ADR-0004 amendment and lifecycle rustdoc now say so. The old reload failure paragraph is corrected to match the current complete-layer-before-installation code, which has no reload slot. A real directory-at-logs-file then directory-at-metrics-file probe verifies `Failed`, zero lost measurements, and the data-point warning. Entropy and unresolved-directory warnings name metrics exactly once; metric-storage failure retains its one warning. ADR-0003 d3's amendment is limited to final-summary format and links to ADR-0004 for flush rules. Its Consequences now document the unstable custom-reader API, caret `0.33` coupling, failure modes and reviewed upstream bumps. The allowlist diff only adds the metrics group.

Ruling 7b1-d5 clarifies the existing shutdown floor without changing behavior: a blocked SDK 0.33 reader can hold shutdown for five seconds despite a shorter caller timeout. ADR-0004 and the shutdown rustdoc now state it. [Issue #112](https://github.com/vig-os/vigil/issues/112), in milestone `1.0.0 — stable`, tracks honoring shorter waits as a non-breaking change. The short-deadline test now holds the lock for the entire 100 ms-budget call, checks metrics `Timeout` and an eight-second upper bound, then releases the lock. Its source assertion pins the requested 100 ms deadline so M22 still fails even though the reader itself also times out after five seconds.

Shutdown now passes both provider results to loss finalization. `FlushError` retains separate sources, appends each to its own signal part, and returns logs then metrics from `Error::source()`, as documented in rustdoc. The real logs-fallback/metrics-directory probe checks the returned SDK metrics source, including `Failed to shutdown`, in Display and `source()`. Exact formatting asserted by the unit tests:

```text
Timeout: at least 2 log records lost; metric export timed out: Operation timed out after 1s
Failed: at least 2 log records lost: Operation failed: logs source; metric export failed: Operation failed: metrics source
```
