# [PR 139](https://github.com/vig-os/vigil/pull/139) feat(traces): trace loss accounting (#8 8b)

## Description

Trace losses now retain their own count, outcome and source in lifecycle accounting. Counts no longer hide a signal's Timeout or Failed label (#131). The trace pipeline is constructed with real SDK providers in tests; init/layer wiring remains slice 8c of #8.

Closes #131 (architect closes manually after merge).

## Changes Made

- Restrict queue accounting to the crate-private two-variant QueueSignal (Logs/Traces) and two QueueCounts slots, making metrics capture/accounting invalid at compile time. Share queue watermarks and pending diagnostics between logs and traces through QueueCounts. Count trace queue overflow at successful flush boundaries and reconcile the SDK shutdown total without duplicates.
- Pin trace runtime-report draining with two pending logs: reporting a stub leaves traces pending at `(0, false)` and logs unchanged at `(2, true)`, including their pending failure flag.
- Reuse the existing unique property-test TempDir guard through `tests/common/temp.rs` in both the property tests and real-stack test, including cleanup on assertion unwinding.
- Centralize each signal's SDK shutdown event and field in ShutdownCapture::new, shared by init and tests.
- Give all three signals independent kinds and sources, ordered logs → metrics → traces. Metrics retain both the data-points-dropped diagnostic and their own Timeout/Failed label, with the source directly after that label. Generalize the flush closure and shutdown capture; preserve typed span timeouts through SDK stringification.
- Add the generic ReportingSpanProcessor and ReportingSpanExporter with the existing Failures reporter. Failed durable span lines count their spans and stubs count one.
- Correct the 8a field_order test comment, include shortened-marker checks in the preserve_order lane, and document/test deterministic separate scopeSpans entries for NaN-valued SDK scope attributes.
- Non-test diff: 450 additions + removals (test-only code excluded), within the 520-line cap set by [architect ruling 8b-d1](https://github.com/vig-os/vigil/issues/8#issuecomment-6139090241). Per-file totals: CHANGELOG 1, init 38, lib 3, lifecycle 345, span_export 7, trace_pipeline 56.

Existing assertion changes (all others retain their asserted values):

- `lifecycle::tests::display_signal_parts`: `Failed: at least 2 log records lost: logs` → `Failed: at least 2 log records lost; log export failed: logs` (source substitution unchanged).
- `lifecycle::tests::display_orders_log_losses_before_metric_timeout_or_failure`, second Display assertion: insert `; log export failed` before the logs source.
- `lifecycle::tests::each_signal_keeps_its_own_kind_and_concurrent_callers_keep_timeouts`: `Failed: at least 3 log records lost; metric data points dropped` → `Failed: at least 3 log records lost; log export failed; metric data points dropped`.
- `lifecycle::tests::sdk_overflow_capture_does_not_repeat_flushed_losses`: move the sdk_overflow assertion's field access into the logs QueueCounts; expected value stays 9.
- `init::dropped_stub_tests`: both pending_stderr assertions gain QueueSignal::Logs; expected values stay `(count - 1, false)` and `(1, false)`.
- Queue operations and queue-field assertions now use QueueSignal::Logs/Traces; expected counts are unchanged.
New Display assertions (introduced by this PR, not changes to pre-existing assertions):

- `display_three_signals_and_counted_outcomes`, Failed case: `Failed: at least 5 metric measurements lost; metric data points dropped; metric export failed: Operation failed: metrics`.
- Same new test, Timeout case: `Timeout: at least 5 metric measurements lost; metric data points dropped; metric export timed out: Operation failed: metrics`.
