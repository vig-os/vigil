# [PR 34](https://github.com/vig-os/vigil/pull/34) fix(rotate): repair fragments and preserve writer progress

## Description

Repair fragments left by killed rotating writers while preserving healthy writer progress and consistent, lock-free reader retries during rotation.

## Type of Change

- [x] `fix` -- Bug fix
- [x] `test` -- Adding or updating tests

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- Fragment repair: inspect the live tail under the directory lock and prefix a newline in the same single append when needed. Include that byte in rotation accounting and retain write-failure rollback.
- Writer progress: use blocking `File::lock` with a kernel wait. After acquisition takes more than ten seconds, emit one stderr warning per process naming the directory; stderr errors are ignored. Hung-writer protection is intentionally deferred: batch queue saturation already produces a diagnostic.
- Reader progress and consistency: take no reader locks. Compare segment paths and the live device/inode before and after each copy; retry up to eight times. On exhaustion, `read_since` returns only the last rotated-file prefix, excluding a live tail that could skip intervening segments. `find_newest` returns its final best-effort candidate.
- Search performance: visit newest files and lines first, stopping file reads at the first match. Search callbacks may be repeated when an attempt races with rotation.
- Document separate file boundaries: a rotated segment can retain an unterminated fragment; readers and shippers must process files separately instead of concatenating raw bytes. The Collector already does so.
- Serialize process tests through Nextest configuration included in the Nix source filter. No dependencies added.

## Changelog Entry

### Manual Testing Details

The parent kills it before rollback and verifies a fresh writer preserves the next JSON record. The paused-reader test uses a channel barrier inside the read step and verifies a concurrent append finishes before the reader is resumed. A separate test holds the writer lock for eleven seconds, verifies the append eventually succeeds, and exercises the diagnostic threshold; a synthetic clock-duration test checks that warning emission is once-only and includes the directory.

## Additional Notes

The damaged record remains invalid; repair isolates subsequent healthy records. Reader retries are bounded and may omit recent records on exhaustion; pruning can remove retained records during copying. A stopped writer can block other writers, as required by the blocking-lock policy. A stopped reader holds no lock and cannot impede writers.
