# [PR 255](https://github.com/vig-os/vigil/pull/255) feat(audit): add receipt waivers and late adoption

## Summary

Two new builders on `Verifier` close ADR-0005 decision 5's "Waivers, for an honest crash" and "Late adoption" gaps (ruling 13-V7-d1 point 6):

- `Verifier::waive(seq, hash, reason) -> Result<Self, AuditError>` waives one unreceipted `audit.record` on its exact `(seq, hash)`. A matched waiver emits one `ReceiptWaived` (info) at the record and suppresses `NoReceipt` there. A mismatched waiver is `ReceiptMismatch` with subject `waive seq <s> hash blake3:<64 hex>` and the record still produces its ordinary `NoReceipt`. The hash pins the record, so a waiver cannot be moved.
- `Verifier::receipts_from(seq, hash, reason) -> Result<Self, AuditError>` pins a late-adoption deployment's receipt coverage. A matched `from` emits one `ReceiptWaived` (info) at the record and exempts every record at or below `s` from reconciliation. A mismatched `from` is `ReceiptMismatch` and exempts nothing.

Either call turns reconciliation on by itself. A duplicate `waive` for one `seq`, a duplicate `receipts_from`, an empty reason or a reason containing LF/CR return `InvalidConfig` with a message naming the failed check. A whitespace-only reason is accepted verbatim (not trimmed). The `ReceiptWaived` detail grammar lives once on `FindingKind::ReceiptWaived`; the builders link to it.

`receipts.rs` now has one shared match wrapper (`match_one`) that handles receipts, waivers and `from` through a single `Subject` enum; the receipt, waive and from paths all run through it, so there is no duplicated subject-format/set-aside/mismatch sequence. The reader (`src/audit/runs.rs`, `src/audit/storage*.rs`) is untouched.

## Rows

All rows live in `src/audit/verify/waivers_tests.rs` and end in one whole-list `assert_findings` (`assert_eq!` on `Vec<Finding>`); every hex in an expected detail is a module-level `const` pinned by `fixture_hashes_match_literals`. Shared helpers (`located`, `unlocated`, `assert_findings`, `trust_with_key`, `report_of`, `parse_cp`) live in `src/audit/verify/tests_common.rs` and are used by both `receipts_tests.rs` and `waivers_tests.rs`.
