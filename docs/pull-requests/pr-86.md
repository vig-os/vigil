# [PR 86](https://github.com/vig-os/vigil/pull/86) feat(audit): directory lock and validated trail scanning (B2a/3)

## Description

Add the internal read-side core for existing audit trails. Every refresh takes the shared directory lock, rechecks directory/live identity, and validates newly observed continuations from the cached head before exposing the current live descriptor. It does not revalidate historical segment contents. No public sink API or recovery writes are added.

This is the approved B2a split. Acceptance comes from ADR-0002 decisions 3, 7 and 13 and ADR-0005 decision 8 (lines 499–518). A complete JSON checkpoint without its final LF remains a record under decision 5; the scanner also accepts that honest sealing prefix.

## Changes Made

- Extract the existing directory registry/lock into a crate-internal locked-section API; telemetry continues using the same registry and lock implementation. Document registry → directory gate → flock → caller-state ordering, with no nested audit/log locks.
- Scan existing segments and live data, checking trail identity, hashes, sequence/link continuity, MMR roots/peaks/counts, identical duplicates, repair digests and existing resume declarations. Opening checkpoints seed archived-prefix state; expected heads must actually be present and linked.
- Move the reader to `audit::storage`, share the validation payload cap, reserve telemetry signal `audit`, and detect same-directory callback lock reentry with `WouldBlock`. Symlink, directory and FIFO trail files are structural corruption; FIFO opens are nonblocking. Document the ADR-0005 decision 8 limit: cached same-length in-place rewrites require offline verification.
- Keep the old live descriptor open. Unchanged files need no data read; growth reads only the new suffix, including any pending fragment. Rotation orders filenames relative to the retained old descriptor and follows only newer segments, verifying each opening checkpoint against the prior head. If the old segment was archived, the previously observed sealed filename supplies the lower bound. Historical filenames/metadata are listed, but historical contents are not reread. Truncation and missing/broken continuations fail closed.
- Provide settlement callbacks under the same lock for B2b. B2b will enforce marker/staging lifecycle, append/rotation durability and crash recovery. The reader takes the marker's trail id from that caller; it does not authenticate signatures, as specified for writers in ADR-0005 decision 8.

## Round 3

- ADR-0005 lines 524–525 retain a resumed live file unchanged, including a last entry instead of a closing checkpoint. Lines 406, 411 and 770 allow a trailing fragment and require writer/verifier parity. Segment-boundary validation now waits for the successor: an unclosed predecessor requires an opening checkpoint followed immediately by a valid resume declaration matching its last complete head/hash and the opening's loss bound. Missing, ordinary, late or mismatched declarations remain structural corruption. `file=` remains informational under line 525; filenames do not authenticate the resume. Only existing layouts are read; no resume writer or recovery writes are introduced.
- Sealed segments open read-only, including mode 0400; live files remain writable. Fixtures cover rollback, a torn tail with an adjacent resume, expected-head checking, and a lagging reader across a resume plus a subsequent rotation. Resumed predecessor bytes stay unchanged.
- Precisely scoped cache limit: on replacement, refresh skips contents of names at or before the retained old live inode, or its saved sealed-name bound if that inode was archived. A forged older-named segment can pass running refresh while fresh open rejects it. This is pinned by a test and documented in module rustdoc, alongside same-length rewrite limits. No equivalence is claimed for edits to skipped historical data.
- Pre-change proof on d40b10f: rollback, torn-tail, matching-resume positive/negative lifecycle, and 0400 sealed-file tests each exited 101. The historical-insertion behavior and intervening-segment negative tests already passed (exit 0), as expected. Removing the previously untested intervening `sealed` check makes the new negative test fail behaviorally (exit 101). Disabling its replacement deferred-boundary check also fails that test (exit 101); both mutations were restored.
- Final acceptance: `cargo test --all-features`, `nix flake check -L`, `just precommit`, and the stable API check exit 0. CI Summary and semver compatibility are required on this revision before completion.
