# [PR 203](https://github.com/vig-os/vigil/pull/203) refactor(audit): move the repair attestation into the pure module (#197 R2a)

## Summary
#197 R2a moves the repair-attestation check out of `src/audit/storage.rs` into
one pure, crate-private `runs::check_attestation(digest, repaired)` in
`src/audit/runs.rs`. The three former `storage.rs` sites (`history_segment`'s
duplicate short-circuit, its mid-segment non-duplicate branch, and `scan_inner`'s
strict scan) merge into one site. The reader still orders attestation ahead of
`apply_checked`'s per-record checks on every path, so every `CorruptTrail`
detail is byte-identical to today's reader (ruling 13-V4-d4 point 1): the pair
`[h5, fragment, next]` still gives `sequence gap inside sealed run segment` on
seq 7 linked and `missing or mismatched repair attestation` on seq 6 broken.

Coverage gate re-keyed for the merge (addendum 7: "re-keyed deliberately"): the
five attestation pins all key on occurrence `0` and `sites.len()` goes `51 ->
49` (31 in `storage.rs` + 18 in `runs.rs`). No UNREACHABLE entry for the removed
sites — addendum 7 says that would hide drift; R0b's stale-label check is the
enforcement.

Carries R1's two doc nits: `///` rustdoc on `storage::State.run` and on the
`storage::apply_checked` shim. Rewrites the `runs.rs` module `//!` caveat and
`runs::apply_checked`'s rustdoc caveat so that, together with
`check_attestation`, `apply_checked` reproduces the reader's first violation
for a sealed-run fragment gap as the reader orders it today; full segment-level
classification stays in `storage.rs` and the caveat now points at #197 R2b.

Pins the identical-duplicate state quirk (197-d1 addendum 12 new pin). No test
pinned it before: the duplicate short-circuit's `continue` deliberately leaves
`state.offset`/`state.newline` at the end of the first copy. The new
`pin_hs_fallback_duplicate_leaves_offset_at_first_copy` asserts it from the
fixture's own bytes. `audit::storage::tests` goes `147 -> 148`.

ADR-0005 §19.9 gets one appended sentence naming R2a scope and R2b scope. No
public API change, no new dependency, no new finding kinds, semver stays minor.

### Round 2 fixes (per architect brief 197-r2a-r2)

- **Blocker: removed the false oracle claim on `runs::apply_checked`.** Its rustdoc said that with `check_attestation` the pair reproduced the reader's first violation for a sealed-run fragment gap "as the reader orders it today", but 197-d1 addendum 12 shows the layout `[cp0, e1, fragment, x(seq=1, prev=cp0, distinct entry)]` through `history_segment(None, opening=true, run=false)` returns `record sequence did not increase inside sealed run` while the pair alone would report `missing or mismatched repair attestation`. The rustdoc now only cross-references the two at their pre-R2a positions and points at the module-doc caveat, which already carries the R2b-bounded wording.
- **ADR section 19.9 wording.** "called first on every reader path" conflicted with the same addendum; it now says the attestation is checked ahead of `apply_checked`'s per-record checks at the reader's existing per-path position, with segment-level checks staying in `storage.rs` until R2b. The duplicated "R2 moves the segment-level ... classification" phrase that preceded "R2b moves ..." is removed.
- **New pins for a pre-existing test gap: the fragment gap must be `take`n after a matching attestation.** Added three pins that assert the observable outcome on each path (R2b will move this code):
  - `pin_sc_attestation_consumes_gap` and `pin_hs_attestation_consumes_gap` run `[cp0, e1, fragment, e2(attested)]` through the strict path and require the returned state's `gap` to be empty.
  - `pin_hs_fallback_duplicate_branch_consumes_gap` runs a duplicate-with-attestation layout through the fallback body and asserts the exact detail `first successor lacks resume`.

  **Mutant proof.** `cargo test --features audit --locked audit::storage::tests`, `aeac8b5bbc7a1c38f32cf135eff3bbe857459bfa + round-2 commit`:

  - M2a (scan_inner, 1 site): change `gap.take().map(|g| *g.finalize().as_bytes())` at the single site in `scan_inner` to `gap.as_ref().map(|g| *g.clone().finalize().as_bytes())`. Exit **101**: `pin_sc_attestation_consumes_gap` and `pin_hs_attestation_consumes_gap` FAIL. Revert: exit **0**, `151 passed; 0 failed; 0 ignored`.
  - M2b (history_segment, 2 sites): apply the same replacement at both call sites in the fallback body of `history_segment`. Exit **101**: `pin_hs_fallback_duplicate_branch_consumes_gap` FAIL. Revert: exit **0**, `151 passed; 0 failed; 0 ignored`.

- **Nit: re-cited `pin_hs_fallback_duplicate_leaves_offset_at_first_copy`** to the R2a brief's binding amendments (which is where the quirk comes from) and added a comment that the `newline` half of the quirk is not observable on this layout because the trailing `not json\n` always overwrites `s.newline` on the fragment/invalid branch.
- **Not a finding** (architect's own note on the brief): swapping the attestation with the immediate-resume check in `scan_inner` is equivalent. `storage.rs` rejects any fragment while `boundary_resume` is set, so the gap is always `None` when that check can fire. No test for it.
