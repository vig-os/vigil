# [PR 243](https://github.com/vig-os/vigil/pull/243) feat(audit): add Verifier::start_from and report StartMismatch

## Summary

`Verifier::start_from(Checkpoint) -> Self` accepts the first record of an archived trail as the start, so the prefix `SeqGap` for `0..s−1` is not reported. Acceptance requires the trail to be the verified trail, the first record (lowest `seq` across native and shipped copies) to be a checkpoint at the start's `seq` with the start's hash, not forked, and trusted at its `seq` (ADR-0005 decision 11 `.start_from`; ruling 13-V6-d2). A failure emits one `StartMismatch` with the first failing condition's detail in the seven-step precedence; the record's own `BadSignature` / `UntrustedKey` are independent and still fire. A start that is not accepted is not used (point 4), so the prefix `SeqGap` still fires; an accepted start suppresses only `0..s−1` (point 5), so a forged record later in the file is still reported and the revocation rules above the start still apply. A second `start_from` call replaces the first (point 1). `Checkpoint` gains no new field; the single `trusted` predicate and the shared `forked()` / first-copy helper / verified trail id are reused (rulings 13-V5-d1 point 3 and 13-V6-d1 points 1-2).
