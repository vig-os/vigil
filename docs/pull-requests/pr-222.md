# [PR 222](https://github.com/vig-os/vigil/pull/222) refactor(audit): snapshot segment source over the verifier's collected bytes

## Summary

Adds the classifier-ready snapshot segment source so V4a can run its
one classify pass over the bytes `verify::input::collect` already read
from disk — rulings 13-V3-d2 (one snapshot per verification) and
13-V4-d5 (b) (classifier generic over a byte source). Builds on the
`ByteSource` extraction from #219. Zero behaviour change on every
existing reader path: the new path is exercised only in tests until
V4a lands.

## What changed

- `storage::ByteSource::Memory(Cursor<Rc<[u8]>>)` (ruling 13-V4-d6
  point 1): shared bytes the verifier captured, cursor-backed via
  `std::io::Cursor` (no hand-rolled `Read`/`Seek`/`pos`). `try_clone`
  returns a fresh `Cursor` at offset 0 over the same `Rc`.
  `ByteSource::into_file` returns `None` on `Memory` by design (the
  snapshot plan drives `Reaction::Collect`, which never stashes a
  file into `Cache`).
- `storage::PlanStep::Snapshot { bytes: Rc<[u8]>, is_live }` and
  `SegmentSource::for_snapshot(&[(Rc<[u8]>, bool)])` (ruling 13-V4-d5
  (b), 13-V4-d6 point 2): one segment per entry, `is_live` picks the
  yield shape (`Live` vs. `Sealed`). No directory handle (the field
  is `dir: Option<&File>`; file-backed constructors set it, snapshot
  does not).
- `input::Data` grows `bytes: Option<Rc<[u8]>>` (ruling 13-V4-d5 (b));
  `decode(file, keep_bytes)` reads raw via `read_to_end` when
  `keep_bytes` is set and streams spans/items from
  `io::Cursor<&[u8]>`. `copy` passes `keep_bytes = native(path)`, so
  shipped inputs decoded in isolation carry no retained bytes
  (ruling 13-V4-d5 (a)). A shipped path that hard-links to a native
  path shares the native's `Rc<Data>` through the inode cache, and
  because nothing reads `bytes` on a shipped input that is
  harmless. Known cost: one `Rc<[u8]>` of segment size per native
  segment is alive for the verification.
- `Collection::native_segments(&self) -> Vec<NativeSegment>`: native
  inputs in `inputs` order, with the retained bytes and the live-last
  flag. Shipped inputs are excluded; V4a feeds the vec into
  `for_snapshot`. `NativeSegment.input_index` has no non-test reader
  in this PR — it is read by the `input_tests` rows below and by
  V4a's fold verifier (lands later with `verify::fold::check_runs`).
- `runs::classify`: carries "this segment is the live segment" as its
  own fact (`matches!(&seg, SegmentRead::Live(_))`) so `final_state`
  is set from the walker's post-segment state whenever the segment
  was live, regardless of whether the `ByteSource` yielded a `File`
  handle through `into_file` (ruling 13-V4-d6 point 2:
  `for_snapshot` and `for_live_open` over the same bytes must give
  the same `ClassifyOutput`). `ClassifyOutput::final_state` and
  `ClassifyOutput::live_file` get rustdoc listing every `None` case.
- Comment corrections on `ByteSource` and `classify`:
  `File::try_clone` is a POSIX `dup` and the two `File` objects share
  one OS file offset; each walker seeks its source before reading, so
  the shared offset is not interference. `Memory::try_clone` returns
  a fresh `Cursor` at 0 (truly independent cursor).

## Acceptance rows

Classifier-level, under `Reaction::Collect`, in
`src/audit/storage_snapshot_tests.rs`:

- `snapshot_equals_live_open_on_simple_run_collect`: snapshot plan
  over the retained bytes equals `for_live_open` on the files for a
  live-present layout. `assert_classify_equal` pins every field that
  must agree: `violations`, `head_mismatch`, `segments.len()`,
  per-segment (`class`, `damage`, `run_membership`, `boundary_resume`,
  `final_state` in full), `found (seq, hash)`, `final_state` in full
  (via `state_sig`: `run` fold, `length`, `checkpoint_time`,
  `since_checkpoint`, `offset`, `tail_newline`, `gap_digest_raw`),
  every `RunReport` field. `sealed_before` and `live_file` are
  excluded by construction (snapshot source has no `newest` path and
  `Memory::into_file` is `None` by design).
- `snapshot_equals_live_open_on_empty_live_file_collect`: empty live
  file; the live-only `EmptyLiveFile` violation fires on both paths.
- `snapshot_equals_live_open_on_torn_tail_live_file_collect`: live
  file ending in an unterminated JSON fragment; the tolerant pass
  handles the tear on both paths.
- `snapshot_archive_with_closer_emits_run_report`: real archive (no
  live file) with a sealed closer; pins exact `RunReport` fields
  (`first_segment=1`, `last_segment=2`, `closing_opening` = closer
  `Head`, one loss point) and per-segment `SegmentClass`
  `[Base, InRun, Closer]`.
- `snapshot_archive_unclosed_run_emits_no_run_report`: archive with
  an unclosed run at end of plan; `runs` empty; per-segment class
  `[Base, InRun]`.
- `snapshot_final_state_matches_live_open_head_seq`: literal pin that
  `final_state.run.head.seq` equals the resume record's seq (ruling
  13-V4-d6 point 2).
- `snapshot_archive_final_state_is_none`: literal pin that
  `final_state` and `live_file` are `None` on an archive-only
  snapshot.

Input-level, in `src/audit/verify/input_tests.rs`:

- `snapshot_collect_dir_matches_collect_explicit_paths`: real archive
  (no live file; closer sealed inside the archive);
  `collect([dir])` and `collect([seg paths])` produce equal
  `native_segments` and an equal `ClassifyOutput`, with literal
  `input_index [0, 1, 2]` per variant, `violations == vec![]`
  per variant, and exactly one `RunReport` whose fields are pinned
  (`first_segment=1`, `last_segment=2`, `closing_opening` = closer
  `Head`, one loss point).
- `snapshot_collect_archive_plus_trail_dir_matches_full_single_dir`:
  archive part (base + run opener) plus trail part (closer: opening
  cp + resume); the closer in the trail part closes the run that
  opened in the archive part. `collect([arch, trail])` and
  `collect([full])` produce equal `native_segments` and an equal
  `ClassifyOutput`, with literal `input_index [0, 1, 2]` and
  `violations == vec![]` per variant, and the same one-`RunReport`
  pin.
- `snapshot_collect_live_closed_run_pins_final_state_length_byte_exact`:
  live-present closed-run snapshot; pins `final_state.length` to
  the live file's on-disk byte count, plus the clean-run invariants
  (`violations == vec![]`, per-segment class
  `[Base, InRun, Closer]`, one `RunReport` with the pinned closer
  fields).
- `snapshot_native_segments_excludes_shipped_inputs`,
  `snapshot_native_segments_filters_shipped_siblings_and_retains_none`:
  cover the filter in `native_segments`.
- `snapshot_native_segments_shipped_hardlinked_to_native_dedups_to_native`:
  a shipped alias hard-linked to a native path; inode dedup keeps
  only the native `Input` (lower `key`) and `data.bytes` stays
  `Some`, matching the `Data` rustdoc's retention claim.
- `snapshot_native_segments_input_index_pins_order_on_multi_native_dir`,
  `snapshot_native_segments_input_index_literal_with_shipped_siblings`:
  literal `input_index` sequences on multi-native layouts, and on a
  layout that also carries shipped siblings filtered out of
  `native_segments`.
- `snapshot_native_segments_is_live_true_only_on_audit_jsonl`,
  `snapshot_native_segments_order_is_sort_live_last_literal`,
  `snapshot_native_segments_bytes_equal_file_contents`: literal rows
  over `native_segments` (is_live, order, byte contents).

## Mutants

Each mutant applied locally, each killer run, exit 101 confirmed,
reverted, green reconfirmed. The table below lists the killers that
fail under the mutant at this head.

- M-SNAP-1 (reverse plan): 7 killers, among them
  `snapshot_equals_live_open_on_simple_run_collect` and
  `snapshot_archive_with_closer_emits_run_report`.
- M-SNAP-2 (append synthetic Live tail): 9 killers, including
  `snapshot_archive_with_closer_emits_run_report` and
  `snapshot_archive_unclosed_run_emits_no_run_report`.
- M-SNAP-3 (`Snapshot` arm drops `is_live`, always `Sealed`):
  killers include
  `snapshot_equals_live_open_on_empty_live_file_collect`
  (live-only `EmptyLiveFile` fires on both paths on correct code)
  and
  `snapshot_equals_live_open_on_torn_tail_live_file_collect` (live
  tolerant pass vs. strict sealed arm on a torn trailing fragment).
- M-SNAP-6 (`ByteSource::Memory` reads EOF immediately): 8 killers,
  among them the `snapshot_equals_*` and `snapshot_collect_*` rows.
- M-SNAP-7 (`native_segments` emits shipped): both
  `snapshot_native_segments_excludes_shipped_inputs` and
  `snapshot_native_segments_filters_shipped_siblings_and_retains_none`
  fire via the production `expect` in `native_segments`. **No
  assertion-only killer is possible here:** in every reachable
  `Collection`, an `Input` with `native = true` has
  `data.bytes = Some` (`copy` sorts natives before shipped, `decode`
  is called with `keep_bytes = native(path)`, and inode dedup
  shares the native's `Rc<Data>`), so the `expect` fires only when
  a mutant bypasses the filter and lets a shipped input through.
- M-SNAP-9 (`decode(keep_bytes=true)` streams from the exhausted
  `BufReader<File>` after `read_to_end`):
  `inode_alias_precedence_and_duplicate_names`,
  `retry_discards_old_decode_items_and_reads_live_tail`,
  and six more rows cover the span-set equality.

M-SNAP-4, M-SNAP-5 and M-SNAP-8 are dropped. M-SNAP-4 was
`from_raw_fd(-1)`, which is not a real mutation of the production
code. M-SNAP-5 is a strict duplicate of M-SNAP-2 (both are "append a
synthetic Live step on the archive case"); both killers were the
archive rows, so keeping M-SNAP-5 adds no distinct coverage. M-SNAP-8
targeted the hand-rolled `Memory::seek` that this PR no longer
carries — the `Memory` variant is `std::io::Cursor` and its seek is
std code, so the mutation would target a std implementation that is
out of scope here.
