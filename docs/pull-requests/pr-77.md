# [PR 77](https://github.com/vig-os/vigil/pull/77) docs(adr): ADR-0005 amendment 2 for attested repairs, reviewed warnings and resume gaps

## Description

This PR decides the two questions the #66 amendment deferred. Both are written in place in `docs/adr/0005-audit-trail.md`, under an "Amended 2026-10-11 (#68, #70), Proposed" line. Status reads "amendment 2 Proposed", so the architect accepts after review. These rules gate #13 (`--strict` and resume handling).

| Question | Decided rule |
|---|---|
| **#68**: an honest crash's torn write fails `--strict` forever | **Attested repairs.** A writer that repairs a torn tail sets `audit.repaired` on the next line it writes. The new attribute is hashed, uses tag `0x07`, and holds blake3 over the gap bytes. An attested gap covered by a trusted checkpoint (or a matching `end=`) is `TornWriteRepaired` (info), so `--strict` passes. A gap followed by a line that does not attest it is `RepairMismatch` (error), so inserted fragments no longer pass plain verify. **Reviewed warnings.** Warnings that no write can clear are accepted by hash-pinned `accept <kind> <seq> <hash> <reviewer> <reason>` lines in a separate review file (`--reviewed`, `Verifier::accept`). Those warnings are a trailing fragment on a retired or resume-sealed file, `Resumed`, `ClockWentBackwards` and `DuplicateRecord`. Errors can never be accepted. A changed or rolled-back record makes the line `AcceptMismatch`. |
| **#70**: receipts lost across a `resume` | **`resume` never reuses a `seq`.** It continues above a mandatory `--lost-through`, the highest `seq` the deployment holds evidence of. The chain may therefore jump once at a declared resume gap, and `mmr_size` counts records. A gap is confirmed when its resume record matches a receipt or an `accept` line; receipts, waivers, `from` and `accept` lines inside a confirmed gap are `LostRecord` (info). **Anchors and `through=` pins inside a gap are set aside only when the gap's opening checkpoint is itself anchored** (the `start_from` analogue); otherwise they stay errors. Inside an unconfirmed gap, every input keeps its error, because a signature alone never demotes anything. `expect_head` and the rotation's expected head need no change. `resume` gets its own staging file, promoted only with both lines. `vigil.audit.` becomes a reserved action prefix. |

The new decision 17 covers each rule under the four threat models (write access without a key, stolen key, honest crashes, multiple writer processes): what is detected, by which finding, and what remains undetectable without an anchor (#57).

**Changes to the rest of ADR-0005 that the rules force:**
- Two format changes before 1.0, which decision 12 allows on `dev`:
  - the optional `audit.repaired` attribute (decisions 3 and 4). The merged format layer from PR #73 has neither tag `0x07` nor `mmr_size` ≠ `seq` (`src/audit/format.rs` rejects it); **#79 tracks both**.
  - `mmr_size` counts records instead of equalling `seq` (decisions 7 and 8). The two are identical on any trail without a resume gap.
- Decision 6 adds a storage requirement: a crash never exposes unwritten bytes. Supported for regulated use are ext4 in its default mode and APFS, each only once a crash test proves the prefix property there (added to #11's and #46's scope by comment). ext4 `data=writeback` is documented to break it.
- `AuditConfig::resume` gains `lost_through`, and the `resume` CLI gains a mandatory `--lost-through`.
- The fixed `audit.details` form of a resume record.
- New finding kinds under the existing `#[non_exhaustive]` enum.

No new `AuditErrorKind`, so ADR-0004 needs no change.

### Manual Testing Details

- `just precommit` (inside `nix develop`): exit 0.
- **Probe:** a scratch crate outside the repo, Rust 1.95.0, using `blake3`, `ed25519-dalek` with decision 14's features, and `serde_json`. It is an executable model of the writer and verifier rules, run against the core rules ("Old"), the withdrawn `lost`-line draft ("Withdrawn") and this amendment ("New"). The architect's copy is at `~/.local/state/architect/vigil/scratch/adr-0005-amend2-probe`. `cargo test --release`, three runs, exit 0:
  - 32 scenarios pass under New.
  - 5 comparisons:
    - Old fails `--strict` forever after one honest SIGKILL.
    - Old passes plain verify with inserted fragments.
    - Old keeps lost receipts as `ReceiptMismatch` forever.
    - Withdrawn hides a rollback behind an old resume (#70's M1).
    - Old and Withdrawn give `HeadMismatch` with `expect_head` after a resume (M2).
  - 16 mutants of the new rules, each killed by at least one scenario.
  - Multi-process run: 8 writers plus 3 writers SIGKILLed mid-write, real processes under `File::lock` and `sync_data`, 20 runs. Every gap was attested by whichever process wrote next, and New passed `--strict`; Old failed every run.
- **Architect review round 2** (blocker: a receipt or an accept line set aside anchors inside a gap) is fixed in ff95492, together with its nits: the verifier now rejects an accept line for bytes after a rotation-sealed closing checkpoint, the supported filesystems are stated honestly, the digest is spelled out as one hash, and the missing #13 tests are added. Probe scenarios `r7` (an accept line alone leaves `AnchorMismatch`; an anchored opening checkpoint gives `LostRecord`) and `s13` (the `AcceptMismatch` on rotation tails, and the unmarked case when an archive is verified alone) cover them.
- **Three rounds of independent adversarial review**, a fresh reviewer each round, each with its own attack tests on the model:
  - No round found a bypass under the write-access or stolen-key models.
  - Round 1 found two honest permanent failures (a crash during `resume`, a Collector copy of a resumed trail) and several underspecified rules. All fixed.
  - Round 2 found that a power-loss prefix of the resume staging write was still promoted. Fixed.
  - Round 3 found that the same problem remained for a resume with nothing lost, that `create` was undefined under the new `seq` rule, and that a name-based "sealed by resume" check was fragile. Fixed with a separate `.audit-resume.jsonl`, `seq 0` after genesis, and by keeping bytes after a rotation-sealed closing checkpoint as a `TornWrite` warning that the review criteria forbid accepting; this is a documented residual in decision 17.
  - **The round-3 fixes have not had a fourth independent review (round cap).** They are covered by probe scenarios r15 (every staging prefix, with and without a gap, over deleted and torn live files) and r16 (sealing and `create` settlement).
