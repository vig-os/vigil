# [PR 241](https://github.com/vig-os/vigil/pull/241) feat(audit): add Verifier::anchor and report AnchorMismatch

## What changed

Add `Verifier::anchor(Checkpoint) -> Self` on the offline verifier and emit one `AnchorMismatch` (error) per failing anchor on the verified trail (ADR-0005 decision 10; ruling 13-V6-d1 points 1-2).

- An anchor pins a `(trail, seq, hash)` triple built from a `Checkpoint` outside the trail directory. It matches only when its `trail` is the verified trail, the verified set holds exactly one distinct record at its `seq` (byte-identical duplicates count as one record), and that record carries the anchor's hash. Shipped-only copies count as records in the trail (ruling 13-V5-d4). A forked `seq` (ruling 13-V5-d2, shared `engine::forked`) is never matched, even when one copy carries the anchor's hash. Each distinct `(trail, seq, hash)` is checked once; duplicates collapse.
- A failure yields one `AnchorMismatch` at `seq` `s`, with the detail taken from the first failing condition:
  1. `anchor seq <s> hash <hex>: trail differs`
  2. `anchor seq <s> hash <hex>: no record`
  3. `anchor seq <s> hash <hex>: seq is forked`
  4. `anchor seq <s> hash <hex>: hash differs (record <hex>)`
- Every finding locates at the first copy of the record at `seq` in the engine's merge order (the same copy `DuplicateRecord` reports as the original), including the `trail differs` case when the verified trail holds that `seq`; the `no record` case has no record to locate against and so no location.
- Anchors are not signature-checked: supplying one is the operator's statement (ADR-0005 decision 10).
- `Checkpoint` gains a private trail field, filled by `Checkpoint::parse` from the line's `audit.trail`. The in-process constructors (`AuditTrail::checkpoint`, `AuditTrail::close`, `AuditConfig::resume`, `checkpoints`) all delegate to `parse`, so a `Checkpoint` built in process carries its trail.
- The anchors check lives in a new crate-private module `src/audit/verify/anchors.rs`; `engine::check` threads the anchor list in with the minimum change and emits findings in the engine's existing sort order. The `(path, line, hash)` first-copy rule is shared through a crate-private helper in `verify/mod.rs`, used by `anchors`, `end` and `stale`. Rustdoc on `Verifier::anchor` carries the full rule, the four-detail precedence, forks and shipped copies, where anchors must come from (ADR-0005 decision 10, in substance), and that anchors are not signature-checked; `FindingKind::AnchorMismatch` briefly states the detail grammar and links to it.
- An end-record form of this finding arrives with `end_before` (#13).

## Public API delta

- `+ pub fn vigil::audit::Verifier::anchor(self, anchor: vigil::audit::Checkpoint) -> Self`

The public API gets no `Checkpoint` trail accessor: no caller outside `verify` needs one. `Checkpoint` derives `Clone, Debug` only (no `PartialEq`/`Hash`), so the new field adds no equality or hashing behaviour.
