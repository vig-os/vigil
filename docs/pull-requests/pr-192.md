# [PR 192](https://github.com/vig-os/vigil/pull/192) feat(audit): verifier fragment context, resume warnings and strict predicates (#13 V3b-1)

## Description

Implements V3b-1 of #13: fragment-run context, the no-crash mark, a plain `Resumed` warning per `vigil.audit.resume` record, the `UncoveredTail` info, and the `is_strict_valid` / `first_broken_link` predicates. Flips ADR-0005 §19.3 to Accepted. Structural resume validation stays for V3b-2.

## Type of Change

- [x] `feat` -- New feature

## Changes Made

- Fragment context: each fragment run is checked against its "after" record (ruling 13-V3-d4, addendum 10). A failing run yields `Unparsable` "fragment line failed context" per line while the gap bytes, lengths and digests stay V2-identical. Trailing runs trivially pass. File-start or non-`Records`-after runs fail.
- No-crash mark: a trailing `TornWrite` whose archive ends in a closing checkpoint and whose successor native input opens with a checkpoint at `closing.seq + 1`, linked by `previous == closing.hash`, whose second complete record is not `vigil.audit.resume`, carries `"; no crash outcome"` on its detail. Archive verified alone, missing-link opening, wrong successor seq, non-checkpoint successor first record, successor starting with a fragment, or an opening followed by a resume: all unmarked.
- Plain `Resumed`: every `vigil.audit.resume` record raises one `Resumed` warning per `(seq, hash)`, attributed to the native copy when present (ruling 13-V3-d4 point 3; addendum 8). A canonical declaration yields `operator=<a> reason=<r> head=<seq>:<hex> gap=<range|none> lost_records=0`; a malformed one yields `malformed declaration` and leaves any `SeqGap` the chain loop emitted. A foreign-trail resume gives `TrailMismatch` only, never `Resumed`.
- Uncovered tail: every non-empty trail carries one `UncoveredTail` info spanning `first_seq..=last_seq` until V5 trusts a checkpoint; `is_strict_valid` stays false (addendum 7).
- Predicates: `Report::is_strict_valid` (no error, no warning, no `UncoveredTail` without `tail_exempt`, no `Unreconciled`) and `Report::first_broken_link` (first error-severity finding in V3a-2's ruled sort order; every error kind qualifies). A private `tail_exempt` field is reserved for V5's `end=` exemption.
- Documents native batch-line acceptance (ruling 13-V3-d4 point 4): `audit.repaired` is read from the first record only, so a later record's `repaired` is silently ignored; no finding is attached to such a line.
- Drops `verify::input::LineItem::bytes` (and the matching `verify::lines::Item::bytes`); spans already carry the length and digest.
- Corrects the ADR d13 `Finding` row by removing the Report-only `is_strict_valid` / `first_broken_link` text (it stays on the `Report` row).
