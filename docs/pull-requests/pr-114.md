# [PR 114](https://github.com/vig-os/vigil/pull/114) feat(metrics): add the stable recording facade

## Description

This PR delivers #7 slices 7b2a and 7b2b together: a stable static metrics facade, deterministic identity conflict handling, poisoned-stream export filtering and opt-in unstable global meter installation. Reviewed #119 was merged into this branch at 0681405; its merge is now linearized onto dev b74300e. No runtime implementation changed during landing.

## Changes Made

- Five opaque static instruments, Scope, scope macro and Value conversions with const builders and compile-time validation; stable signatures expose no SDK types.
- Publish provider/losses/stopped state only after successful installation. Lazy handles bind after publication; disabled or failed metrics stay silent. Before-init losses transfer to period accounting and startup reporting, including when metrics are disabled; publication races drain at period finish. Shutdown records warn once without counting, and explicit shutdown never duplicates measurement summaries.
- Registry retains every declaration and Prometheus-series identity under one mutex. Conflicts poison all involved names; existing handles stop recording and cumulative exports remove poisoned streams across scopes without reordering. Compatible cross-scope declarations receive sorted name@version reminders.
- Prometheus 3.12 / otlptranslator v1.0.0 translation rules, deterministic outcomes and measurement/DataLost accounting cover all declaration orders. Standalone unstable exporters retain their behavior without a registry.
- Unstable Config::install_opentelemetry_globals installs the meter provider only at the successful publication/install point; ForeignSubscriber preserves a sentinel global provider. README and conformance coverage include healthy data surviving poisoned streams.

### Applied rulings

- 7b2a-d1: the facade and identity implementation land together as one PR. #119 is merged into this branch, satisfying the former draft-stack prerequisite.
- 7b2a-d2: omitted histogram boundaries retain SDK defaults; explicit empty boundaries export no buckets, with count/sum/min/max preserved.
- ADR-0004 d4's tracer-provider half is delivered by #8 (ruling 7b2b-d1).
- 7b2b-d2: separate-process comparison masks only timestamps, resource service.instance.id and resource process.pid; names and data-point values remain observable.
- 7b2b-d3: canonicalize -0.0 to +0.0 in both registry and SDK boundaries, use one total comparison basis for equality/ordering, and document deterministic positive-zero exports. Invalid NaN/infinite/duplicate boundaries remain rejected.

### Description-clause equivalence proof

For the same scope and exact name with different descriptions, `self == other` is false. Translation depends only on name, kind and unit, never description or boundaries. The following partition applies to every valid name and boundary slice:

| Kind | Equal unit, equal boundaries | Equal unit, different boundaries | Different units, equal boundaries | Different units, different boundaries |
|---|---|---|---|---|
| Counter | identical `_total` series overlap | identical `_total` series overlap | `!compatible` | `!compatible` |
| CounterF64 | identical `_total` series overlap | identical `_total` series overlap | `!compatible` | `!compatible` |
| UpDownCounter | identical base series overlap | identical base series overlap | `!compatible` | `!compatible` |
| Gauge | identical base series overlap | identical base series overlap | `!compatible` | `!compatible` |
| Histogram | identical bucket/sum/count series overlap | identical bucket/sum/count series overlap | `!compatible` | `!compatible` |

With different units, series may be disjoint, but incompatibility short-circuits before the description expression. If that expression could otherwise be decisive (compatible kind/unit/boundaries and equal spelling), the overlap branch has already returned true. A different kind likewise short-circuits through incompatibility. Thus there is no case in which the description clause changes the answer; overlap alone is not claimed for different-unit pairs.

Before removal, `description_conflict_clause_is_redundant_for_every_kind` passed (exit 0). After removal the same test passed (exit 0): 320 pairs in both directions, all five kinds, both unit orders (`ms`/`s`), and every pairing of None, empty, `[1,2]`, `[1,3]` boundaries. It asserts both conflict and equivalence with `overlap || !compatible`. The removal is an equivalent mutant, intentionally not claimed as killed.

### Signed-zero proof and validation

The two separate child processes bind `zero.h` with `[-0.0,1.0]` and `[0.0,1.0]` in opposite orders. Both keep one metric with count 2, report no poisoning or DataLost, and export a positive-zero first explicit bound (checked by bits). Their entire files are byte-identical after the existing d2 mask removes only timestamps, resource `service.instance.id`, and resource `process.pid`. Both JSON map lanes exercise these tests.

`validate_boundaries` checks `is_finite()` and strict ascending `<`: it rejects every NaN payload, both infinities, duplicate values, and adjacent -0.0/+0.0; finite subnormals remain valid and are preserved. A single signed zero is valid and is canonicalized. Equality, partial ordering and total ordering now use one `total_cmp` basis; there is no `Hash` implementation to diverge.
