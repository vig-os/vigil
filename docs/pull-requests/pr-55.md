# [PR 55](https://github.com/vig-os/vigil/pull/55) ci(supply-chain): gate dependency policy with pinned cargo-deny

## Description

Gate the locked dependency graph with cargo-deny 0.19.6 from the existing flake-pinned nixpkgs. Newly introduced incompatible licenses, vulnerabilities, unmaintained crates and git/alternate-registry sources fail CI.

## Type of Change

- [x] `ci` -- CI/CD pipeline changes
- [x] `build` -- Build system or dependency changes

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

- Add `deny.toml`: commented Apache-2.0/MIT/Unicode-3.0 allow-list, no advisory ignores, unmaintained crates denied, yanked releases warned. Yanks can be packaging-only and warrant review rather than automatic rejection.
- Warn on other duplicate versions; review and pin the syn 2.0.119 skip because proc-macro dependencies currently span syn 2/3 without sharing runtime types.
- Check every `opentelemetry*` crate for distinct semver compatibility lines, including distinct 0.x minors. A small metadata wrapper handles the prefix and compatibility semantics that cargo-deny's per-crate duplicate-version switch cannot express; patches within a line remain allowed. Pass the same all-features, all-targets, dev-inclusive locked metadata to cargo-deny.
- Expose cargo-deny in consumer-owned `extraPackages`; add a SHA-pinned CI extension job using `inputs.runner-json`. The existing Rust project helper automatically adds offline bans/license/source checks to `nix flake check` when `deny.toml` exists. Full advisory checking needs a live RustSec fetch, which cannot run inside an ordinary network-isolated Nix derivation, so the full gate runs separately and participates in CI Summary. It explicitly fetches, validates DB HEAD dates against a seven-day window, then runs the offline subset and advisory checks in independent cargo-deny invocations with `--disable-fetch`; every independent failure is reported, even when advisory loading aborts. OpenTelemetry conflict diagnostics are flushed immediately so they appear before subprocess output.
- Document policy updates and advisory DB refresh in README. No new Rust dependencies; `Cargo.lock` and `src/` unchanged.

## Additional Notes

Fetch errors fail the gate, while cargo-deny 0.19.6 may silently retain a cache on an offline fetch. The wrapper therefore checks the actual configured advisory DB HEAD commit dates (seven days), rejects missing/malformed/future-dated DBs, and continues to report all other findings. A recent cache can pass an offline fetch that reports success; a quiet DB with no commits for seven days deliberately fails for investigation. No vulnerability exceptions are configured.

The consumer-owned `supply-chain.yml` checks `dev` weekly (Monday 06:23 UTC) and supports manual dispatch. It resolves runner labels and devkit settings from `dev` using the existing resolver, pins external actions by SHA, and runs the same full gate. Failures remain red Actions runs; maintainers should subscribe to failure notifications. Neither scheduled nor `workflow_dispatch` runs work until the workflow reaches the default branch (`main`) in the 1.0 release; PR CI provides the supply-chain gate until then. Both triggers check out `dev` once enabled: [GitHub scheduling rules](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

### Revision proof

- The aggregation regression test failed before the change (exit 1, `AssertionError: 1 != 3` (and `3 != 4` for independent advisory invocations)) and passes afterward. The full Python suite now has 19 passing tests (exit 0), covering freshness boundaries, malformed/missing/future HEAD dates, fetch failures and aggregation.
- cargo-deny 0.19.6 accepted the DB rewound to `79832ae026e3cd24ace77313e11eec727ab27919` (2020-12-30) even with `maximum-db-staleness = "P7D"` and `--disable-fetch` (exit 0). Therefore the ineffective setting was replaced by the explicit HEAD-date check.
- On that same isolated stale DB with `unshare -rn` (network disabled), the pre-revision wrapper exits 0, while the revised wrapper exits 1 and still runs all cargo-deny checks. `RUSTC_WRAPPER=` was needed for this namespace proof because the host compiler-cache client needs network access.
