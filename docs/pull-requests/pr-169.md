# [PR 169](https://github.com/vig-os/vigil/pull/169) docs(adr): ADR-0002 amendment, bounded disk use (#163)

## Description

ADR-0002 amendment 3 (**Proposed**) for #163: how vigil bounds its disk use. Docs only, no code. Revised under architect rulings 163-d1 and 163-d2.

## Type of Change

- [x] `docs` -- Documentation only

## Changes Made

`docs/adr/0002-rotation-and-retention.md`, decisions 16 to 23 (in-place `(amendment 3, Proposed)` tags on decisions 2 and 8 and in Consequences) and the `docs/adr/README.md` status row:

- 16: optional `max_segments` (rotated, per signal) and `max_total_bytes`; both off by default; both apply. **Zero is honoured**: `Some(0)`/`0` keep no rotated segment (the live file is never deleted) or make the total always over the cap; `None`/unset is unlimited. `max_bytes(0)` still clamps to 1.
- 17: the total cap is one budget over all telemetry signals. The live-file reservation is `max(M_s, live_len + pending_len)` for the writing signal and `max(M_s, current length)` for the others, so the cap holds for any line length; the prune point must see the pending length (`src/rotate.rs:443-447`). Cross-signal order is the name stamp, then signal, then counter: weaker than it looks, and it decides only which segment is pruned, never whether the bound holds.
- 18: exact signatures: `RotationConfig::{max_segments, max_total_bytes, signal}`, new `SignalRotation`, `Config::{max_segments, max_total_bytes, signal_rotation}`.
- 19, 20: prune order (age, count, total), continue past a failed `unlinkat`, one stderr warning per process for an unmet cap; the live file is never deleted.
- 21: `audit` files are never counted or deleted, also when they share the directory.
- 22: worst-case formula in **logical bytes** (`st_size` of live, rotated and unlinked-but-open files), with a retained-handle term counted per writer instance, `R = Σ_s W_s · max(M_s, L_max,s)`, and an explicit paragraph that filesystem block rounding and metadata are not bounded. Consumer example: 264 MiB visible, `264 + 56·W` MiB for `W` `init` processes.
- 23: eleven `VIGIL_*` variables (minimum 0 for the two caps' segment/total variables), precedence, warn-once.
- A count cap is a per-signal ceiling, not a floor: under total-cap pressure a quiet signal's rotated history can be fully pruned.
- Acceptance evidence: multi-process bound asserted inside the lock at every prune point (deterministic), ordering asserted per deletion policy, retained-handle fixture with many writers in one process and several processes, long-line case, mutant list.

Open questions and rulings: OQ1, OQ2, OQ3, OQ5 accepted; OQ4 rejected (zero honoured); OQ6 rejected as written (explicit weak order). Deferral: the default cap before 1.0 is #168.

4. The isolation claim is removed: a count cap is a ceiling, not a floor; a quiet signal's rotated history can be fully pruned under total-cap pressure; no floor (no consumer need in #163, no issue).

## [Comment #2](https://github.com/vig-os/vigil/pull/169#issuecomment-6570480693) by [@gerchowl](https://github.com/gerchowl)

_Posted on November 2, 2026 at 06:15 AM_

Architect ruling 163-d2: applied in the head below.

1. Retained handles are counted per **writer instance**, not per process (`RotatingFile::open` makes independent writers): `W_s` is the number of open writers on signal `s` over every process sharing the directory; each retains at most one unlinked segment of at most `max(M_s, L_max,s)` until its next append or drop; term `R = sum_s W_s * max(M_s, L_max,s)`. `init` opens one writer per enabled signal per process, so `W_s` = process count for `init` users; the #163 example is restated as `264 + 56*W` MiB. The fixture uses 16 writers in one process and several processes.
2. The contract is on **logical bytes** (`st_size` of live files, rotated segments and unlinked-but-open segments), measured with `fstat` `st_size` through the open writers. "Allocated bytes" wording removed. A paragraph states that block rounding, metadata and preallocation are not bounded (operators add `F * B`).
