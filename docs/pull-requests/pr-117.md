# [PR 117](https://github.com/vig-os/vigil/pull/117) feat(audit): operator rotate and checkpoint with exact-head (B3c)

## Description

Add operator rotation and checkpoint calls that refuse unless the sequence and hash held by the operator exactly equal the disk head. The check and write share one directory lock, preventing intervening writer appends from being covered by the new key.

## Type of Change

- [x] `feat` -- New feature
- [x] `docs` -- Documentation
- [x] `test` -- Tests

### Modifiers

- [ ] Breaking change (`!`)

## Changes Made

1. Add consumed `Sink::operator_write` with poison check, settlement, full initial scan, exact comparison before public-key access, signing, and one write/fsync under one lock. No sealing or cadence checkpoint. Drop is inert on all return paths. Reserved writer actions use `ReservedAction`. ADR-0005 decision 9: “exactly that record”; decision 8: reserved `vigil.audit.` prefix.
2. Add `AuditConfig::rotate`, taking the old key from the hash-pinned checkpoint at the bound. Write `vigil.audit.key_rotated` with trail-id object and fixed old-key/bound details, then its covering new-key checkpoint. Return the entry receipt (zero unsigned records) and checkpoint; mirror after unlock. ADR-0005 decision 9: “writes two things signed by the new key”; decision 8: “What is signed”.
3. Add `AuditConfig::checkpoint` with the same mandatory exact-head check, returning one checkpoint without an entry. ADR-0005 decision 9: “takes the same mandatory `--expect-head`”.
4. Apply amendment 3 rules 1–6 to both calls, including poison before settlement and fsync rollback/poison on failed truncation. Add both full method names to its write-path list.
5. Add operator, public-consumer and mirror tests; extend the eight-process clean-stop/SIGKILL harness. Test same-length rewrites and a lock-honouring intervening writer through the hook between open and the operator lock; test poison introduced at that same boundary, including promotable staging. The verify/NoReceipt half of the between-closes scenario belongs to #13.
6. Document decision 9, expected-head provenance, errors, overshoot and the three crash outcomes in rustdoc; document exact-head HeadMismatch.
7. Record amendment 8, including bound validation/layout, crash recovery and waiver evidence, fixed reason forms and separate rotate/resume placements from architect rulings B3c-d1 and B3c-d2. Update Status, Issues and decision 13.
8. Regenerate the public API snapshot and justify both additions in the allowlist with decision 9 and amended decision 13.

## Round-two fixes

- Both torn-tail recovery paths now assert exact on-disk bytes: original plus fragment, LF, and returned R/C lines as applicable. Each reopens using the returned checkpoint as expected head.
- `OperatorOp::validate` is the single argument-validation implementation, called before disk access and by the one-shot sink. Both mirror callers use one event helper after unlock.
- Builder expected-head misuse has an accurate message tested for both commands.
- Kept the typed reserved-action override: it enforces the enum's action even if an internal caller supplies a different entry action. The internal writer test now asserts that override; its deletion fails at runtime.
- Removed the blank line splitting the Added list.
