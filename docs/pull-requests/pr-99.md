# [PR 99](https://github.com/vig-os/vigil/pull/99) feat(audit): fsync poisoning scope (B2b2a)

## Description

Implement ADR-0005 amendment 3's fsync poisoning scope. A failed staging write or fsync now neutralises the staging file; a failed directory fsync after a rename stops all writers with `audit.poison`; poisoned handles return before locking, settling or signing. Drop reports a new checkpoint failure once and remains silent for an already poisoned handle.

## Changes Made

- Case 1, ADR lines 458–464 and 831–833: truncate failed staging writes, file fsyncs and staging-name fsyncs to zero. Failed writes leave the handle usable; failed fsyncs poison it, and failed fsync rollback creates a shared barrier naming the staging file. Cover both sealing and creation, including creation/write injection.
- Case 2, lines 466–475 and 835–842: create the shared barrier before releasing the lock after failed renamed-directory fsyncs in sealing, running settlement, open settlement and creation. Text includes the underlying failure, `directory fsync after rename`, staging/live names and available sealed names. Preserve the explicit residual when barrier creation fails, and permit other writers after staging-name/discard failures.
- Case 3, lines 476 and 843: preserve the exact 33-byte marker, without staging or poison, after either marker fsync failure; retain the marker-without-trail recovery.
- Case 4, lines 477 and 844: retain poison-before-settlement ordering and prove it for creation, sealing and hand-built resume staging, across open, record, checkpoint and consuming close.
- Case 5, lines 478 and 845–846: reject poisoned checkpoint/close before acquiring the lock or signing; Drop of a poisoned handle is inert and silent. Cover checkpoint, close and Drop fsync failures with and without rollback failure, lock contention, counting signers and expected-head recovery.
- Case 6, lines 479 and 847: healthy checkpoint/close/Drop respect a shared barrier; no signature or storage change occurs, close consumes the handle, and Drop reports once on stderr.
- Line 841: add restart/remount → verify → remove clearing instructions to `AuditErrorKind::Poisoned` rustdoc, including the unsynced poison file's restart residual. No public API declarations change.
- Line 832, architect ruling 11b2b2-d1: amend the creation parenthetical inline. After restart a complete creation staging file is promoted; empty/torn staging is discarded and leaves marker-without-trail. Decision 6 rule 1 and decision 8 decide by disk content.

The test-only durable-state model pins inodes with open descriptors, records successful file fsync contents and successful directory fsync name maps, and reconstructs those durable contents/names at replay, preserving hard links and modes. Initial disk state is durable; a durable name without a data fsync replays empty; failing fsyncs never advance the saved view. The complete staging replay fixture explicitly persists its prior view before injecting the failed fsync; the empty fixture persists only the name. These are storage-layer simulations, not a real power-loss probe. Second-writer tests use a second Sink in the same process, with its own cache/poison flag, as the thread-local-hook ruling requires. The inert-close contention test uses a separately opened File holding the directory lock.

Size: at most 143 changed non-test lines (conservatively counting all sink.rs edits, including test-hook helpers), below 900. The model and acceptance tests are cfg(test). No dependency or lockfile changes.
