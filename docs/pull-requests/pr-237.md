# [PR 237](https://github.com/vig-os/vigil/pull/237) feat(audit): check end= and grant a matching end= its exemptions in the verifier

## Summary

Implements `end=` retirement check (ADR-0005 decision 9; rulings 13-V5-d1 point 5 and 13-V5-d5). The verifier evaluates two independent conditions against the engine's merged records on the verified trail:

- **at `s`:** the verified set holds exactly one distinct record at `s` and its hash is `h` (byte-identical copies count once). First failing check in this order: `seq <s> is forked` (no location), `no record at seq <s>` (no location), or `record at seq <s> has hash blake3:<64 hex>` (at the first copy in merge order).
- **above `s`:** no record of the verified trail has `seq` strictly above `s`. Detail `records seq <a>..=<b> above the end` at the first such record in merge order.

Every detail starts with `end=<s>:blake3:<64 hex>: `. A **match** (neither condition fails) grants exactly three things, at or below `s`: the report's tail exemption (`UncoveredTail` stays an info but `--strict` does not fail on it), confirmation of every `through=` bound (the pin still runs), and promotion of a 13-V5-d2 attester to `TornWriteRepaired`. A mismatch grants none of them. No `end=` in the section checks nothing and grants nothing.

The new `end=` evaluation runs once in `engine::check` and threads its `Option<u64>` matched end `seq` into `file_findings` (repair promotion), `revocation::check` (bound confirmation) and `Report::with_tail_exempt`. The match is computed once and every consumer reads the same value. Reader bytes untouched.

**T5 equivalence.** The mutant flips `tail_exempt` from `false` to `true` only when `matched_end` is `None` (i.e. mismatch or no `end=`). Mismatch always emits `TrailEnded` (an error), which forces `is_strict_valid()` to `false` whatever `tail_exempt` is set to; no `end=` sets `matched_end` to `None` and `tail_exempt` to `false` under both the mutant and the correct implementation (nothing to flip). So the mutant produces the same observable behaviour across every realistic layout on the public API; the flag is visible only through `Debug`.

**T10 equivalence.** The forked-at-`s` and absent-at-`s` checks are mutually exclusive by construction: `conflicting_seqs` is derived from `groups` as the set of seqs with >= 2 distinct hashes, so `conflicting_seqs.contains(&s)` implies `groups.contains_key(&s)`. An absent seq is not in `groups` and so cannot be forked; a forked seq is in `groups` and so cannot be absent. Swapping the two check orders therefore produces the same finding on every input.
