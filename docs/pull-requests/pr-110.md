# [PR 110](https://github.com/vig-os/vigil/pull/110) ci(clippy): gate every supported feature combination

## Description

Feature-specific warnings can pass the all-features clippy gate. Add eight flake checks covering every user-feature subset with and without `vigil_unstable`, with `--all-targets` and `-D warnings`.

## Type of Change

- [x] `ci` -- CI/CD pipeline changes

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- Derive the powerset from `builtins.fromTOML (builtins.readFile ./Cargo.toml)`. Exclude Cargo's `default` selector and the explicitly CI-only `test-preserve-order` feature; keep existing all-features checks.
- Add `clippy-no-default`, `clippy-audit`, `clippy-metrics`, `clippy-audit-metrics`, and each `-unstable` twin. Feature names are sorted. Adding #41's `push` doubles the subsets from four to eight; evaluation rejects more than sixteen subsets pending a ruling.
- Reuse the stable all-features dependency artifacts for plain checks. Build one separate `buildDepsOnly` artifact with identical `vigil_unstable` RUSTFLAGS and check artifacts for all dependency feature variants; share it among every unstable twin and existing `unstable-clippy`. This avoids rebuilding transitive dependencies for each unstable check.
- Reject generated-name collisions at evaluation with a ruling message. Also reject optional dependencies lacking a `dep:<name>` reference in a user feature, including target-specific dependency tables, so implicit features cannot escape coverage.
- Remove CI's fully redundant Unstable clippy step: the existing all-features `unstable-clippy` and the new unstable matrix run through `nix flake check`, which feeds CI Summary. The pre-commit cargo-clippy hook stays unchanged.
- No library behavior changes or warnings required fixes on the current origin/dev; `OTelSdkResult` uses in `src/init.rs` were already path-qualified.
