# [PR 71](https://github.com/vig-os/vigil/pull/71) docs(adr): ADR-0005 amendment for the clean-stop head, receipts, start_from and revocation scope

## Description

Decides the four sub-decisions ADR-0005 left open in #66, **in place** in `docs/adr/0005-audit-trail.md` (each "Open — decided in #66" marker is replaced by the rule; an "Amended 2026-10-11 (#66), Accepted" line sits under Status). After the architect's review (no blockers), Status reads "Accepted (2026-10-11), amended by #66" and the review nits are fixed in 852e8f2.

| Sub-decision | Decided rule |
|---|---|
| Clean-stop `--expect-head` source (decision 9) | `AuditTrail::close(self) -> Result<Checkpoint, AuditError>` always writes and returns a checkpoint; the expected head is the highest `seq` among the receipts and close checkpoints the application holds across processes; a writer with no returned close → restart once and close. |
| Receipts range (decision 5) | From seq 0 (or the start) **through the head**; every unreceipted record is `NoReceipt`; receipts above the head are `ReceiptMismatch`; one-record hash-pinned `waive` lines for crash orphans (`ReceiptWaived`, info) with a review criterion; one `from` line for late adoption; `--receipts-live` ends at the longest fully reconciled prefix (`Unreconciled`, info, fails `--strict`); operator CLI records print receipts. |
| `start_from` / archiving (decisions 2, 11) | The start comes from the archive's own record, never the disk; accepted only as the first record, a trusted checkpoint; inputs below it are `OutOfRange` only if the start is **anchored**, else `UnanchoredStart` (error); no start and seq 0 missing → `SeqGap`. |
| Revocation scope (decision 9) | A key revoked on one trail is revoked on every trail that lists it: mixed `through=` is a parse error (`InvalidConfig`); a key at most once per section; one trail id per section; retired WORM trails use `end=` (`TrailEnded`); every trail a key signs for belongs in one trust file. |

New decision 16 states, per rule, what is detected under (a) write access without key, (b) stolen key, (c) honest crashes, (d) multi-process writers, by which finding, and what stays undetectable without an external anchor (#57). Consequences and rejected alternatives cover each rule.

**Deferred, with issues:** `--strict` with reviewed warnings (an honest crash's `TornWrite` fails `--strict` forever in the core) → #68; receipts across a `resume` (a `lost`-line mechanism drafted in review was broken by round 3 and withdrawn) → #70.
