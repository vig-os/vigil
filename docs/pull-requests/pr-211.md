# [PR 211](https://github.com/vig-os/vigil/pull/211) refactor(audit): extract the segment byte source (#197 R2b S3b1a)

## Summary

Behaviour-preserving refactor (ruling 197-d1 addendum 25, S3b1 first half):
extracts two `pub(crate)` types in `src/audit/storage.rs` that own the
byte-level I/O previously inlined in `history_segment`'s `events` /
`on_feed` closures and in `scan_inner`:

- **`SegmentBytes`** — seek, `read_line`, the glued-byte / LF check,
  `decode_line_kind`, and the shared `last_offset` / `last_newline`
  / `offset_cursor` byte bookkeeping. One implementation serves
  both the tolerant (`history_segment`) and strict (`scan_inner`)
  sides through `check_glue_byte_strict` / `next_event` /
  `note_record_fed` / `note_newline`. The two
  `corrupt("bytes glued to complete unterminated record")` calls
  behaved identically on the Err path, so they merge into one
  shared `consume_glue_byte` helper: the syn gate's site count
  drops **50 → 49** (7 in `storage.rs`, 42 in `runs.rs`).
- **`SegmentSource`** — lazy base-order segment plan: `for_live_open`
  (rotated names → live), `for_refresh_rotate` (cached-file prelude
  → lazy `segments_after` → live), `for_refresh_append` (cached
  live only). Each file is opened only inside `next_segment`, and
  on refresh rotate the `segments_after` listing itself is deferred
  until after the prelude is yielded, so a directory-listing error
  surfaces exactly where it does at base (addendum 25.2: prelude
  first, then the newer segments).

`initial_record` and `refresh` drive the source; each per-segment
walk still runs in `storage.rs` here. S3b1b moves the loops into
`runs::classify` (addendum 25).

Round-3 lifts the last local byte cursor out of the shim: the
tolerant epilogue's `length` is now `bytes.offset_cursor()`, the
same cursor the strict side already uses. The shim no longer keeps
a `final_offset` local — the sole end-of-segment byte cursor lives
in `SegmentBytes` (20.1 / 25.2). The writer-only `cp_time` /
`since_cp` fold and the `expected` / `found` writeback remain
closure-locals; they are not byte-level.

## Pins

Seven byte-source pins now live in `audit::storage::tests::details`,
each with a literal expected outcome:

- `sb1_liveopen_base_order_short_circuits_on_segment_0_error` — a
  corrupt seg_0 plus a non-regular seg_1 (FIFO). The reader surfaces
  seg_0's `invalid audit record in sealed run`, not seg_1's
  `nonregular trail file`.
- `sb1_refresh_rotate_prelude_walks_before_segments_after` —
  `chmod 0300` on the directory after rotating a corrupt prelude.
  The reader surfaces the prelude's `invalid audit record in sealed
  run`, not `Io Permission denied` from an eager `segments_after`
  listing.
- `sb2_glue_across_segments_live_open_ok` and
  `sb2_glue_across_segments_refresh_rotate_ok` — pin the exact
  `(offset, length, newline, gap)` tuple on both multi-segment
  paths; the refresh-rotate row keeps the prelude unterminated
  (no trailing LF appended before rotation) and is killed by MA3 / MA3b
  / NRF2 on the live-segment scan.
- `sb3_refresh_append_bookkeeping_pins_state` — the exact
  (`offset`, `length`, `newline`, `gap`) tuple after `fixture +
  append + refresh + append + refresh`.
- `sb4_fragment_at_segment_end_multi_segment` — multi-segment
  `TrailReader::open` over seg_0 = `[cp0, "{\"torn\":"]` and a
  cp1 live, pinning CorruptTrail `"resume checkpoint lacks its
  declaration"`.
- `sb4_fragment_at_segment_start_multi_segment` — chained
  `history_segment` on `[fragment, cp0]` after a sealed state pins
  the sealed-run seq detail `"record sequence did not increase
  inside sealed run"`.

Plus four new glue-cursor pins (and the two legacy glued-byte pins) for the merged-helper and strict-length
mutants:

- `pin_hs_glued_byte` and `pin_sc_glued_byte` — the two legacy
  reader-side pins of the `"bytes glued to complete unterminated
  record"` detail, which still cover the two call sites that now
  share `consume_glue_byte` (one on the strict eager path, one on
  the tolerant lazy path).
- `mx2_mx3_strict_glue_sets_last_offset_and_last_newline` —
  `scan(opening=false)` after the state-unterminated + `\n`
  append pins `(offset, length, newline) = (X+1, X+1, true)`,
  and a further record append scans Ok.
- `mx4_tolerant_glue_bumps_offset_cursor` —
  `history_segment(unterminated, opening=false, run=true)` over
  `"\nnot json\n"` pins `length = X + 10`.
- `mh5_strict_glue_eof_returns_false` — pins
  `(offset, length, newline=false)` on `scan(opening=false)` with
  state-unterminated and no new bytes, then appends `x` and pins
  the error `"bytes glued to complete unterminated record"`.
- `scn1_strict_fragment_length_is_offset_cursor` — strict scan
  over `[cp0, "{\"torn\":"]` (fragment at end, no LF) pins
  `length = len(cp0) + 8` (`offset_cursor` past the fragment),
  distinguishing it from `last_offset` (at the record boundary).
