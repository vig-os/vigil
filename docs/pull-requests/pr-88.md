# [PR 88](https://github.com/vig-os/vigil/pull/88) feat(resource): assign a UUID to each pipeline instance

## Description

Concurrent producers of one service need distinct resource identities so cumulative metrics can remain separate. Both `init` and `layer` now generate one lowercase RFC 9562 UUID v4 `service.instance.id` per pipeline and retain it across exports.

This is #7a1: resource identity and synchronous log SDK configuration. The metrics data path follows separately after this PR merges.

- [x] `test` -- Adding or updating tests

- [ ] Breaking change (`!`)

## Changes Made

- Use `getrandom = { version = "0.3", default-features = false }` for 16 random bytes and set the RFC version and variant bits. This direct runtime dependency was already locked through the development dependency graph; no package entries were added to `Cargo.lock`.
- Keep synchronous batch queue size, batch size and delay explicit in one tested helper. These values were already pinned; this change preserves their behavior and adds regression coverage against all four `OTEL_BLRP_*` variables. Export timeout is available only on the unused async processor; the synchronous processor has no concurrency setting.
- Check resource identity through both installation paths, consistency across exports, uniqueness across pipelines, UUID spelling and version/variant bits. Golden content comparison permits only the new resource attribute. OS randomness failures use the existing stderr degradation path with a warning naming the identity generation failure, documented in README. An injected test-only failure verifies the warning, live fallback logging, successful flush/shutdown and no panic. Two separate init processes also produce distinct IDs, and temporary directories are removed during assertion unwinding.
