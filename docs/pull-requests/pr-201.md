# [PR 201](https://github.com/vig-os/vigil/pull/201) test(audit): pin every reader CorruptTrail detail per path (#197 R0b)

## Description

R0a (PR #199, merged at `66ce3b0`) pinned the live, strict-`scan` and
`scan_inner` paths and installed the per-site coverage gate. R0b picks up
the paths and layouts R0a deferred and empties `PENDING_R0B`.

Tests only; no product-code changes (ruling 197-d1 addendum 9 permits a
`[dev-dependencies]` edit for the gate's `syn` dependency, below).

The site/line numbers below are labels (they shift under any refactor of
`storage.rs`); the mutants, run against today's `storage.rs`, are the
real proof that each pin binds behaviour.

## Type of Change

- [x] `test` -- Adding or updating tests

## Changes Made

- Fallback rescan through `TrailReader::open`: a dedicated pin per
  fallback-reachable site in `history_segment`'s post-strict body.
- Refresh with `opening=false`: real tests for the three sites that
  used to sit in `PENDING_R0B` (which is now removed): the missing
  live file guard, the same-inode shrink guard, and the retained-
  descriptor truncation guard across a rotation.
- Resume path: `Sink::resume` surfaces `predecessor_run` corrupt errors
  from the fallback body; a bogus `.audit-resume.jsonl` that actually
  reaches `scan_staged` makes `promote_resume` return
  `ResumeOutcome::Discarded`, unlinking the staging. The test pins the
  `Discarded` outcome and the staging unlink -- a source-text pin of
  the `Sink::resume`-only discard string was removed as per round 3's
  nit, because no path reachable from this test module surfaces that
  exact detail.
- Archived base dependence (section 4): `cp(7, [42;32], genesis_fold)`
  -- `scan` is Ok (archived prefix accepted), `scan_staged` runs with
  `genesis=true` and gives `initial checkpoint does not link genesis`.
- Named layouts: `boundary_resume` on a sealed-run and on a fragment-
  only predecessor, each with the opening in a rotated successor
  (L498 "first successor lacks immediate resume") and in the live
  file (L914 "unclosed segment lacks matching immediate resume"); the
  closing-opening MMR mismatch; the hash-link boundary pin
  `[cp0, e1, x(seq=1, prev=e1.hash, other content)]` on live `open`,
  strict `scan` and refresh; and the Section 5 accepted layout --
  genesis closer after a fragment-only first segment, with
  `history_segment`'s `&mut run` reporting the fragment-only seg0 as
  a run.
- Gate (197-d1 addendum 9): the coverage gate parses `storage.rs` and
  `storage_tests.rs` with `syn::parse_file` and a `syn::visit::Visit`
  walk, instead of a hand-written lexer. `syn 2.0.119` is already a
  transitive dependency (via proc-macro crates); the Cargo.lock diff
  adds two direct dev-dependency edges from `vigil-telemetry` to
  already-locked crates, `syn 2.0.119` and `proc-macro2 1.0.107`
  (round 4, for walking macro token streams). No new crate enters the
  supply chain, and cargo-deny passes. Ruling 197-d1 addendum 11 accepts
  the `proc-macro2` edge; dropping it in favour of `syn::buffer` is a
  follow-up issue. The
  walk requires every use of a path ending in `assert_corrupt` --
  other than the helper's own `fn` item -- to be a direct `ExprCall`
  whose detail argument is a string literal and whose site argument
  is an integer literal; aliases (`let f = assert_corrupt;`), fn
  pointers (`let f = assert_corrupt::<()>;`), and non-literal args
  all panic. Known limit (recorded in the gate's doc comment):
  reachability (`if false { .. }`) cannot be proven statically; the
  mutants listed below are the proof each pin fires at runtime. The
  stale-label, uncovered-site and 51-site checks are kept.

### Gate hardening -- addendum 10 (round 4) probes

Round 3's review (ruling 197-d1 addendum 10) found three remaining
shapes that still let a bogus or defused `assert_corrupt` slip past
the syn-based gate. Each was closed and probed. Threat model stated
in the gate's doc comment and on the dead-code row above.

| addendum-10 fix | injected shape | result |
|---|---|---|
| fix 1: shadowing `fn` | `fn assert_corrupt<T>(_: Result<T, AuditError>, _: &str, _: usize) {}` nested in a test fn before a real pin | exit 101 "expected exactly one `fn assert_corrupt` item, found 2" |
| fix 2: macro-wrapped call (`vec!`) | `let _ = vec![assert_corrupt::<()>(Ok(()), "macro wrapped bogus", 0)];` | exit 101 "`assert_corrupt` appears as an identifier inside a macro invocation's token stream" |
| fix 2: macro-wrapped call (`assert!`) | `assert!({ let f = assert_corrupt::<()>; let d2 = "dyn"; f(Ok::<(), AuditError>(()), d2, 0); true });` | exit 101 (same panic as above) |
| fix 3: `use` alias | `use self::assert_corrupt as ac;` followed by `ac::<()>(Ok(()), "aliased bogus", 0);` | exit 101 "`assert_corrupt` appears in a `use` tree (as alias source or destination)" |

hardened gate):
