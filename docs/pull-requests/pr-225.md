# [PR 225](https://github.com/vig-os/vigil/pull/225) feat(audit): verifier run detection through the shared classifier over the confirmed snapshot

## Summary

Wire `verify::fold::check_runs` into `engine::check` so `Verifier::verify_dir` / `Verifier::verify_files` emit one `SegmentStructure` finding per closed run that `runs::classify` returns under `Reaction::Collect` over the verifier's confirmed snapshot bytes. The classifier runs once over the merged `Collection` through `storage::SegmentSource::for_snapshot`, which opens nothing (rulings 13-V4-d5, 13-V4-d6). Each finding carries the ADR-0005 decision 11 run digest; the detail follows the 13-V4-d8 point 1 grammar (ranges, then spans with `after start` at a segment's first byte, then `digest blake3:<hex>`); the `(file, line, seq)` are the run's first segment and its first record on the verified trail (13-V4-d8 point 5). Shipped-copy runs are out of scope at this head (owner decision 13-V4-d7; #224).

Ruling 13-V4-d9 (#226) is implemented here: a run's spans come from the run's own segments only, `first_segment..last_segment` (exclusive), so the closing segment never contributes to the run digest. The two classifier-level tests that pinned the old behaviour are rewritten and renamed; their `.take(last_segment + 1)` restore mutant is killed twice at the classifier level (by `closer_spans_excluded_torn_live_tail_p10` and `closer_spans_excluded_in_sealed_closer_p01`) and again at the verifier level by R14 and R15. The pinned A1/A3/A8/A9 digests stay unchanged because none of those closers carries a fragment.

The A1 / A3 / A8 / A9 builders, their helpers, and their captured run-digest constants moved from `src/audit/runs_v4a_tests.rs` into a shared `#[cfg(test)] pub(crate)` fixture module `runs_v4a_fixtures`, so the classify-level rows (`runs::classify_v4a_walk`) and the new verifier-level rows (`verify::runs_tests`) share one source of truth. No duplicated fixture code.

Rulings: 13-V4-d3, 13-V4-d4, 13-V4-d5, 13-V4-d6, 13-V4-d8, 13-V4-d9. Refs #13, #226.

## Classifier `Err` enumeration on a `for_snapshot` source (13-V4-d8 point 4)

Every `?` in `runs::classify` was audited for the Collect case on a `SegmentSource::for_snapshot` plan at this head:

- `source.next_segment()?` — on `PlanStep::Snapshot` the arm returns `Ok` unconditionally; `for_snapshot` sets no `pending`, so the `expand_rotate_after` branch is unreachable.
- `source.try_clone().map_err(storage::io_error)?` (span-handle clone) — `ByteSource::Memory`'s `try_clone` constructs a fresh `Cursor` over a shared `Rc<[u8]>` with no I/O.
- Walker arms `storage::history_segment` / `scan_closing` / `scan` under `Reaction::Collect` — each internally seeks and reads the `ByteSource`; `ByteSource::Memory::seek` / `::read` are infallible `Cursor` operations. The tolerant fallback in `runs::history_segment` swallows `CorruptTrail` into recorded violations.
- `collect_segment_spans_and_records`:
  - `source.seek(SeekFrom::Start(0))` on `ByteSource::Memory` — infallible.
  - `u32::try_from(segment_index)` — the only `Err` producer in the audit. Overflows only on a crafted `Collection` with more than `u32::MAX` native segments (each at least a `PathBuf` + `Rc<Data>` + `BTreeMap<Inode, Rc<Data>>` entry built in `input::collect` **before** `check_runs` ever runs, so >= 4 GiB of structures alone — unreachable from any crafted input the verifier can produce).
  - `super::verify::lines::stream` over `BufReader<ByteSource::Memory>` — `fill_buf` on a `Cursor` is infallible.

Result: no reachable `Err` on crafted bytes. `check_runs` calls `runs::classify(...).expect(...)` whose message cites the single `u32::try_from` site with the construction argument.

### M13 equivalence argument

The trail check (`TrailIdentityDiffers`) runs first inside the classifier's state machine on both the strict and the tolerant pass of `runs::classify`. Any foreign-trail record inside a walked segment is a classifier `Violation`, and ruling 197-d1 addendum 28 point 2 together with 13-V4-d8 point 3 then empties every run via the `suppress_runs` guard. So on any layout where a run segment carries a foreign-trail record, no run finding is emitted — and the first-record lookup in `fold::emit_run_finding` never runs. On a layout with no foreign records in the run's first segment, the trail filter has no observable effect either way. The mutant is therefore equivalent, not missed.
