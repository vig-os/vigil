# [PR 23](https://github.com/vig-os/vigil/pull/23) feat(logs): add OTLP/JSON Lines log exporter and line-sink seam

## Description

Adds `vigil::logs::OtlpJsonLogExporter`, an `opentelemetry_sdk` 0.33 `LogExporter` that writes each export batch as **one line = one `LogsData`** in OTLP/JSON (the OTel file-exporter format), serialized by `opentelemetry-proto`'s serde support through a small `LineSink` trait (`vigil::sink`). Closes #3.

## Type of Change

- [x] `feat` -- New feature

## Changes Made

- `src/logs.rs`: the exporter. `set_resource` captures the resource, `shutdown_with_timeout` flushes the sink, no async runtime (the returned future is already ready). Empty batches write nothing.
- `src/sink.rs`: `LineSink`, `AppendFile` (`O_APPEND|O_CREAT`, 0600, `line + '\n'` in one `write`, an error on a short write, never a split retry), `MemorySink` (clone-shared test sink), `impl LineSink for Arc<T>`.
- Pre-mortem items:
  1. **Non-finite doubles**: spelled `"NaN"`/`"Infinity"`/`"-Infinity"`. Verified against collector-contrib **0.155.0** (`otlpjsonfile` → `file`): it ingests them as `doubleValue` and re-emits them unchanged. (`{"doubleValue":null}` loses the line.) `opentelemetry-proto`'s own reader rejects these strings; documented on `NON_FINITE`. Pinned in the golden file.
  2. **Determinism**: resources, scopes (name, version, schema url, attrs) and all attribute lists, including nested `kvlistValue`s, are sorted. Golden test repeats 50 runs; a second test does 25 fresh runs.
  3. **`timeUnixNano`** copied from observed time when 0.
  4. **Fixtures in Nix**: `tests/fixtures` added to `extraSrcFiles`; the golden test reads the file at run time and fails if it's missing (only `VIGIL_BLESS=1` creates it), so `nix flake check` passing proves the fixture is visible.
- `VIGIL_BLESS=1 cargo test --test golden` regenerates the golden file.

### Dependencies (crates.io, justification)
- `opentelemetry`, `opentelemetry_sdk` (`logs`): the exporter trait and record types.
- `opentelemetry-proto` (no default features; `logs`, `gen-tonic-messages`, `with-serde`): message types, SDK→proto transform, OTLP/JSON serde.
- `serde_json`: line encoding and the non-finite patching.

**No tonic/tokio/hyper/prost-build**: `cargo tree -i tonic` and `cargo tree -i tokio` both fail with "package ID specification ... did not match any packages"; `tests/deps.rs` asserts that `Cargo.lock` has none of tonic, tokio, hyper, prost-build, reqwest, h2, tower. Direct tree: `opentelemetry`, `opentelemetry-proto`, `opentelemetry_sdk`, `serde_json` (prost 0.14 only).

## Changelog Entry

### Added

- `vigil::logs::OtlpJsonLogExporter`, an `opentelemetry_sdk` `LogExporter` that writes each export batch as one OTLP/JSON `LogsData` line to a `vigil::sink::LineSink`, with deterministic ordering, `timeUnixNano` backfilled from the observed time, and non-finite doubles spelled `"NaN"`/`"Infinity"`/`"-Infinity"` so the Collector keeps the line ([#3](https://github.com/vig-os/vigil/issues/3))
- `vigil::sink::{LineSink, AppendFile, MemorySink}`: the line-sink seam, an `O_APPEND` single-`write(2)` file sink (mode 0600) and an in-memory test sink ([#3](https://github.com/vig-os/vigil/issues/3))
