# [PR 194](https://github.com/vig-os/vigil/pull/194) feat(audit): verifier structural resume validation (#13 V3b-2)

## Description

Implements V3b-2 of #13 per ruling 13-V3-d5: structural resume
validation for every `vigil.audit.resume` record whose declaration
parses on the selected trail, with a mandatory
`structural=valid|invalid(<reason>)` suffix on the `Resumed` detail and
the corrected `gap=0..=<L>` genesis text (ADR-0005 l.407, l.411). No
new `FindingKind`, no public API change, no demotion of any existing
finding.

## Type of Change

- [x] `feat` -- New feature

## Changes Made

- Structural check for S1a (opening at `k = L+1` is a checkpoint), S1b
  (resume at `k+1`), S2a (head present with declared hash on this
  trail), S2b (head is the last record below `k`), S2c/S3a (opening's
  `previous` links to head or to the genesis value), and S3b (nothing
  precedes `k` for a genesis declaration). The first failure is
  reported in d5 point 4's order: `no-opening`, `resume-not-at-k+1`,
  `head-not-present`, `head-not-last`, `link-mismatch`,
  `genesis-not-first`.
- Fixes the genesis gap text: `is_genesis_head = (h == 0 && hash is
  the genesis value)` (addendum 9); `gap=0..=<lost_through>` for a
  genesis head, otherwise `gap=none` (nothing lost) or
  `gap=<h+1>..=<L>`.
- "The record at `k`" and "the opening" follow addendum 8: among
  qualifying checkpoints, the first in input order (native first) is
  the opening. "No candidate" / "any candidate" rules apply across
  native + shipped.
- A malformed declaration keeps its exact
  `"malformed declaration"` detail and gets no suffix.
- Native + shipped copies of the same `(resume seq, resume hash)` share
  one computed outcome (d5 point 10).
- Validated tuples (`ResumeCandidate`) are harvested into a
  scope-local `_pending_resumes` in `check` and reserved for #13 V4
  (rule 2 fold), V6 (start) and V7 (confirmation). The `Report` type
  is unchanged.
- Updates ADR-0005 §19.9 (one sentence); §19.6 stays Proposed until
  V7/R10. Updates the `verify` rustdoc with the suffix grammar, the
  ordered reason tokens, and the archived/deleted-head equivalence
  note.
- Renames the base's l.388 lib test to
  `resume_at_genesis_with_no_opening_marks_structural_invalid_and_strict_fails`
  and asserts the exact `gap=0..=0 ... structural=invalid(no-opening)`
  suffix. The malformed-declaration exact-equality assertion is kept
  byte-identical (M10 killer); `resume_in_native_and_shipped_emits_once_on_native`
  and `tests/audit_verify.rs:resume_record_from_writer_emits_one_resumed_with_parsed_detail`
  stay byte-identical.
