# [PR 233](https://github.com/vig-os/vigil/pull/233) feat(audit): report trusted coverage, UncoveredTail and covered repairs in the verifier

## Summary

Reports trusted-checkpoint coverage in the offline verifier (ADR-0005 decision 5 and decision 11; rulings 13-V5-d1 point 6 and 13-V5-d2). `Report::covered_through` returns the highest `seq` of a checkpoint whose signature verifies **and** whose key is trusted at that `seq`, or `None` when no candidate is trusted. `UncoveredTail` lists exactly the records strictly above `covered_through` (or every record when `None`), with detail `records seq {a}..={last}` where `a = covered_through + 1` (or the first verified `seq`); the last record being covered yields no `UncoveredTail`.

A native gap whose attesting record is a record of the verified trail, at `seq <= covered_through`, and the only DISTINCT hash at its `seq` (not one side of a `SeqConflict` fork) is reported as `TornWriteRepaired` (info). A byte-identical duplicate stays `DuplicateRecord` and does NOT block promotion -- "forked" is decided once in a shared helper that reads it from the same set the `SeqConflict` emission uses, so a duplicate copy is not a fork. An attester of another trail or one side of a real fork stays `TornWrite`: its `TrailMismatch` or `SeqConflict` error is reported as before. `RepairMismatch`, a trailing gap with no attesting record, and a `fragment not present` detail (native or shipped) are never promoted. Refs #13.
