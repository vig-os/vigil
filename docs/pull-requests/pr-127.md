# [PR 127](https://github.com/vig-os/vigil/pull/127) feat(audit): writer-handle rebuild across resume (B3d2b1)

## Description

An open writer can retain acknowledged records that an operator resume declares lost. Discover every resume after the cached boundary before validating the old descriptor, then either rebuild through open or refuse the handle permanently when the declared bound contradicts its acknowledgements. Equality continues, including a truncated old inode (A=3, B=1, L=3 → record 6).

## Type of Change

- [x] `feat` -- New feature
- [x] `fix` -- Bug fix
- [ ] Breaking change (`!`)

## Changes Made

- Track the highest returned receipt/checkpoint sequence with `fetch_max`, including signer-down receipts; start fresh handles at zero.
- Under the existing directory lock: check the sticky gate, settle, discover the minimum loss bound from the first two records of each segment after the cached boundary and the live file, then refresh or rebuild through the same full fold as open. Discovery is bounded and does not fold. Accepted discovery still requires full history validation.
- Keep reader refresh unchanged; document reopening readers across a resume. No new public API or resume entry point. Amendment 9 stays Proposed and cites rulings B3d2-d6/B3d2-d7.
- Share the inode-boundary lookup and resume-details parser between discovery and validation; reuse the existing directory snapshot helper. Correct the ADR gate name to `with_resumes`.
- Remove the redundant checkpoint comparison clause, retaining the genesis leaf fold. Replace the Genesis-base hard-coded line cite with decision 7 'Leaves'.

## Changelog Entry
