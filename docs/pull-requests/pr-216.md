# [PR 216](https://github.com/vig-os/vigil/pull/216) refactor(audit): V4a-facing classify reports and runs.rs module doc (#197 R2b S3b2)

## Summary

V4a-facing report types + the `mod classify_v4a_walk` row set on `ClassifyOutput`. Membership comes from the reader's own run flag, exactly (ruling 197-d1 addendum 28, 13-V4-d3 point 1): a segment is a run member iff `run_in || run_out`, and a segment ends a run iff `run_in` was true entering it AND `apply_checked` accepted the closing resume. Reports are built only under `Reaction::Collect`; the walker's own `closed_run` latch is gated on `ctx.run` on both the strict and the tolerant pass AND fires only AFTER `apply_checked` accepts the resume (ruling 197-d1 addendum 28 point 1; 13-V4-d3 point 1).

- Types + fields: `SegmentClass`, `SegmentReport`, `RunReport`, `LossPoint`; `segments: Vec<SegmentReport>` and `runs: Vec<RunReport>`, filled under `Reaction::Collect` only (ruling 197-d1 addendum 28 point 1).
- Addendum 28 point 2: `runs` stays empty whenever `violations` is non-empty or `head_mismatch` is set; `segments` is still filled with its damage flags.
- Reports are built only under `Reaction::Collect`; under `Reaction::Stop`, `segments` and `runs` are empty.
- `closed_run` is a `SegmentOutcome` field threaded up from the Classifier's own (i)+(ii) latch. Strict mode latches it only when `ctx.run && boundary_resume && !first && is_resume AND apply_checked accepted the resume`; tolerant mode latches it only when `count == 1 && closing && is_resume AND apply_checked accepted the resume AND ctx.run` (an accepted tolerant closer without an actual inherited open run is NOT a closer; a rejected resume (e.g. `ResumeDeclarationDoesNotDescribeGap`) is NOT a closer either). No `&mut bool` out-param and no `#[expect(clippy::too_many_arguments)]`.
- `classify` derives `SegmentClass` from `(closed_run, member, damage)` with an exhaustive match and no catch-all arm. The walker invariant `closed_run => run_in` is asserted by `debug_assert!`. `Base` = not a member (`!run_in && !run_out`), `Closer` = ends a run, `Damaged` = member with damage that is not the closer, `InRun` = any other member. An honest intermediate segment with `run_in` false both entering and leaving stays `Base` even when its layout contains an opening checkpoint and an immediate `vigil.audit.resume` entry.
- Grouping: a run is bounded by a `Closer`, and a `Closer` that reopens begins a new run at the same segment (`p01` reports two runs with the correct `closing_opening`).
- Overflow at a loss point drops only that run; a non-increasing seq is a violation, so `runs` is empty.
- Spans concatenated per segment with `seg` rewritten run-local (ruling 13-V4-d2 point 2); `after == u64::MAX` iff the span starts at the segment's first byte.
- `closing_opening` captures the Closer segment's first-record `Head` (ADR-0005 amendment 6 (i)).
- `storage.rs`: no class/role/`boundary_resume` bookkeeping or `storage::sealed` call under `Reaction::Stop`; the reader's outputs are unchanged (the reader differential reports 0 differences).
- Collect keeps only `Option<(first, last)>` record heads per segment (the gap-point check needs exactly that pair); spans are the product.
- `storage::sealed` is `pub(crate)`; `storage::tests` and its `runs` helpers are widened to `pub(crate)` so `classify_v4a_walk` reuses them without duplicate builders.
- `verify/mod.rs`: `pub(crate) mod lines` so `classify` can call `verify::lines::stream` and `run_digest`.
- No public API change. `check_public_api.py` shows no diff; `cargo-semver-checks` reports no breaking change.

## Walker closed-run proof sentence

On the strict pass `ctx.run` implies an opening segment (the refresh-rotate prelude is walked first with `run == false`), so `initial_boundary_resume = opening && (ctx.run || !sealed(prior))` is true. `feed_record` rejects a non-resume second record (`UnclosedSegmentLacksResume`) and `finish_strict_check` rejects a segment without one (`ResumeCheckpointLacksDeclaration`). The walker latches `closed_run = true` AFTER `apply_checked` has accepted the resume record: a resume whose declaration is rejected (e.g. `ResumeDeclarationDoesNotDescribeGap`) returns `Err` from `apply_checked` and the segment is classed `Damaged` rather than `Closer`. Code location: `src/audit/runs.rs` `feed_record` strict closed-run block, under the `apply_checked` Ok arm.

The tolerant pass gates the latch on `self.ctx.run` for the same reason (tolerant's `closing` requires `inherited = *run || unsealed_boundary`, which can be true without an actual open run under `unsealed_boundary`), and also waits for `apply_checked`'s Ok arm before latching.
