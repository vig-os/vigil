# [PR 148](https://github.com/vig-os/vigil/pull/148) fix(audit): one line classifier; resume seals zero-filled tails (#143, #13 13-R)

## Description

Fixes #143: one crate-private line classifier implements ADR-0005 §19.5's fragment → framed decode → object → record order. `open` rejects damaged live tails; `resume` seals their original bytes; later `open` succeeds. Oversized physical lines are consumed through LF/EOF with bounded retained memory, so suffix bytes cannot become a new record or repair fragment.

## Type of Change

- [x] `fix` -- Bug fix
- [ ] Breaking change (`!`)

## Changes Made

- Add `audit::lines::classify` returning Fragment, Unparsable(error), or Record(result), reusable by V2 for findings and spans. Reader paths and `Record::parse_line` share it; delete the old fragment classifier and read-side cap checks.
- Preserve object-level InvalidField, UnknownVersion, MissingField, UnknownField and HashMismatch. A non-object is Unparsable even with nested duplicate keys. Writer validation and v1 emitted bytes are unchanged.
- Observable stable behavior fix: `AuditError::finding_kind()` returns Unparsable for NUL/control/over-cap input and JSON non-objects; over-cap parsing retains TooLarge. No type or public API changes.
- Accept OQ9 in ADR-0005, record the four boundary rulings, fold #145's JSON-key and genesis-gap bookkeeping nits, and include anchors in `AuditConfig::resume`'s lost-through rustdoc (#142).
