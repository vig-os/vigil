# [PR 52](https://github.com/vig-os/vigil/pull/52) chore(changelog): merge concurrent entries and curate Unreleased

## Description

Concurrent PRs inserting entries into Unreleased conflict on the same lines. Use Git's built-in union driver for CHANGELOG.md and curate all unreleased features against the current implementation, folding their pre-release fixes into Added. Validate duplicate release/Unreleased headings, repeated section kinds within a version, and duplicate top-level list entries on every local commit and in CI, because union can hide a real release-sync conflict.

### Duplicate validation and release sync

Final section/list policy: each version may contain a `###` section kind only once. Unindented top-level list entries are deduplicated by text across the whole version and section kind, including repeated sections and deeper headings. The same text is allowed in Added versus Fixed or in different versions. Indented items are deliberately excluded, so nested explanations under different parents do not conflict. Unordered markers and numbered markers (`1.` / `1)`) are ignored when comparing list text. README and the checker docstring document this policy.

Round-three regression proof: the final eleven-test checker suite against the previous implementation (3d707f8) exits 1 (5 failures, 5 errors); the corrected checker passes. New cases cover repeated sections, bullet scope across repeated sections and deeper headings, nested text under distinct parents, numbered entries and marker changes, and an actual `git merge-tree` union that cleanly retains two Security sections which the validator rejects. Together with conformance unit tests, all fifteen Python tests pass (exit 0). The first pre-commit run exited 1 because ruff-format reformatted one test file; formatting was staged before the final checks.


`python3 -m unittest discover -s scripts -p test_check_changelog.py -v` passes all eleven tests (exit 0). ### Manual Testing Details

Reproduction script (run from the repository root; isolated temporary repository, no changes to project branches):

```python
import pathlib, subprocess, tempfile
root=pathlib.Path(tempfile.mkdtemp(prefix='vigil40-merge-'))
def git(*args, check=True):
    return subprocess.run(['git','-C',str(root),*args],text=True,stdout=subprocess.PIPE,stderr=subprocess.STDOUT,check=check)
git('init','-q')
git('config','user.name','Merge replay')
git('config','user.email','merge-replay@example.invalid')
git('config','commit.gpgsign','false')
base='# Changelog\n\n## Unreleased\n\n### Added\n\n- Existing entry\n'
for mode in ['baseline','union']:
    if mode=='union':
        git('checkout','-q','baseline-base')
        (root/'.gitattributes').write_text(pathlib.Path('.gitattributes').read_text())
    (root/'CHANGELOG.md').write_text(base)
    git('add','.')
    git('commit','-qm',mode+' base')
    git('branch',mode+'-base')
    for side in ['a','b']:
        git('checkout','-q','-b',mode+'-'+side,mode+'-base')
        (root/'CHANGELOG.md').write_text(base.replace('- Existing entry',f'- Parallel PR {side.upper()}\n- Existing entry'))
        git('add','CHANGELOG.md'); git('commit','-qm','Add parallel entry '+side)
    command=f'git merge-tree --write-tree {mode}-a {mode}-b'
    result=git('merge-tree','--write-tree',mode+'-a',mode+'-b',check=False)
    print('$ '+command+'\n'+result.stdout+f'exit: {result.returncode}')
    assert result.returncode==(1 if mode=='baseline' else 0)
    if mode=='union':
        tree=result.stdout.splitlines()[0]
        merged=git('show',tree+':CHANGELOG.md').stdout
        print('$ git show '+tree+':CHANGELOG.md\n'+merged)
        assert merged.count('## Unreleased')==1
        assert merged.count('- Parallel PR A')==merged.count('- Parallel PR B')==1
        assert '<<<<<<<' not in merged
print('PASS: baseline conflicts; union retains both additions under one Unreleased heading')
```

### GitHub Update branch limitation

GitHub's server-side Update branch does **not** honor the union merge rule; do not depend on it to resolve changelog conflicts. The [GitHub support discussion](https://github.com/orgs/community/discussions/9288) includes the support explanation that server-side merging ignores user-defined attributes, with continuing reports through October 2026. This is documented evidence, not a newly performed remote update-branch experiment. Fetch and rebase locally, review ordering, duplicates and contradictory edits, then push the feature branch with `--force-with-lease` when necessary. Union is a textual merge and cannot enforce semantic correctness or prevent duplicate headings introduced by contributors. Fragments are the requested long-term remedy.
