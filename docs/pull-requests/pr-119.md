## Description

When bound declarations disagree about metric identity or collide after Prometheus translation, every involved name is poisoned. Existing handles stop recording and cumulative exports remove those names in every scope, so bind order cannot choose a winner. The unstable configuration method also installs the meter provider for matching-version global instrumentation.

This PR is stacked on `feature/7-metrics-facade`; the two changes land together. Local gates and all 19 CI checks pass on `c6ca019e4d221b132b1dccce10c92f496cdb6f40`, verified through REST check-runs.

## Changes Made

- Registry: retain every distinct declaration, including conflicting declarations and binds to already-poisoned names, in per-name vectors and a Prometheus-series index. One mutex covers registration, poisoning, diagnostics and SDK handle creation (ADR-0003 d21, amended as authorized).

- Export: filter before point counting without reordering; remove empty scopes/resources and skip an empty write. The standalone unstable exporter has no registry and retains its existing behavior (d2).
- Tests: every P15/P17 pair in both orders, exact sorted diagnostics, all six D1/D2/D3 and A/B/C orders, D0–D3, duplicates, staged cumulative export, measurement counts, period resets and separate-process file determinism in both JSON lanes.
- Globals: install only after successful subscriber installation, or at the end of layer after slot commit; cover opt-in versus default, poisoned global streams and a sentinel provider surviving ForeignSubscriber.
- Boundaries: canonicalize signed zero before constructing registry declarations and SDK instruments; equality and ordering share the same total comparison of canonical boundaries. `Declaration` has no hashing implementation. The const builder and stable API remain unchanged.
- Conformance/docs: the Collector accepts a shorter poisoned run containing its healthy counter. README explains lazy-path conflicts and recommends recording every instrument once. Preserve d23's lost rustdoc exclusion. Correct startup reporting docs in their own carried-fix commit.

### Description-clause equivalence proof

For the same scope and exact name with different descriptions, `self == other` is false. Translation depends only on name, kind and unit, never description or boundaries. The following partition applies to every valid name and boundary slice:

| Kind | Equal unit, equal boundaries | Equal unit, different boundaries | Different units, equal boundaries | Different units, different boundaries |
|---|---|---|---|---|
| Counter | identical `_total` series overlap | identical `_total` series overlap | `!compatible` | `!compatible` |
| CounterF64 | identical `_total` series overlap | identical `_total` series overlap | `!compatible` | `!compatible` |
| UpDownCounter | identical base series overlap | identical base series overlap | `!compatible` | `!compatible` |
| Gauge | identical base series overlap | identical base series overlap | `!compatible` | `!compatible` |
| Histogram | identical bucket/sum/count series overlap | identical bucket/sum/count series overlap | `!compatible` | `!compatible` |

With different units, series may be disjoint, but incompatibility short-circuits before the description expression. If that expression could otherwise be decisive (compatible kind/unit/boundaries and equal spelling), the overlap branch has already returned true. A different kind likewise short-circuits through incompatibility. Thus there is no case in which the description clause changes the answer; overlap alone is not claimed for different-unit pairs.

Before removal, `description_conflict_clause_is_redundant_for_every_kind` passed (exit 0). After removal the same test passed (exit 0): 320 pairs in both directions, all five kinds, both unit orders (`ms`/`s`), and every pairing of None, empty, `[1,2]`, `[1,3]` boundaries. It asserts both conflict and equivalence with `overlap || !compatible`. The removal is an equivalent mutant, intentionally not claimed as killed.

### Signed-zero proof and validation

The two separate child processes bind `zero.h` with `[-0.0,1.0]` and `[0.0,1.0]` in opposite orders. Both keep one metric with count 2, report no poisoning or DataLost, and export a positive-zero first explicit bound (checked by bits). Their entire files are byte-identical after the existing d2 mask removes only timestamps, resource `service.instance.id`, and resource `process.pid`. Both JSON map lanes exercise these tests.

`validate_boundaries` checks `is_finite()` and strict ascending `<`: it rejects every NaN payload, both infinities, duplicate values, and adjacent -0.0/+0.0; finite subnormals remain valid and are preserved. A single signed zero is valid and is canonicalized. Equality, partial ordering and total ordering now use one `total_cmp` basis; there is no `Hash` implementation to diverge.
