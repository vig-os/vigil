# [PR 91](https://github.com/vig-os/vigil/pull/91) docs(adr): ADR-0005 amendment 3 for the scope of fsync poisoning

## Description

ADR-0005 amendment 3 (#90): settles the scope of fsync poisoning that decision 6 left open. Docs only; no code. The writer core (B2b1) implements only the original text until this lands; B2b2 implements the amendment.

## Type of Change

- [x] `docs` -- Documentation only

## Changes Made

- Decision 6: "Amendment (2026-10-12, #90): the scope of poisoning", original text intact. Principle: a failed fsync is never retried; undo if the undo needs no durability, otherwise stop every writer with `audit.poison`.
  1. Failed staging fsync: truncate to 0, `Io`, poison the handle; `audit.poison` only if the truncate fails.
  2. Failed directory fsync: `audit.poison` after a rename into or out of the live name; `Io` (plus a poisoned handle, where one exists) for staging-name, discard and marker fsyncs; `create` and `resume` have no handle, and a call that returned `Io` after its renames is recovered by restart plus a waiver citing the `Io` error. Clearing: restart, verify, remove `audit.poison` (no staging deletion).
  3. Marker fsync in `create`: `Io`, marker stays, the existing "marker without a trail" state.
  4. `audit.poison` is checked before staging settlement.
  5. A handle poisoned in memory is inert: `record`, `checkpoint`, `close` return `Poisoned`; `Drop` writes nothing.
  6. `checkpoint`, `close`, `Drop` and `resume` fail `Poisoned` while `audit.poison` exists; `verify` ignores it.
- Pointers in decisions 6 and 8, a probe section (scratch model of the rules, not the kernel), one acceptance test per case, consequences, alternatives, header status, `docs/adr/README.md` row.
- Status is Proposed; the reviewer decides on Accepted. Review rounds fixed: the clearing rule, the wording of the principle, the `create` carve-out (round 1 blocker was the `create` staging test contradicting rule 3), `resume` having no handle, and a waiver for operator calls that returned `Io`.
