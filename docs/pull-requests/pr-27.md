# [PR 27](https://github.com/vig-os/vigil/pull/27) fix(rotate): rotate atomically relative to locked directories

## Description

State-directory swaps during rotation could redirect unlink and undo operations into a replacement directory. A failed undo also left duplicate names for one inode without reporting the second failure. Rotation now uses atomic no-replace rename, and every critical-section file operation is relative to the locked directory descriptor.

## Type of Change

- [x] `fix` -- Bug fix

### Modifiers

- [ ] Breaking change (`!`) -- This change breaks backward compatibility

## Changes Made

- Recheck directory identity after locking, refresh the shared descriptor with bounded retries, and recreate missing directories with mode 0700.
- Use descriptor-relative open, stat, listing, rename, unlink and retention operations, including during initial open. A swap during an append leaves that append in the locked directory; the next acquisition finds the replacement.
- Rotate atomically with `RENAME_NOREPLACE` on Linux and `RENAME_EXCL` on macOS, retrying segment-name collisions.
- Fall back to descriptor-relative link/unlink only for EINVAL, ENOSYS, EOPNOTSUPP or ENOTSUP. Return both errors if unlink and undo fail, and heal multiply linked live files only when a matching signal segment in the locked directory shares the inode, without logging a recovery record. External backup links stay intact.
- Update module docs, ADR-0002 and changelog; whitelist the POSIX `WRONLY` identifier for the spelling gate.

## Additional Notes

Dependency justification: crates.io `rustix` 1.1.5 (latest at implementation), with only the `fs` feature requested, provides safe directory-relative syscall wrappers and atomic no-replace rename while preserving `#![forbid(unsafe_code)]`. Its default std/alloc features support File conversion and directory iteration. Cargo.lock includes its registry dependencies and Nix vendoring passes.

macOS cross-check was attempted with `cargo check --target aarch64-apple-darwin` (exit 101): `error[E0463]: can't find crate for core`; the target standard library is not installed. Source review of rustix 1.1.5 confirms Apple cfgs expose `renameat_with`, map `NOREPLACE` to `RENAME_EXCL`, and call `renameatx_np` (ENOSYS when unavailable); descriptor iteration, stat and mode types are supported on Apple. macOS compilation was not completed locally.

Local gate friction resolved: clippy rejected a platform-dependent redundant nanosecond conversion; using a checked u32 conversion handles Linux and Apple types. The spelling hook reported `WRONLY` should be `WRONGLY`; a narrow identifier exception fixes that false positive.
