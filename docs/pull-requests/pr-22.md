# [PR 22](https://github.com/vig-os/vigil/pull/22) feat(rotate): add multi-process-safe size rotation and age retention

## Description

Adds `vigil::rotate`: a std-only, multi-process-safe rotating JSON Lines appender with age retention (port and generalisation of s1-mcp PR #6, plus the pre-mortem fixes).

## Type of Change

- [x] `feat` -- New feature

## Changes Made

- `RotatingFile::open/append`, `RotationConfig`, `segments`, plus readers `segments_since`, `read_since`, `find_newest`.
- `flock` on a separate never-renamed `<signal>.jsonl.lock`; `(dev, ino)` recheck and reopen under the lock; rotate when `len + line + 1 > max_bytes` (oversize lines go alone into a fresh file).
- Segment names `<signal>-<UTC stamp with nanos>Z.jsonl`, collision suffix `_NNNNNN` (sorts after the bare name); string sort == chronological.
- One lock fd per path per process via a registry: a second `open` shares it (no deadlock).
- Partial write is truncated back under the lock; all size arithmetic is checked/saturating (release builds).
- Prune on rotation and once per `open`; never touches the live or lock file; errors ignored.
- No new crates; `forbid(unsafe_code)` kept.

## Changelog Entry

### Added

- **Multi-process-safe size rotation and age retention** ([#4](https://github.com/vig-os/vigil/issues/4))
  - `vigil::rotate::RotatingFile` appends whole lines to `<dir>/<signal>.jsonl` under an `flock` on a separate `.lock` file, reopens when another process rotated, rolls back partial writes, and names rotated segments so they sort chronologically
  - `segments`, `segments_since`, `read_since` and `find_newest` read them back
