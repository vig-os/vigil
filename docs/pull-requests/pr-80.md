# [PR 80](https://github.com/vig-os/vigil/pull/80) test(perf): benchmark public APIs and document consumer budgets

## Description

Add public API performance measurements and disk-based consumer budgets. CI compares the actual merge-base and PR head sequentially on one runner instead of comparing unrelated machines.

## Type of Change

- [x] `test` -- Adding or updating tests
- [x] `ci` -- CI/CD pipeline changes

## Changes Made

- Cover single/eight-process append, pipeline init/export/split, and retention scans at 100/1,000/10,000 files. Validate counts, output, retained files and size limits through public APIs; no library source changes.
- Remove the committed machine-specific baseline. When the merge-base already declares and locks Criterion, a disposable worktree receives the identical head harness; both builds use --locked with their own manifest and lockfile. A base predating the dependency explicitly skips timing with a notice and summary rather than resolving packages. Separate Cargo artifact directories prevent binary reuse; both runs share a fresh Criterion directory and scratch filesystem. Locked base saves `base`; locked head compares against `base`. Logs include both SHAs, hardware, filesystem and compiler.
- Build/run failures and missing/invalid estimates fail the performance job and CI Summary. Only elapsed time >=2x emits a warning and exits 0. Keep exactly one explicit blocking `cargo test --locked --bench performance`: every workload runs once without timing assertions. Broader default/serial Cargo test steps select --lib --bins --tests --examples, excluding benchmarks.
- Remeasure full 100-sample workloads on ext4 under HOME (/dev/vdd, virtual block device), with cached writes and no fsync. Shared KVM Ryzen 7 9800X3D, 12 vCPUs, Linux 6.18.55, Rust 1.95.0. Means: append 333k records/s single, 220k aggregate eight; export 352k; split 34.5k; init 0.141 ms; rotation 0.150/2.059/35.708 ms. README explicitly distinguishes VM append headroom (6.66x/8.80x) from measured EPYC 7763 4-vCPU ext4 CI headroom (76.7k/40.6k records/s: 1.53x/1.62x). Budgets stay unchanged; margins are observations, not guarantees.
- Use neutral reproduction paths, document quick mode's 1,000 resamples, refuse reference updates with quick provenance or fewer than 100 samples, and deliberately ignore cleanup errors in Drop.
- Criterion 0.8.2 is the only added direct dev dependency: statistical sampling, throughput and named baselines; default features disabled. Cargo.lock is committed; runtime dependencies unchanged.
