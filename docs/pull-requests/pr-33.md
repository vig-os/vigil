# [PR 33](https://github.com/vig-os/vigil/pull/33) fix(init): retain guards and bound error diagnostics

## Description

Retaining the initialization guard now produces a compiler warning when ignored. Events after guard drop produce one warning instead of one SDK diagnostic per event. Runtime export failures report the first error and cumulative dropped-record counts, with subsequent reports limited to once per minute during failing exports and an outstanding summary at shutdown.

## Changes Made

1. Add the requested `Guard` must-use diagnostic and a compile-fail doctest.
2. Filter events after shutdown, warning once even for 1,000 subsequent events.
3. Wrap the initialization exporter to count failed-batch records and rate-limit diagnostics; document that runtime failures lose records rather than falling back to stderr.
4. Reject relative `VIGIL_DIR` values with a warning and default path resolution; warn once on invalid `RUST_LOG` and use `info`.
5. Use the existing rustix dependency's portable `uname().nodename()` for `host.name`, enabling its `system` feature. No new dependency.
6. Document initialization after fork and the inherited lock/subscriber with no child batch worker.

Serialize nextest cases because individual tests start child writers on shared hosts. Exporter serialization, rotation, and conformance files remain unchanged.
